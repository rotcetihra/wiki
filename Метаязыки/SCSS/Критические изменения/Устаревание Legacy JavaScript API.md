# Критическое изменение: Устаревание Legacy JavaScript API

Sass официально прощается со старым способом взаимодействия с JavaScript. Если вы используете Sass в своих сборках через Node.js (например, в конфигах Webpack, Gulp или кастомных скриптах), это изменение затронет то, как вы вызываете компилятор.

---

## 1. В чем суть изменений?

Исторически библиотека `sass` (Dart Sass) поддерживала тот же API, что и старый, ныне покойный `node-sass`. Это было сделано для легкого перехода. Теперь, когда Dart Sass стал стандартом, пришло время заменить громоздкие и медленные методы на современные и эффективные.

**Что устарело:**

- Метод `sass.render()` (асинхронный через callback).
    
- Метод `sass.renderSync()` (синхронный).
    

**Что пришло на смену:**

- `sass.compile()` (синхронная компиляция файла).
    
- `sass.compileAsync()` (асинхронная компиляция, возвращает Promise).
    
- `sass.compileString()` и `sass.compileStringAsync()` (для работы со строками кода).

---

## 2. Сравнение старого и нового API

Новый API стал чище: он больше не требует вложенных объектов вроде `{ file: '...' }` и использует современные стандарты JavaScript.

|**Особенность**|**Legacy API (render)**|**Modern API (compile)**|
|---|---|---|
|**Результат**|Через Callback|Возвращает объект (или Promise)|
|**Путь к файлу**|`render({file: 'path'})`|`compile('path')`|
|**Импортеры**|Сложная логика `importer`|Новый интерфейс `importers`|
|**Скорость**|Медленнее (из-за обратной совместимости)|Максимальная производительность|

### Пример кода (Было/Стало)

**Старый стиль (Legacy):**

```JavaScript
const sass = require('sass');

sass.render({
  file: "style.scss"
}, (err, result) => {
  if (!err) console.log(result.css.toString());
});
```

**Новый стиль (Modern):**

```JavaScript
const sass = require('sass');

// Синхронно (рекомендуется для простых скриптов)
const result = sass.compile("style.scss");
console.log(result.css);

// Или асинхронно (Promise)
// const result = await sass.compileAsync("style.scss");
```

---

## 3. Почему это важно?

1. **Поддержка новых функций:** Некоторые современные возможности Sass (например, новая система модулей или продвинутая работа с цветом) лучше работают или требуют именно новый API.
    
2. **Производительность:** `compile()` работает быстрее, так как он напрямую обращается к ядру Dart Sass без лишних прослоек для имитации поведения `node-sass`.
    
3. **Типизация:** Новый API гораздо лучше дружит с TypeScript.

---

## 4. Изменения в Importers и Functions

Если вы писали свои **кастомные импортеры** (для загрузки файлов из необычных мест) или **Sass-функции на JS**, вам придется их переписать.

- В старом API импортеры возвращали объект `{ file: ... }` или `{ contents: ... }`.
    
- В новом API появились четкие интерфейсы `FileImporter` и `Importer`. Они разделяют логику поиска файлов на диске и загрузки виртуальных файлов.

---

## 5. Как обновиться?

1. **Проверьте зависимости:** Если вы используете `sass-loader` (для Webpack) или `gulp-sass`, обновите их до последних версий. Популярные инструменты уже перешли на новый API под капотом.
    
2. **Ручное обновление:** Если у вас свои скрипты, замените `render` на `compile`. Помните, что `compile` принимает путь к файлу строкой в качестве первого аргумента.
    
3. **Внимание к Callback:** Новый асинхронный метод `compileAsync` возвращает `Promise`, поэтому используйте `await` или `.then()`.

---

## 6. Сроки

- **Текущий статус:** Использование `render()` и `renderSync()` вызывает `Deprecation Warning` в консоли.
    
- **Sass 2.0.0:** Старый API будет полностью удален. Все инструменты, не успевшие обновиться, перестанут работать.
    

Это изменение — отличный повод почистить свои скрипты сборки и сделать их более современными.
