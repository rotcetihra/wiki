# Критическое изменение: Совпадение имен функций и миксинов с CSS

Sass стремится к тому, чтобы ваш код был максимально совместим с будущими стандартами CSS. Это изменение вводит предупреждения для пользовательских функций и миксинов, чьи имена совпадают с существующими или потенциальными функциями CSS.

---

## 1. Суть проблемы

CSS постоянно расширяется, добавляя новые функции, такие как `oklch()`, `light-dark()`, `env()` или `var()`. Если вы создаете в Sass функцию с таким же именем, возникает конфликт: компилятор не всегда может однозначно определить, должен ли он выполнить вашу логику или просто вывести строку в CSS для браузера.

Раньше Sass пытался использовать сложную эвристику, чтобы «угадать» ваши намерения, но это часто приводило к ошибкам и мешало внедрению новых возможностей CSS.

---

## 2. Что именно попадает под ограничение?

Теперь Sass выдает предупреждение (**Deprecation Warning**), если вы определяете функцию или миксин с именем, которое зарезервировано CSS или является частью базового синтаксиса.

**Список зарезервированных имен включает (но не ограничивается):**

- **Математика:** `calc()`, `min()`, `max()`, `clamp()`, `abs()`, `round()`, `sin()`, `cos()`.
    
- **Служебные вызовы:** `var()`, `env()`, `url()`, `attr()`.
    
- **Цвета:** `rgb()`, `rgba()`, `hsl()`, `hsla()`.
    
- **Современные функции:** `light-dark()`, `oklch()`, `palette-mix()`.

---

## 3. Примеры: Конфликт и решение

### Ошибочный подход (Устарело)

Вы определяете свою функцию `min` для каких-то внутренних расчетов. Это вызовет конфликт с нативной функцией CSS `min()`.

```SCSS
// Это вызовет предупреждение в консоли
@function min($a, $b) {
  @if $a < $b { @return $a; }
  @else { @return $b; }
}

.box {
  // Непонятно: это вызов вашей функции или CSS-функции?
  width: min(10px, 20px);
}
```

### Правильный подход

Чтобы избежать проблем, используйте уникальные имена или встроенные модули Sass.

```SCSS
// Решение 1: Добавление префикса (пространство имен)
@function app-min($a, $b) { ... }

// Решение 2: Использование встроенного модуля
@use "sass:math";

.box {
  width: math.min(10px, 20px); // Теперь всё однозначно
}
```

---

## 4. Почему это важно для будущего?

Если Sass позволит вам «перехватывать» имя `calc()`, вы лишитесь возможности использовать настоящий CSS `calc()` в его оригинальном виде. Резервируя эти имена, Sass гарантирует, что нативные возможности браузера всегда будут доступны без конфликтов.

---

## 5. Исключения

- **Регистр:** Хотя CSS-функции нечувствительны к регистру, Sass-функции чувствительны. Тем не менее, Sass всё равно будет предупреждать даже при использовании другого регистра (например, `Min()` или `CALC()`), чтобы предотвратить путаницу и ошибки при написании кода.
    
- **Вендорные префиксы:** Имена вроде `-webkit-calc()` обычно не вызывают предупреждений, так как они специфичны для конкретных движков и вряд ли станут частью глобального стандарта Sass.

---

## 6. График внедрения

- **Dart Sass 1.80.0+**: Начинают появляться предупреждения о том, что выбранное имя для функции или миксина совпадает с CSS.
    
- **Sass 2.0.0**: Это станет фатальной ошибкой. Вы не сможете скомпилировать проект, если в нем определены функции с именами вроде `min` или `calc`.

> [!TIP]
> 
> Лучшая стратегия сейчас — проверить свои проекты на наличие «коротких» имен функций и добавить к ним префиксы, соответствующие вашему проекту или бренду (например, `utils-calc()` вместо `calc()`).
