# Критическое изменение: Ограничение `@extend` для составных селекторов

Директива `@extend` — один из самых мощных и одновременно сложных инструментов Sass. Она позволяет одному селектору наследовать стили другого. Однако использование `@extend` с **составными селекторами** (compound selectors) приводило к созданию избыточного, запутанного и тяжелого для браузера CSS-кода. В связи с этим Sass вводит ограничение на этот функционал.

---

## 1. Что такое составной селектор?

**Составной селектор** — это последовательность простых селекторов, которые не разделены комбинаторами (такими как пробел, `>`, `+` или `~`).

- **Простой селектор:** `.button`, `a`, `%placeholder`.
    
- **Составной селектор:** `a.important`, `.header.active`, `input[type="text"]`.

---

## 2. Суть изменения

Ранее Sass позволял использовать `@extend` для таргетинга составного селектора целиком.

**Новое правило:** Вы больше не можете расширять (extend) составной селектор. Можно расширять только **одиночные простые селекторы** (чаще всего это классы или плейсхолдеры).

---

## 3. Почему это изменилось?

Использование `@extend` с составными селекторами порождало «комбинаторный взрыв» в итоговом CSS.

**Пример проблемы:**

Если вы расширяете `.a.b`, Sass должен найти в вашем коде все упоминания `.a` и `.b`, которые встречаются вместе, и добавить туда ваш новый селектор. Но что если в коде есть `.a.b.c` или `.a.d.b`? Sass пытался вычислить все возможные комбинации, чтобы гарантировать применение стилей, что приводило к генерации огромных простыней селекторов, которые практически невозможно отлаживать.

---

## 4. Примеры: Как было и как стало

### Ошибочный синтаксис (Устарело)

```SCSS
.alert.is-important {
  background-color: red;
}

.error-message {
  // ТЕПЕРЬ ЭТО ВЫЗЫВАЕТ ПРЕДУПРЕЖДЕНИЕ ИЛИ ОШИБКУ
  @extend .alert.is-important;
}
```

### Рекомендуемый подход (Placeholder)

Лучший способ решить эту задачу — использовать плейсхолдеры (`%`). Плейсхолдеры специально созданы для `@extend` и не создают лишнего мусора в CSS.

```SCSS
%important-alert {
  background-color: red;
}

.alert.is-important {
  @extend %important-alert;
}

.error-message {
  @extend %important-alert;
}
```

---

## 5. Как исправить существующий код

Если в вашем проекте используется расширение составных селекторов, воспользуйтесь одной из следующих стратегий:

1. **Разделение на простые селекторы:** Расширьте каждый класс по отдельности (если логика это позволяет).
    
    - _Вместо:_ `@extend .a.b;`
        
    - _Сделайте:_ `@extend .a; @extend .b;`
        
2. **Использование плейсхолдеров (лучший вариант):** Вынесите общие стили в `%placeholder` и расширяйте его там, где это необходимо.
    
3. **Использование миксинов:** Если наследование через `@extend` становится слишком сложным, замените его на `@include`. Это немного увеличит размер CSS-файла (за счет дублирования свойств), но избавит от проблем с запутанными селекторами и значительно ускорит компиляцию.

---

## 6. Сроки внедрения

- **Текущий статус:** Использование `@extend` с составными селекторами выдает **Deprecation Warning**.
    
- **Sass 2.0.0:** Этот синтаксис станет фатальной ошибкой.
    

### Резюме

Это изменение направлено на повышение предсказуемости Sass. Ограничивая `@extend` простыми селекторами, разработчики Sass гарантируют, что итоговый CSS будет чистым, а процесс его генерации — быстрым и надежным.
