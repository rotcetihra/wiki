# Критическое изменение: Неправильное расположение "Rest"-аргументов (`...`)

В Sass аргументы с многоточием (`...`), также известные как **rest arguments** (остаточные аргументы) или **spread operator** (оператор расширения), позволяют передавать или принимать неопределенное количество значений. Это критическое изменение делает правила их использования более строгими и логичными, приводя их в соответствие с другими языками программирования (например, JavaScript).

---

## 1. Суть изменения

Ранее Sass позволял размещать аргумент с `...` в середине списка параметров при определении миксина/функции или при их вызове.

**Новое правило:** Аргумент с многоточием **обязательно должен быть последним** в списке. Любой код, где после `...` идет другой аргумент, теперь считается устаревшим и со временем станет ошибкой.

---

## 2. Почему это изменилось?

1. **Однозначность:** Когда «остаток» находится в середине, компилятору и разработчику сложно понять, какие именно значения должны попасть в этот список, а какие — в последующие именованные аргументы.
    
2. **Совместимость с CSS:** Современный CSS (например, функции `clamp()`, `min()`, `max()`) и будущие стандарты требуют четкой структуры параметров.
    
3. **Стандартизация:** Почти во всех современных языках программирования rest-параметры могут быть только в конце.

---

## 3. Примеры: Как делать нельзя и как правильно

### При объявлении (Parameters)

```SCSS
// УСТАРЕЛО (Вызывает предупреждение):
@mixin syntax-error($args..., $last-arg) {
  // Логика...
}

// ПРАВИЛЬНО:
@mixin correct-syntax($first-arg, $rest...) {
  // Логика...
}
```

### При вызове (Arguments)

```SCSS
$colors: red, green, blue;

// УСТАРЕЛО:
.element {
  color: my-function($colors..., #fff);
}

// ПРАВИЛЬНО:
.element {
  color: my-function(#fff, $colors...);
}
```

---

## 4. Как исправить существующий код

Если вы получили предупреждение **"Variable arguments must be at the end of the argument list"**, вам необходимо изменить порядок аргументов:

1. **Переставьте обязательные аргументы в начало:** Если у вас есть именованные параметры, которые должны идти после списка, переместите их перед списком.
    
2. **Используйте ключевые слова:** Если вы не можете изменить порядок (например, во внешней библиотеке), передавайте аргументы, идущие после "остатка", как именованные аргументы, но это все равно потребует того, чтобы `...` стоял в конце вызова.

> **Важное примечание:** Если вы вызываете встроенные функции Sass (например, `meta.call()`), убедитесь, что `$args...` всегда является финальным аккордом в скобках.

---

## 5. Влияние на `arglist`

Тип данных `arglist` (специальный список, создаваемый rest-параметрами) по-прежнему собирает все лишние позиционные аргументы. Это изменение никак не ограничивает возможности Sass, оно лишь наводит порядок в синтаксисе, делая его более читаемым.
