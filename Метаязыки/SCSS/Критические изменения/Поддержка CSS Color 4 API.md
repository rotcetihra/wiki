# Критическое изменение: Поддержка CSS Color 4 API

Это обновление превращает Sass из простого препроцессора в мощный инструмент для работы с цветом нового поколения. CSS Color Module Level 4 принес в браузеры невероятную глубину цвета и новые способы его описания, и Sass полностью пересмотрел свой внутренний «движок», чтобы соответствовать этим стандартам.

---

## 1. Зачем это нужно? (The Big Picture)

Раньше мир веба был ограничен пространством **sRGB** (те самые `rgb()`, `hex` и `hsl()`). Современные мониторы и смартфоны поддерживают гораздо больше цветов (**Wide Gamut**), и CSS Color 4 позволяет их использовать.

Sass обновил свой API, чтобы вы могли:

1. Работать в новых цветовых пространствах (Lab, OKLCH, Display P3).
    
2. Сохранять высокую точность цвета при расчетах.
    
3. Использовать ключевое слово `none` для «отсутствующих» компонентов цвета.

---

## 2. Новые цветовые пространства

Sass теперь понимает, что цвет — это не просто три цифры, а точка в определенном пространстве.

|**Пространство**|**Описание**|**Зачем использовать?**|
|---|---|---|
|**OKLCH**|Основано на человеческом восприятии.|Самый интуитивный способ менять яркость, не меняя оттенок.|
|**Lab / LCH**|Охватывает весь спектр видимых человеком цветов.|Идеально для максимально точной цветопередачи.|
|**Display P3**|Стандарт для современных экранов Apple и Android.|Позволяет выводить более сочные и яркие цвета, чем sRGB.|

---

## 3. Изменения в функциях модуля `sass:color`

API стал более строгим и мощным. Функции теперь принимают аргумент `$space`, который определяет, в каком «мире» будут происходить расчеты.

### `color.mix()`

Теперь вы можете смешивать цвета не только как «краски», но и с учетом физики света в разных пространствах. Смешивание в `oklch` дает гораздо более естественные градиенты без «серых зон» в середине.

```SCSS
@use "sass:color";

// Смешивание в пространстве OKLCH для чистого перехода
$mixed: color.mix(blue, red, $space: oklch);
```

### `color.adjust()`, `color.scale()`, `color.change()`

Эти функции были расширены для поддержки новых компонентов:

- `$chroma`: Насыщенность (для LCH/OKLCH).
    
- `$whiteness` / `$blackness`: Для пространства HWB.
    
- `$lightness`: Теперь работает корректно во всех пространствах.

---

## 4. Перцептивная равномерность (OKLCH)

Одним из главных нововведений является поддержка **OKLCH**. В отличие от старого HSL, где желтый кажется ярче синего при одинаковом параметре Lightness, в OKLCH яркость $L$ действительно соответствует тому, что видит глаз.

> **Почему это важно?** Теперь создание доступных (accessible) цветовых схем с правильным контрастом стало математически простым.

---

## 5. Обработка «выхода за пределы» (Gamut Mapping)

Когда вы вычисляете очень яркий цвет в OKLCH и пытаетесь вывести его в старом `rgb()`, он может «не поместиться» в возможности sRGB.

- Sass теперь умеет корректно обрабатывать такие ситуации.
    
- Вы можете использовать `color.is-in-gamut()`, чтобы проверить, увидит ли пользователь этот цвет на обычном мониторе.
    
- Функция `color.to-gamut()` поможет «втиснуть» супер-яркий цвет в рамки стандартного CSS без резких искажений тона.

---

## 6. Как это влияет на ваш код (Миграция)

1. **Строгость параметров:** Теперь нельзя просто передать «что-то» в качестве альфа-канала или яркости. Sass будет проверять, имеет ли значение смысл для выбранного пространства.
    
2. **Сериализация:** Если вы используете новые цвета, Sass выведет их в современном формате: `color(display-p3 1 0.5 0)` или `oklch(70% 0.1 150)`. Убедитесь, что ваши целевые браузеры их поддерживают (или используйте PostCSS для фолбеков).
    
3. **Ключевое слово `none`:** Теперь компоненты цвета могут быть «пустыми» (`none`). Это полезно при интерполяции цветов:

```SCSS
// Цвет с неопределенным оттенком
$color: oklch(70% 0.1 none); 
```

---

### Итог

Переход на Color 4 API в Sass — это прыжок от «рисования фломастерами» к «профессиональной цветокоррекции». Если вы занимаетесь современным дизайном, самое время начать использовать `oklch` и модуль `sass:color` с указанием `$space`.
