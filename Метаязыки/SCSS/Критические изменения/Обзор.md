# Критические изменения (Breaking Changes) в Sass

Sass активно развивается, стремясь к полной совместимости с современным CSS и устранению архитектурных ошибок прошлого. Критические изменения — это запланированные обновления, которые нарушают обратную совместимость ради долгосрочной стабильности и производительности языка.

---

## 1. Новая система модулей (`@import` → `@use`)

Это самое масштабное изменение в истории Sass. Директива `@import` признана устаревшей и в будущем будет полностью удалена.

**Проблема `@import`:**

- **Глобальная область видимости:** Все переменные, миксины и функции становятся глобальными. Сложно понять, откуда пришел конкретный стиль.
    
- **Конфликты имен:** Если два импортированных файла имеют переменную `$color`, один перезапишет другой.
    
- **Дублирование кода:** Если файл импортируется несколько раз, его содержимое дублируется в итоговом CSS.
    

**Решение: `@use` и `@forward`**

- **Инкапсуляция:** Файлы теперь являются «модулями». К их содержимому нужно обращаться через пространство имен (имя файла).
    
- **Однократная загрузка:** Модуль загружается один раз, сколько бы раз вы его ни вызывали.

|**Характеристика**|**Старый подход (@import)**|**Новый подход (@use)**|
|---|---|---|
|**Доступ к переменным**|Глобальный (`$primary`)|Через префикс (`theme.$primary`)|
|**Область видимости**|Всегда глобальная|Локальная для модуля|
|**Производительность**|Медленно (повторные рендеры)|Быстро (кеширование модулей)|

## 2. Деление и оператор `/`

Sass долгое время использовал символ `/` для деления. Однако в CSS этот символ стал активно использоваться как разделитель (например, в `font: 12px/1.5` или `grid-area: 1 / 2`).

**Изменение:**

Использование `/` для деления теперь **запрещено** (вызывает предупреждение, а в будущем — ошибку). Для деления необходимо использовать функцию `math.div()` из модуля `sass:math`.

```SCSS
// Устарело
$width: 100px / 2;

// Современный стандарт
@use "sass:math";
$width: math.div(100px, 2);
```

> **Важно:** Если вам нужно вывести символ `/` в CSS (например, для шрифтов), используйте интерполяцию: `font: #{$size}/#{$line-height}`.

## 3. Строгость единиц измерения (Unit Strictness)

Раньше Sass позволял некоторые математически некорректные операции с единицами измерения. Теперь правила стали строже для предотвращения багов.

- **Сравнение:** `1px == 1` теперь возвращает `false`. Число с единицами никогда не равно числу без них.
    
- **Математика:** Попытка сложить `10px + 5em` вызовет ошибку на этапе компиляции, так как Sass не может знать значение `em` без контекста браузера.
    
- **Умножение:** Умножение `10px * 10px` теперь дает результат `100px*px` (квадратные пиксели). Хотя CSS это не поймет, это математически верно. Для получения `100px` нужно умножать число с единицей на число без единицы.

## 4. Обновление функций цвета

Глобальные функции цвета, такие как `lighten()`, `darken()`, `saturate()`, признаны устаревшими.

**Почему?**

Эти функции были недостаточно гибкими и часто давали непредсказуемые результаты при работе с очень темными или светлыми цветами.

**Замена:**

Используйте `color.adjust()` или `color.scale()` из модуля `sass:color`. Они позволяют более точно настраивать каналы цвета (RGB, HSL, HWB).

```SCSS
@use "sass:color";

// Вместо lighten($color, 10%)
$new-color: color.scale($color, $lightness: 10%);
```

## 5. Изменения в JS API

Для разработчиков, использующих Sass через Node.js, произошел переход с **Legacy API** на **Modern API**.

- **Legacy API (`render`, `renderSync`):** Медленное, не поддерживает новые функции модулей.
    
- **Modern API (`compile`, `compileAsync`):** Значительно быстрее, поддерживает все современные фишки Sass и предоставляет более удобные интерфейсы для кастомных импортеров.

## Как справляться с изменениями: Sass Migrator

Чтобы не переписывать тысячи строк кода вручную, команда Sass разработала инструмент **Sass Migrator**. Он автоматически обновляет ваш код, заменяя устаревшие конструкции на актуальные.

**Основные команды мигратора:**

- `sass-migrator module --migrate-deps <entrypoint>` — переводит проект на систему `@use`.
    
- `sass-migrator division <entrypoint>` — заменяет деление через `/` на `math.div`.
    

### Рекомендации по переходу

1. **Сначала обновите компилятор:** Убедитесь, что вы используете последнюю версию Dart Sass.
    
2. **Слушайте предупреждения:** Не игнорируйте `Deprecation Warnings` в консоли — они указывают на места, которые сломаются в следующем мажорном релизе.
    
3. **Используйте пространство имен:** При переходе на `@use` старайтесь давать модулям короткие и понятные псевдонимы: `@use "variables" as v`.
    

Эти изменения могут показаться болезненными в краткосрочной перспективе, но они делают Sass более мощным, быстрым и соответствующим современным стандартам веб-разработки.
