# Критическое изменение: Запрет `null` в качестве альфа-канала

Это изменение устраняет непоследовательность в работе функций цвета. Ранее в некоторых функциях (например, `rgba()` или `color.change()`) передача `null` в качестве значения альфа-канала (прозрачности) могла игнорироваться или интерпретироваться как «отсутствие изменений». Теперь это официально считается устаревшим.

---

## 1. Что именно изменилось?

Теперь Sass требует, чтобы аргумент альфа-канала, если он передан, был **числом от 0 до 1** (или соответствующим процентом). Передача значения `null` больше не поддерживается для параметров, отвечающих за прозрачность.

Это касается следующих функций:

- Встроенная функция `rgba($color, $alpha)`.
    
- Функции модуля `sass:color`: `color.change()`, `color.adjust()`, `color.scale()`, `color.mix()`.

---

## 2. Почему это важно?

1. **Предсказуемость:** В программировании `null` обычно означает отсутствие значения. Однако в функциях цвета Sass возникла путаница: должен ли `null` сбрасывать прозрачность до 1.0, оставлять её прежней или вызывать ошибку?
    
2. **Типизация:** Sass стремится к более строгой проверке типов. Альфа-канал — это строго числовой параметр, и допущение `null` создавало «серые зоны» в логике кода.
    
3. **Единообразие:** Другие параметры цвета (красный, синий, насыщенность) уже давно не принимают `null` подобным образом. Это обновление приводит работу с прозрачностью к общему стандарту.

---

## 3. Примеры: Как было и как стало

Самый частый случай — динамическая передача переменной, которая может оказаться пустой.

### Ошибочный синтаксис (Устарело)

```SCSS
$my-opacity: null;
$base-color: #ff0000;

// Раньше: Sass мог просто вернуть красный цвет без изменений
// Теперь: Выдаст предупреждение (Deprecation Warning)
.element {
  color: rgba($base-color, $my-opacity);
}
```

### Корректный синтаксис

Если вы хотите изменить прозрачность только в том случае, если значение существует, используйте стандартные инструменты Sass для проверки условий или функции модуля `color`.

```SCSS
@use "sass:color";

$my-opacity: null;
$base-color: #ff0000;

.element {
  // Вариант 1: Условная проверка
  color: if($my-opacity != null, rgba($base-color, $my-opacity), $base-color);

  // Вариант 2: Использование именованных аргументов (просто не передавайте alpha)
  color: color.change($base-color, $alpha: $my-opacity or 1.0);
}
```

---

## 4. Как исправить существующий код

Если вы столкнулись с предупреждением **"Passing null for the alpha parameter is deprecated"**, выполните следующие шаги:

1. **Проверьте переменные:** Найдите места, где в `rgba()` или функции `color` попадает переменная, которая может быть `null`.
    
2. **Удалите лишние аргументы:** Если ваша цель — оставить альфа-канал неизменным, просто не передавайте этот аргумент в функцию.
    
3. **Используйте значения по умолчанию:** Если переменная может быть `null`, задайте ей значение по умолчанию (например, `1` для полной непрозрачности) до того, как передать в функцию цвета.

---

## 5. Сроки внедрения

- **Текущий статус:** Dart Sass выдает **Deprecation Warning**. Код пока продолжает работать, но заваливает консоль предупреждениями.
    
- **Sass 2.0.0:** Передача `null` в качестве альфа-канала станет **фатальной ошибкой**, и компиляция проекта будет остановлена.

> [!NOTE]
> 
> Это изменение делает ваш код более надежным: если функция ожидает число для настройки прозрачности, она должна его получить. Это избавляет от «магии» незаметного игнорирования пустых переменных.
