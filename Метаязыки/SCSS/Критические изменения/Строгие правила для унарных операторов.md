# Критическое изменение: Строгие правила для унарных операторов

В Sass унарные операторы (плюс `+` и минус `-`) используются для обозначения положительных или отрицательных чисел (например, `-5`). Однако те же самые символы используются как бинарные операторы для сложения и вычитания. Чтобы устранить неоднозначность в коде, Sass вводит более строгие правила синтаксиса для их использования.

---

## 1. Суть проблемы: Неоднозначность списков

Основная причина изменений — конфликт между математическим вычитанием и списком элементов. В CSS пробелы часто используются для разделения значений в списке.

Рассмотрим пример:

`margin: 10px -5px;`

Здесь `-5px` — это отрицательное число (унарный минус), а всё выражение — список из двух значений. Однако в некоторых случаях Sass мог ошибочно интерпретировать это как вычитание: `10px` минус `5px` равно `5px`.

---

## 2. Новые правила синтаксиса

Теперь интерпретация символа зависит от наличия пробелов вокруг него:

1. **Бинарный оператор (Вычитание/Сложение):** Должен быть отделен пробелами с обеих сторон ИЛИ не иметь пробелов вовсе (но это не рекомендуется для читаемости).
    
2. **Унарный оператор (Отрицание/Положительное число):** Должен иметь пробел **перед** собой, но **не иметь** пробела после себя.
    

### Таблица интерпретации символа `-`

|**Пример**|**Интерпретация**|**Результат**|
|---|---|---|
|`10px - 5px`|Бинарный (Вычитание)|`5px`|
|`10px -5px`|Унарный (Список)|`10px` и `-5px`|
|`10px-5px`|Бинарный (Вычитание)|`5px` (Вызывает предупреждение)|

---

## 3. Что считается ошибкой (Deprecation)

Sass теперь выдает предупреждение, если унарный оператор используется сразу после другого значения без четкого разделения, которое могло бы привести к путанице.

Самый проблемный случай — когда оператор стоит **после** пробела, но за ним следует не число, а переменная или вызов функции без скобок.

```SCSS
// УСТАРЕЛО (Вызывает предупреждение)
$val: 5px;
.element {
  margin: 10px -$val; // Непонятно: это список или 10px минус $val?
}

// ПРАВИЛЬНО (Для списка)
.element {
  margin: 10px (-$val); // Используйте скобки для ясности
}

// ПРАВИЛЬНО (Для вычитания)
.element {
  margin: 10px - $val; // Пробелы с обеих сторон
}
```

---

## 4. Рекомендации по исправлению

Чтобы ваш код был стабильным и понятным как для компилятора, так и для других разработчиков:

- **Всегда ставьте пробелы вокруг `+` и `-`**, если вы хотите выполнить арифметическую операцию.
    
- **Используйте скобки**, если вы передаете отрицательную переменную в список или в качестве аргумента функции: `padding: 10px (-$offset)`.
    
- **Избегайте записи `10px-5px`**. Хотя это технически работает как вычитание, отсутствие пробелов делает код трудночитаемым и провоцирует ошибки при добавлении переменных.

---

## 5. Исключения

Правила не применяются внутри конструкций, где синтаксис CSS жестко определен и не допускает неоднозначности:

- Внутри функций `calc()`, `min()`, `max()`, `clamp()`.
    
- В селекторах (например, `n-1` в `:nth-child`).
    

Эти изменения делают парсинг Sass более надежным и предотвращают ситуации, когда небольшое изменение отступа или переменной могло кардинально изменить итоговый CSS.
