# Критическое изменение: Отказ от `@import` в пользу модульной системы

Директива `@import` долгие годы была основой Sass, но она имела фундаментальные недостатки, которые мешали масштабированию крупных проектов. В современном Sass (Dart Sass) `@import` официально признан устаревшим и будет полностью удален в будущих мажорных версиях. Его заменяет современная система модулей: `@use` и `@forward`.

---

## Почему `@import` признан устаревшим?

Главная проблема `@import` заключалась в том, что он работал по принципу простого объединения файлов в одно гигантское глобальное пространство. Это порождало три критические проблемы:

1. **Загрязнение глобального пространства (Namespace Pollution):** Все переменные, миксины и функции становились доступны везде. Если два разных файла использовали переменную `$color`, один из них неизбежно перезаписывал другой, что приводило к труднодоступным багам.
    
2. **Непрозрачность:** Глядя на код `.element { color: $primary; }`, невозможно было понять, в каком именно файле определена переменная `$primary`, не перерывая весь проект.
    
3. **Дублирование кода:** Если файл `_base.scss` импортировался в пять разных файлов, которые затем объединялись, содержимое `_base.scss` могло пять раз дублироваться в итоговом CSS, раздувая его размер.

---

## Новая система: Директива `@use`

Директива `@use` загружает файл как **модуль**. Это означает, что всё содержимое файла остается внутри его собственного пространства имен.

- **Инкапсуляция:** Переменные и миксины не "утекают" в глобальную область.
    
- **Безопасность:** Вы четко видите, откуда пришел конкретный инструмент.
    
- **Оптимизация:** Сколько бы раз вы ни вызывали `@use` для одного и того же файла, Sass скомпилирует его только один раз.
    

### Пример синтаксиса

```SCSS
// _colors.scss
$primary: #3498db;

// main.scss
@use "colors";

.button {
  background-color: colors.$primary; // Обращение через пространство имен
}
```

Для удобства можно использовать псевдонимы:

`@use "long-file-name" as c;` $\rightarrow$ `c.$variable;`.

---

## Управление библиотеками: Директива `@forward`

Если `@use` предназначен для потребления инструментов, то `@forward` — для их организации. Она позволяет собрать несколько маленьких модулей в один большой "входной файл" библиотеки, не делая их содержимое доступным в самом этом файле.

```SCSS
// Входной файл библиотеки: _index.scss
@forward "buttons";
@forward "forms";
@forward "typography";
```

Это позволяет пользователям вашей библиотеки подключить один файл и получить доступ ко всем её инструментам.

---

## Настройка модулей через `with`

Поскольку `@use` не является глобальным, старый способ переопределения переменных (просто объявить переменную перед импортом) больше не работает. Теперь для настройки модулей используется конструкция `with`.

```SCSS
// _library.scss
$theme: "light" !default;

// main.scss
@use "library" with (
  $theme: "dark"
);
```

## График прекращения поддержки

Команда Sass установила четкие этапы вывода `@import` из эксплуатации:

|**Этап**|**Состояние**|
|---|---|
|**Dart Sass 1.23.0**|Внедрена система модулей (`@use`).|
|**Октябрь 2022**|Директива `@import` помечена как `deprecated`. Появились предупреждения в консоли.|
|**Sass 3.0.0 / 4.0.0**|Полное удаление поддержки `@import`. Код с этой директивой перестанет компилироваться.|

## Инструмент для автоматической миграции

Для перевода старых проектов на новую систему не обязательно вручную переписывать каждый файл. Разработан официальный инструмент **Sass Migrator**, который автоматически заменяет `@import` на `@use`, расставляет префиксы и создает файлы `@forward`.

**Установка и запуск:**

```Bash
npm install -g sass-migrator
sass-migrator module --migrate-deps main.scss
```

Флаг `--migrate-deps` гарантирует, что инструмент пройдет по всей цепочке зависимостей и обновит все связанные файлы проекта.

> **Важно:** Переход на модульную систему — это не просто смена синтаксиса, а переход к более чистой, предсказуемой и производительной архитектуре CSS. Чем раньше проект откажется от `@import`, тем проще будет его поддержка в долгосрочной перспективе.
