# Критическое изменение: Ограничение настройки приватных переменных через `@use ... with`

В системе модулей Sass существует четкое разграничение между публичными и приватными членами (переменными, функциями и миксинами). Это критическое изменение касается того, как внешние файлы могут взаимодействовать с внутренними настройками модулей через конструкцию `@use ... with`.

---

## 1. Что такое приватные члены в Sass?

В Sass любой член модуля считается **приватным**, если его имя начинается с символа подчеркивания (`_`) или дефиса (`-`).

- **Публичные:** `$primary-color`, `@mixin button-style`. Доступны везде.
    
- **Приватные:** `$_internal-spacing`, `@mixin -helper-logic`. Доступны только внутри того файла, где они определены.
    

Приватные члены созданы для того, чтобы авторы библиотек могли скрывать детали реализации, которые не предназначены для использования или изменения конечными пользователями.

---

## 2. Суть изменения

Ранее в Sass существовала лазейка: пользователь мог переопределить значение даже приватной переменной, используя предложение `with` при импорте модуля через `@use`.

**Изменение:** Теперь попытка настроить переменную, имя которой начинается с `_` или `-`, через конструкцию `@use ... with` считается **устаревшей (deprecated)**. В будущих версиях Sass это будет приводить к **ошибке компиляции**.

---

## 3. Почему это важно? (Инкапсуляция)

Разрешение изменять приватные переменные извне нарушает принцип **инкапсуляции**.

1. **Стабильность:** Если разработчик библиотеки пометил переменную как приватную, он рассчитывает, что может безопасно переименовать или удалить её в любой момент.
    
2. **Предсказуемость:** Если пользователи начинают полагаться на внутренние переменные, это «связывает руки» автору библиотеки — любое внутреннее изменение может сломать код у тысяч пользователей.
    
3. **Безопасность:** Приватные переменные часто используются для промежуточных расчетов, которые не должны зависеть от внешнего ввода.

---

## 4. Примеры: Как было и как стало

### Файл библиотеки (`_library.scss`):

```SCSS
// Приватная переменная, которую автор не планировал делать настраиваемой
$_internal-multiplier: 2 !default;

@function calculate($value) {
  @return $value * $_internal-multiplier;
}
```

### Файл пользователя (Ошибка):

```SCSS
// РАНЬШЕ: Работало, но теперь выдает предупреждение
// В БУДУЩЕМ: Ошибка компиляции
@use "library" with (
  "_internal-multiplier": 5
);

.element {
  width: library.calculate(10px);
}
```

---

## 5. Как исправить код

Если вы столкнулись с этим предупреждением, у вас есть два пути решения в зависимости от вашей роли.

### Если вы автор библиотеки:

Если вы хотите, чтобы пользователи могли настраивать переменную, вы **должны сделать её публичной**, удалив подчеркивание или дефис в начале имени.

```SCSS
// Было
$_config: default !default;

// Стало
$config: default !default;
```

### Если вы пользователь библиотеки:

1. **Проверьте документацию:** Скорее всего, библиотека предоставляет публичные переменные для настройки тех же параметров.
    
2. **Свяжитесь с автором:** Если нужный вам параметр скрыт за приватной переменной, попросите автора сделать её публичной (открыть API).
    
3. **Используйте обходные пути (не рекомендуется):** Если изменение критично, а библиотеку нельзя поправить, вам придется искать другие способы влияния на стили (например, через CSS-переменные или переопределение миксинов), но прямое вмешательство в приватную логику через `with` должно быть прекращено.

---

## 6. Технические подробности и логика `!default`

Важно помнить, что настройка через `with` работает только для тех переменных, которые помечены флагом `!default`. Если переменная приватная и имеет флаг `!default`, она все равно остается недоступной для внешней настройки. Это изменение делает поведение Sass более логичным и строгим.

### Итог

Это изменение направлено на создание более надежной экосистемы модулей. Оно заставляет разработчиков явно определять границы своего API, разделяя "внутреннюю кухню" проекта и инструменты, предназначенные для конечного пользователя.
