# Критическое изменение: Обработка `@-moz-document`

Директива `@-moz-document` — это нестандартное расширение браузера Firefox, которое позволяло применять стили в зависимости от URL-адреса страницы. В рамках очистки языка Sass от устаревших и специфических функций, специальная поддержка этого правила прекращается.

---

## 1. Суть изменения

Раньше Sass имел специальный встроенный парсер для `@-moz-document`. Это позволяло использовать функции внутри заголовка правила (такие как `url()`, `url-prefix()`, `domain()`) без кавычек или с особым синтаксисом, который не соответствует стандартному CSS.

**Что изменилось:** Теперь Sass обрабатывает `@-moz-document` как **обычное неизвестное at-правило**. Это значит, что Sass больше не пытается «понять» его внутреннюю структуру и требует, чтобы синтаксис соответствовал общим правилам CSS.

---

## 2. Почему это произошло?

1. **Отказ Firefox:** Сама компания Mozilla (разработчик Firefox) давно ограничила поддержку `@-moz-document`. Сейчас это правило работает только для внутренних страниц браузера (например, `about:config`) или в специфических пользовательских стилях (userContent.css), и практически не используется в обычной веб-разработке.
    
2. **Стандартизация:** Одной из целей Sass является максимальное соответствие стандартам CSS. Поддержка уникального парсера для одного устаревшего вендорного правила усложняет компилятор.
    
3. **Упрощение поддержки:** Удаление специальных случаев парсинга делает Sass быстрее и стабильнее.

---

## 3. Примеры: Как было и как стало

Наибольшие проблемы возникают с использованием функций без кавычек, которые раньше Sass «прощал».

### Устаревший синтаксис (Вызывает предупреждение)

```SCSS
// Ошибка: url-prefix без кавычек воспринимался специальным парсером
@-moz-document url-prefix(http://www.w3.org/Style/) {
  body { color: red; }
}
```

### Современный синтаксис (Правильно)

Чтобы код продолжал работать и не вызывал предупреждений, значения функций должны быть обернуты в кавычки, чтобы они выглядели как валидные токены CSS для общего парсера.

```SCSS
// Правильно: аргументы в кавычках
@-moz-document url-prefix("http://www.w3.org/Style/") {
  body { color: red; }
}
```

---

## 4. Как исправить существующий код

Если вы всё ещё используете это правило (например, для специфических хаков под старые версии Firefox), выполните следующие действия:

- **Добавьте кавычки:** Убедитесь, что все URL, домены и префиксы внутри `@-moz-document` обернуты в `" "` или `' '`.
    
- **Используйте интерполяцию:** Если вы динамически подставляете значения, используйте `#{}`.

```SCSS
$prefix: "http://example.com/";

// Использование интерполяции гарантирует корректный парсинг
@-moz-document url-prefix("#{$prefix}") {
  .header { display: none; }
}
```

---

## 5. Сроки внедрения

1. **Dart Sass 1.7.2:** Введены первые предупреждения об устаревании специального парсинга.
    
2. **Текущий статус:** Использование старого синтаксиса выдает `Deprecation Warning`.
    
3. **Sass 2.0.0:** Специальная поддержка будет полностью удалена. Правила `@-moz-document` с нестандартным синтаксисом будут вызывать ошибку компиляции.
    

### Итог

Это изменение практически не затронет современную веб-разработку, так как нативные альтернативы (такие как проверка фич через `@supports`) полностью заменили старые браузерные хаки. Если ваш проект всё ещё содержит такие правила, просто приведите их к стандартному строковому виду.
