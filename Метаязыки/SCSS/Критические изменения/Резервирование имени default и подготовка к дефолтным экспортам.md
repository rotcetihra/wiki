# Критическое изменение: Резервирование имени `default` и подготовка к дефолтным экспортам

Sass активно развивается в сторону сближения с современными стандартами веб-разработки, такими как **ES Modules (JavaScript)**. Данное изменение подготавливает систему модулей Sass к поддержке «экспорта по умолчанию» (default export), что сделает интеграцию между CSS, Sass и JS более бесшовной.

---

## 1. Суть изменения

В будущих версиях Sass каждый модуль сможет иметь один **дефолтный экспорт** — основной элемент (переменную, миксин или функцию), который можно будет использовать без указания конкретного имени при импорте.

Для реализации этой возможности Sass вводит следующие ограничения:

- **Резервирование слова:** Имя `default` теперь является зарезервированным для членов модуля.
    
- **Запрет на использование:** Вы больше не можете определять переменные, функции или миксины с именем `default`.

---

## 2. Что именно считается устаревшим?

Любое объявление члена модуля с именем `default` теперь вызывает предупреждение (**deprecation warning**). Это касается:

- **Переменных:** `$default: ...;`
    
- **Функций:** `@function default() { ... }`
    
- **Миксинов:** `@mixin default { ... }`

> [!IMPORTANT]
> 
> Если в вашем коде уже используются такие имена, они будут конфликтовать с будущим синтаксисом дефолтных экспортов, поэтому их необходимо переименовать.

---

## 3. Примеры: Как было и как нужно исправить

### Ошибочный синтаксис (Устарело)

```SCSS
// Это вызовет предупреждение
$default: #333;

@mixin default {
  margin: 0;
  padding: 0;
}

.element {
  @include default;
  color: $default;
}
```

### Корректный синтаксис

Рекомендуется заменить `default` на более описательное имя, отражающее суть элемента (например, `standard`, `base`, `main` или `initial`).

```SCSS
// Исправленный вариант
$base-color: #333;

@mixin reset-styles {
  margin: 0;
  padding: 0;
}

.element {
  @include reset-styles;
  color: $base-color;
}
```

---

## 4. Почему это важно?

1. **Совместимость с JS:** Поскольку экосистема фронтенда всё чаще использует общие инструменты (например, переменные из Sass-модулей импортируются в JS через Vite или Webpack), использование ключевого слова `default` позволяет Sass-модулям вести себя так же, как и JS-модули.
    
2. **Упрощение импорта:** В будущем это позволит загружать основную логику модуля без необходимости знать точное имя внутренней переменной, например: `@use "theme" as *;` или использование специального синтаксиса для доступа к дефолтному члену.
    
3. **Избежание конфликтов:** Если бы Sass не зарезервировал это имя сейчас, внедрение дефолтных экспортов позже «сломало» бы тысячи проектов, где `default` использовался как обычное имя.

---

## 5. Влияние на `@use` и `@forward`

Это изменение также подготавливает почву для того, как модули будут перенаправлять (forward) контент. В будущем вы сможете явно указывать, какой элемент является дефолтным при объединении нескольких файлов в одну библиотеку.

|**Тип члена**|**Статус имени default**|**Рекомендация**|
|---|---|---|
|**Переменная**|Устарело|Переименовать в `$base` / `$main`|
|**Миксин**|Устарело|Переименовать в `init` / `apply-default`|
|**Функция**|Устарело|Переименовать в `get-default` / `compute`|

---

## 6. Сроки и автоматизация

- **Dart Sass 1.80.0:** Введены официальные предупреждения.
    
- **Sass 2.0.0:** Использование `default` в качестве имени станет фатальной ошибкой.
    

Для быстрого исправления больших проектов рекомендуется использовать поиск и замену с регулярными выражениями, так как текущая версия `sass-migrator` может не иметь отдельной команды именно для этого изменения, поскольку выбор нового имени — задача контекстная.

> **Примечание:** Это изменение не влияет на использование ключевого слова `default` внутри CSS-свойств (например, `cursor: default`) или флаг переменных `!default`. Речь идет только об именах самих Sass-сущностей.
