# Критическое изменение: Логика в `@media` и других At-правилах

Это изменение устраняет конфликт между встроенными логическими операторами Sass (`and`, `or`, `not`) и синтаксисом современных CSS Media Queries (Level 4). Чтобы обеспечить поддержку будущих стандартов CSS, Sass меняет способ интерпретации этих ключевых слов внутри правил `@media` и `@supports`.

---

## 1. Суть проблемы: Конфликт синтаксисов

Исторически Sass обрабатывал слова `and`, `or` и `not` как собственные логические операторы, если они встречались в определенных контекстах. Однако в современной спецификации CSS эти слова также являются частью синтаксиса медиа-запросов (особенно операторы `or` и `not`).

**Проблема:** Если вы хотели использовать нативный CSS-оператор `or` в медиа-запросе, Sass пытался вычислить его как логическую операцию над значениями Sass, что часто приводило к ошибкам компиляции или некорректному выводу.

---

## 2. Что изменилось?

Теперь внутри правил `@media` и `@supports` слова `and`, `or` и `not` рассматриваются как **обычные CSS-идентификаторы** (текст), а не как операторы Sass, за исключением случаев, когда они являются частью явного выражения Sass (например, связаны с переменными).

### Сравнение поведения

|**Контекст**|**Старое поведение (Sass Logic)**|**Новое поведение (CSS Logic)**|
|---|---|---|
|`and`|Обрабатывался как оператор Sass|Передается в CSS как есть|
|`or`|Пытался объединить значения|Передается в CSS как есть|
|`not`|Инвертировал булево значение|Передается в CSS как есть|

---

## 3. Примеры: Как это выглядит в коде

### Использование оператора `or`

Раньше оператор `or` в медиа-запросах был недопустим, так как Sass ожидал, что по обе стороны от него находятся булевы значения (`true`/`false`).

```SCSS
// ТЕПЕРЬ ЭТО ВАЛИДНЫЙ CSS (Media Queries Level 4)
@media (pointer: coarse) or (hover: none) {
  .button { padding: 20px; }
}

// Раньше Sass выдал бы ошибку, так как пытался бы 
// вычислить "(pointer: coarse)" как логическое значение.
```

### Использование оператора `not`

В CSS `not` может применяться к конкретной функции медиа-запроса, а не ко всему выражению целиком.

```SCSS
// CSS-логика (теперь стандарт)
@media not (color) { ... }

// Раньше Sass мог попытаться инвертировать само выражение, 
// если оно было частью переменной.
```

---

## 4. Как сохранить логику Sass?

Если вам всё же необходимо выполнить именно логическую операцию Sass (например, проверить две переменные перед выводом запроса), теперь нужно использовать **интерполяцию** или выполнять вычисления **вне** медиа-запроса.

```SCSS
@use "sass:meta";

$is-mobile: true;
$is-touch: true;

// Чтобы Sass вычислил это как логику:
@media #{$is-mobile and $is-touch} {
  // ...
}
```

---

## 5. Почему это важно для будущего?

1. **Совместимость с браузерами:** Браузеры начинают поддерживать сложные логические связи в CSS. Sass не должен стоять на пути у нативных возможностей языка.
    
2. **Предсказуемость:** Разработчики ожидают, что то, что они пишут в `@media`, будет передано в браузер без изменений, если только они явно не используют переменные.
    
3. **Единообразие:** Это изменение приводит Sass в соответствие с тем, как работают другие современные препроцессоры и инструменты обработки CSS.

---

## 6. Сроки и миграция

- **Dart Sass 1.54.0:** Введены изменения в парсинге логики.
    
- **Предупреждения:** Если ваш старый код полагался на "жадную" логику Sass внутри медиа-запросов, вы увидите предупреждение о необходимости использовать интерполяцию.

> **Рекомендация:** При написании современных медиа-запросов всегда проверяйте их валидность в инструментах разработчика браузера. Если Sass начинает вести себя необычно при встрече с `and`, `or` или `not`, оберните выражение в интерполяцию `#{...}`, чтобы явно указать на необходимость вычислений.
