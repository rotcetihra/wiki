# Критическое изменение: Недопустимые комбинаторы в селекторах

В CSS комбинаторы (такие как `>`, `+`, `~` и `||`) используются для определения отношений между простыми селекторами. Ранее Sass был излишне лоялен к синтаксису и позволял использовать комбинаторы в местах, где они не имеют смысла с точки зрения спецификации CSS. Текущее изменение делает правила написания селекторов более строгими.

---

## 1. Что такое "Bogus Combinators" (Недопустимые комбинаторы)?

Недопустимыми считаются комбинаторы, которые не связывают два селектора, а висят "в воздухе" или дублируются. К ним относятся:

- **Ведущие комбинаторы (Leading):** Комбинатор стоит в самом начале селектора (например, `> .box`).
    
- **Завершающие комбинаторы (Trailing):** Комбинатор стоит в самом конце (например, `.box +`).
    
- **Повторяющиеся комбинаторы:** Несколько комбинаторов подряд (например, `.a >> .b`).

---

## 2. Суть изменения

Sass теперь выдает предупреждение (а в будущем — ошибку), если обнаруживает такие конструкции. Это касается как обычных правил, так и использования амперсанда (`&`), а также функций модуля `sass:selector`.

**Важное исключение:** Ведущие комбинаторы по-прежнему разрешены, если они используются внутри вложенных правил, так как Sass автоматически объединяет их с родительским селектором.

```SCSS
// ПРАВИЛЬНО: Ведущий комбинатор во вложении
.parent {
  > .child { color: red; } // Скомпилируется в .parent > .child
}

// УСТАРЕЛО (Вызывает предупреждение):
> .standalone-box { color: blue; } 

.element + { margin-bottom: 10px; }
```

---

## 3. Почему это важно?

1. **Соответствие спецификации:** Современный CSS становится всё более строгим. Инструменты и браузеры могут некорректно интерпретировать или полностью игнорировать правила с битыми селекторами.
    
2. **Предотвращение ошибок:** Забытый комбинатор в конце строки часто является опечаткой при копировании или рефакторинге кода. Раннее предупреждение помогает найти ошибку до того, как она попадет в продакшн.
    
3. **Чистота вывода:** Sass стремится генерировать только валидный CSS, который гарантированно будет работать во всех браузерах.

---

## 4. Проблемы с интерполяцией и переменными

Чаще всего это изменение затрагивает разработчиков, которые динамически собирают селекторы из переменных или используют функции манипуляции строками.

```SCSS
$combinator: ">";

// Если $combinator окажется пустым или будет использован неверно, 
// возникнет предупреждение о некорректном селекторе.
.a #{$combinator} .b { 
  display: flex;
}
```

---

## 5. Как исправить ошибки

Если вы получили предупреждение о недопустимом комбинаторе:

- **Удалите лишнее:** Убедитесь, что селектор не заканчивается символами `>`, `+`, `~`.
    
- **Проверьте вложенность:** Если вы используете ведущий комбинатор, убедитесь, что он находится внутри родительского селектора.
    
- **Используйте `selector.unify`:** Если вы программно объединяете селекторы, используйте встроенные функции модуля `sass:selector`, которые умеют корректно обрабатывать и очищать структуру селекторов.

---

## Сроки внедрения

1. **Dart Sass 1.54.0:** Введены предупреждения об использовании недопустимых комбинаторов.
    
2. **Sass 2.0.0:** Все подобные конструкции будут вызывать фатальную ошибку компиляции.
    

Это изменение заставляет разработчиков писать более качественный и стандартный CSS, избавляя кодовую базу от "мусорных" символов в селекторах.
