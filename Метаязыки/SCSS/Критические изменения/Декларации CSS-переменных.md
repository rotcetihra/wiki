# Критическое изменение: Декларации CSS-переменных

Sass всегда стремился быть максимально совместимым с CSS, но нативные переменные (custom properties) — это особый случай. Из-за того, что их синтаксис в CSS почти не ограничен правилами, Sass вносит изменения в то, как он парсит значения внутри конструкций `--переменная: значение;`.

---

## 1. Суть изменения: Переход к нативному парсингу

Раньше Sass пытался парсить значения CSS-переменных так же, как и любое другое свойство (например, `margin` или `color`). Он вычислял математические выражения, вызывал функции и преобразовывал типы данных.

**Новое поведение:** Теперь Sass обрабатывает декларации CSS-переменных практически как "сырой текст". Он больше не пытается автоматически вычислять значения, если они не обернуты в интерполяцию.

---

## 2. Почему это важно?

CSS-переменные могут содержать конструкции, которые абсолютно валидны для браузера, но вызывают ошибки в парсере Sass.

- **Пример:** `--grid-layout: [top-left] 1fr [top-right];`
    

    Для CSS это просто строка. Для старого Sass это была попытка создать список с непонятными скобками, что могло привести к ошибке компиляции.

    

Отказ от глубокого парсинга внутри переменных позволяет Sass поддерживать любые будущие дополнения в синтаксисе CSS без необходимости постоянно обновлять компилятор.

---

## 3. Как теперь использовать Sass-логику в переменных

Поскольку Sass больше не "заглядывает" внутрь значения переменной, чтобы найти там математику или переменные Sass, вам нужно **явно** указывать на необходимость вычислений с помощью интерполяции `#{ }`.

### Сравнение синтаксиса

|**Задача**|**Старый подход (Устарело)**|**Новый подход (Правильно)**|
|---|---|---|
|**Математика**|`--w: 100px / 2;`|`--w: #{math.div(100px, 2)};`|
|**Sass-переменные**|`--main: $primary-color;`|`--main: #{$primary-color};`|
|**Вызов функций**|`--bg: lighten($color, 10%);`|`--bg: #{color.scale($color, $lightness: 10%)};`|

---

## 4. Что произойдет со старым кодом?

Sass не ломает всё мгновенно. Процесс перехода выглядит так:

1. **Предупреждение (Deprecation Warning):** Если вы используете Sass-переменную или функцию внутри CSS-переменной без интерполяции, компилятор выдаст предупреждение. Он всё ещё попытается вычислить значение "по-старому", но предупредит, что скоро это перестанет работать.
    
2. **Будущий этап (Отказ):** В Sass 2.0.0 всё, что находится после двоеточия в `--var: ...`, будет передаваться в CSS буквально. Если вы напишете `--color: $my-color;`, в CSS попадет строка `$my-color`, которую браузер не поймет.

---

## 5. Исключение: Функция `var()`

Важно различать **объявление** переменной и её **использование**. Использование нативной переменной через функцию `var()` в обычных свойствах по-прежнему работает без изменений.

```SCSS
.element {
  // Здесь всё по-прежнему:
  color: var(--main-theme-color);
  
  // А здесь (при объявлении) нужны кавычки интерполяции:
  --local-color: #{$sass-variable};
}
```

---

## 6. Как быстро исправить проект

Если ваш проект использует много Sass-логики внутри CSS-переменных, рекомендуется использовать **Sass Migrator**.

**Команда для запуска:**

```Bash
npm install -g sass-migrator
sass-migrator cascade **/*.scss
```

Этот мигратор автоматически найдет все объявления переменных и обернет значения в интерполяцию там, где это необходимо для сохранения логики.

### Резюме

Это изменение делает границу между "логикой Sass" и "данными CSS" более четкой. Хотя это требует написания чуть большего количества символов (`#{}`), это гарантирует, что ваш код не сломается при появлении новых CSS-функций или необычных синтаксических конструкций в браузерах.
