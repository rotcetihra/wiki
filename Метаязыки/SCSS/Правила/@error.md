# @error

Директива **@error** в Sass — это инструмент «защитного программирования». В то время как большинство функций Sass направлено на создание стилей, @error предназначен для того, чтобы **остановить** процесс, если что-то пошло не так.

На основе официальной документации разберем, как и зачем использовать этот «экстренный тормоз».

## 1. Как работает @error

Когда Sass встречает директиву @error, он немедленно прекращает компиляцию и выводит в консоль указанное вами сообщение. Вместе с текстом ошибки Sass предоставляет **stack trace** (стек вызовов), который показывает, в каком файле, на какой строке и внутри какого миксина или функции произошел сбой.

**Синтаксис:**

```scss
@error <выражение>;
```

**Пример:**

```scss
@mixin colors($theme) {
  @if $theme == "dark" {
    background: #000;
  } @else if $theme == "light" {
    background: #fff;
  } @else {
    // Если передано что-то другое, мы не просто игнорируем это, а бьем тревогу
    @error "Неизвестная тема: #{$theme}. Допустимые значения: 'dark' или 'light'.";
  }
}

.sidebar {
  @include colors("neon"); // ОШИБКА: компиляция прервется здесь
}
```

## 2. Зачем это нужно?

Обычный CSS просто игнорирует ошибки, что часто приводит к «поехавшей» верстке, причину которой трудно найти. @error заставляет разработчика исправить проблему сразу.

**Основные сценарии использования:**

 1. **Валидация аргументов:** Проверка, что в миксин переданы правильные единицы измерения (например, только px или %).
 2. **Библиотеки и дизайн-системы:** Если вы создаете инструменты для других разработчиков, @error поможет им правильно использовать ваш код.
 3. **Сложные расчеты:** Если результат функции математически невозможен в контексте дизайна (например, отрицательная ширина колонки).

## 3. Сравнение: @error, @warn и @debug

В Sass есть три способа вывода сообщений, и важно понимать, какой выбрать.

| Директива | Останавливает компиляцию? | Для чего используется? |
|---|---|---|
| **@error** | **Да** | Для критических ошибок, которые делают дальнейшую сборку бессмысленной. |
| **@warn** | **Нет** | Для предупреждений (например, если метод устарел или использование неоптимально). |
| **@debug** | **Нет** | Для временной проверки значений переменных в процессе написания кода. |

## 4. stack trace (Стек вызовов)

Сила @error не только в тексте сообщения, но и в информации о пути ошибки. Если ошибка произошла внутри миксина, который вызван из другого миксина, Sass покажет всю цепочку:

 1. Файл и строка с @error.
 2. Файл и строка, где был вызван миксин.
 3. Файл и строка основного стиля.

Это позволяет мгновенно найти «виновника» в огромном проекте из сотен файлов.

## Лучшие практики

 * **Будьте конкретны:** Вместо @error "Ошибка!" пишите, что именно пошло не так и какие значения ожидались.
 * **Используйте интерполяцию:** Включайте в сообщение ошибочное значение: @error "Значение #{$val} недопустимо".
 * **Защищайте API:** Если ваш миксин требует определенных ключей из карты, всегда проверяйте их наличие через map.has-key и выбрасывайте @error, если ключа нет.

@error — это ваш способ сказать коллегам (или самому себе через месяц): «Стой, здесь нельзя так делать, это сломает проект!».
