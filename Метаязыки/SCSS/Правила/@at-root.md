# @at-root

Директива **@at-root** в Sass — это инструмент для «побега» из вложенности. Она позволяет написать код глубоко внутри структуры вашего файла (для удобства организации), но при компиляции отправить его на самый верхний уровень — в корень CSS-документа.

На основе официальной документации разберем, как эта директива помогает управлять специфичностью и структурой кода.

## 1. Как работает @at-root: Базовый пример

В обычном Sass вложенные селекторы наследуют путь своих родителей. @at-root обрывает эту связь.

**Пример:**

```scss
.parent {
  color: blue;

  @at-root .child {
    color: red;
  }
}
```

**Результат в CSS:**

```css
.parent { color: blue; }
.child { color: red; } /* Выведен отдельно, а не как .parent .child */
```

## 2. Блочный синтаксис

Если вам нужно «выбросить» в корень сразу несколько правил, используйте @at-root как блок:

```scss
.main-content {
  font-size: 16px;

  @at-root {
    .header { height: 60px; }
    .footer { height: 40px; }
  }
}
```

## 3. Продвинутое управление: with и without

По умолчанию @at-root выносит код только из-под обычных селекторов, но оставляет его внутри «@-правил» (например, @media или @supports). Однако вы можете полностью контролировать этот процесс.

**Синтаксис:** @at-root (without: \<rules>) или @at-root (with: \<rules>).

 * **all**: относится ко всем правилам.
 * **rule**: относится к обычным CSS-селекторам.
 * **media / supports**: относится к конкретным директивам.

### Пример (выход из медиа-запроса):

```scss
@media screen {
  .nav {
    @at-root (without: media) {
      .external-link { color: green; }
    }
  }
}
```

> **Результат:** Класс .nav .external-link будет находиться **вне** @media screen.

## 4. Зачем это нужно на практике?

### А. Методология BEM

Когда вы используете BEM и хотите сохранить логическую вложенность в Sass, но не хотите раздувать специфичность в CSS:

```scss
.block {
  width: 100%;

  @at-root #{&}__element { // Превратится в .block__element
    color: gray;
  }
}
```

### Б. Работа с селекторными функциями

Иногда Sass автоматически добавляет родительский селектор там, где вы этого не хотите (например, при использовании selector.unify). @at-root явно говорит Sass: «Не добавляй сюда родителя, я сам сформирую селектор».

## 5. Сравнение поведения

| Контекст | Обычная вложенность | Использование @at-root |
|---|---|---|
| **Специфичность** | Высокая (цепочка селекторов) | Низкая (только ваш селектор) |
| **Место в CSS** | Внутри родителя | В корне документа |
| **Организация кода** | Стили разбросаны по файлу | Стили компонента сгруппированы в одном месте |

## Итог

Используйте @at-root, когда вы хотите сохранить **логическую связь** между элементами в исходном коде, но при этом получить **плоскую структуру** в итоговом CSS. Это лучший способ борьбы с «адом вложенности» без ущерба для читаемости проекта.
