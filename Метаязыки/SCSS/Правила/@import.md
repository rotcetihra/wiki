# @import

Хотя директива **@import** долгие годы была основным способом организации кода в Sass, сегодня она считается **устаревшей**. Официальная команда Sass настоятельно рекомендует переходить на @use и @forward.

Тем не менее, @import всё еще широко встречается в существующих проектах. Разберемся, как он работает, в чем его слабые стороны и как Sass отличает свои импорты от обычных CSS-импортов.

## 1. Как работает Sass @import

В Sass директива @import делает гораздо больше, чем в обычном CSS. Вместо того чтобы заставлять браузер делать лишний HTTP-запрос, Sass берет содержимое указанного файла и вставляет его прямо в то место, где написан @import.

**Основные правила поиска файлов:**

 * **Расширения:** Вы можете не указывать расширение файла. Sass сам найдет .scss, .sass или .css.
 * **Парциальные файлы (Partials):** Файлы, имя которых начинается с нижнего подчеркивания (например, _colors.scss), не компилируются в отдельные CSS-файлы. Они предназначены только для импорта в другие файлы.
 * **Индексные файлы:** Если вы импортируете папку @import "theme", Sass будет искать внутри неё файл _index.scss или _index.sass.

## 2. Sass @import против CSS @import

Sass компилирует @import в один файл, но в некоторых случаях он оставляет его как «нативный» CSS-импорт (который будет обрабатываться браузером).

**Sass создаст обычный CSS @import, если:**

 1. Файл имеет расширение .css.
 2. Имя файла начинается с http:// или https://.
 3. Имя файла написано как url(...).
 4. У импорта есть медиа-запросы (например, @import "theme" screen;).

## 3. Главная проблема: Глобальная область видимости

Основная причина, по которой @import признан устаревшим, — это **глобальность**. Все переменные, миксины и функции, импортированные через @import, становятся доступными во всем проекте.

**Почему это плохо:**

 * **Конфликты имен:** Если в двух разных файлах есть переменная $color, один файл незаметно перезапишет другой.
 * **Непрозрачность:** Глядя на код в середине файла, невозможно понять, откуда пришел конкретный миксин — из вашей библиотеки или из стороннего файла, импортированного 5 уровней назад.
 * **Дублирование:** Если вы импортируете один и тот же файл в нескольких местах, Sass скомпилирует его содержимое столько раз, сколько вы его вызвали, что раздувает итоговый CSS.

## 4. Вложенный импорт (Nested Import)

Sass позволяет писать @import внутри правил стиля. В этом случае все стили импортируемого файла будут вложены в этот селектор.

```scss
// _theme.scss
p { color: blue; }

// main.scss
.container {
  @import "theme";
}

// Результат:
.container p { color: blue; }
```

> *Примечание: это работает только для стилей. Переменные и миксины всё равно останутся глобальными.*

## 5. Будущее: Миграция на @use

Если вы начинаете новый проект, забудьте про @import. Используйте @use.

**Краткая разница:**

 * @import делает всё глобальным.
 * @use создает **модуль** с пространством имен (например, colors.$primary). Это делает код чистым и безопасным.

| Характеристика | @import | @use |
|---|---|---|
| **Статус** | Устарело (Deprecated) | Рекомендуется |
| **Изоляция** | Нет (всё глобально) | Да (пространства имен) |
| **Повторный импорт** | Дублирует код в CSS | Загружает только 1 раз |
| **Поиск переменных** | Трудно (через весь проект) | Легко (указан префикс модуля) |

## Резюме для разработчика

Если вы работаете со старым проектом, @import будет вашим постоянным спутником. Помните о правиле нижнего подчеркивания для парциалов и следите за тем, чтобы имена переменных в разных файлах не пересекались. Но для любого нового функционала старайтесь внедрять систему модулей через @use.
