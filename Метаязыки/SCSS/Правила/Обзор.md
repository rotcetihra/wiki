# Обзор

Специальные правила, начинающиеся с символа @ (at-rules), — это фундамент, на котором строится вся расширенная функциональность Sass. Если обычный CSS использует их для простых задач (вроде @media), то в Sass они превращают таблицы стилей в гибкую модульную систему.

На основе официальной документации разберем основные категории этих правил.

## 1. Загрузка и модули: Порядок в проекте

Современный Sass (Dart Sass) продвигает модульную систему, которая заменяет старый и небезопасный метод @import.

 * **@use**: Основной способ загрузки стилей. Он импортирует переменные, функции и миксины из другого файла в виде **модуля** с собственным пространством имен. Это предотвращает конфликты имен (например, два файла могут иметь переменную $size, и они не перемешаются).
 * **@forward**: Позволяет организовать «проходной» файл. Он собирает ресурсы из нескольких маленьких файлов и делает их доступными для тех, кто загрузит этот главный файл через @use.
 * **@import**: Устаревший метод. Хотя он всё еще работает, он считается небезопасным, так как делает всё глобальным. Рекомендуется переходить на @use.

## 2. Многоразовое использование кода

Эти правила позволяют вам писать код один раз и использовать его повсюду, сохраняя принцип DRY (Don't Repeat Yourself).

 * **@mixin и @include**: Миксины позволяют определять блоки стилей, которые можно повторно вставлять в другие селекторы. В отличие от простых переменных, миксины могут принимать аргументы.
 * **@function**: Позволяет создавать собственные функции для сложных вычислений. В отличие от миксинов, функции возвращают **значение**, а не блоки CSS-кода.
 * **@extend**: Позволяет одному селектору «наследовать» стили другого. Будьте осторожны: @extend может сильно раздуть ваш CSS, если использовать его необдуманно.

## 3. Управление потоком (Логика)

Sass позволяет добавлять условия и циклы прямо в стили. Это делает возможным генерацию сотен классов (например, для сетки) за несколько строк кода.

 * **@if и @else**: Классические условия. Выполняют блок кода, только если условие истинно.
 * **@each**: Проходит по списку или карте (map) и выполняет код для каждого элемента.
 * **@for**: Цикл, который повторяет блок кода заданное количество раз.
 * **@while**: Повторяет цикл до тех пор, пока условие остается истинным.

## 4. Контекст и сообщения

Эти правила помогают управлять тем, как и где выводится CSS, а также упрощают отладку.

 * **@at-root**: «Выбрасывает» вложенный селектор на самый верхний уровень документа. Это полезно, когда вам нужно описать стиль элемента глубоко внутри структуры, но сгенерировать его как независимый класс.
 * **@error, @warn, @debug**: Ваши инструменты для общения с разработчиком:
	   * @error: Немедленно останавливает компиляцию (используйте для критических ошибок).
	   * @warn: Выводит предупреждение в консоль, но продолжает работу.
	   * @debug: Просто печатает значение переменной или выражения для проверки в процессе разработки.

## Специальное поведение для стандартного CSS

Sass умеет работать и со стандартными @-правилами CSS (такими как @media, @supports, @keyframes), расширяя их возможности:

 1. **Интерполяция**: Вы можете вставлять переменные в медиа-запросы: @media #{$tablet} { ... }.
 2. **Вложенность**: Вы можете писать @media прямо внутри селектора. Sass автоматически «вывернет» его наружу при компиляции.
 3. **Логика внутри**: В правилах @media и @supports можно использовать выражения SassScript напрямую.

## Итог

Понимание @-правил — это то, что отличает верстальщика от Sass-архитектора. Используя @use для модульности, @mixin для повторов и @if/@for для автоматизации, вы создаете код, который легко поддерживать годами.
