# @warn

Директива **@warn** в Sass — это инструмент для «мягкого» общения с разработчиком. В отличие от @error, которая полностью останавливает работу, или @debug, которая нужна только для временных проверок, @warn помогает выявлять потенциальные проблемы, не прерывая процесс сборки проекта.

На основе официальной документации разберем, как эффективно использовать этот инструмент.

## 1. Как работает @warn

Когда Sass встречает директиву @warn, он выводит указанное сообщение в консоль (standard error) вместе со стеком вызовов (stack trace). При этом компиляция продолжается в обычном режиме, и итоговый CSS-файл будет успешно создан.

**Синтаксис:**

```scss
@warn <выражение>;
```

**Пример (предупреждение об устаревшем параметре):**

```scss
@mixin theme-button($theme) {
  @if $theme == "blue" {
    // Сообщаем разработчику, что пора переходить на новый стандарт
    @warn "Тема 'blue' устарела и будет удалена в версии 2.0. Используйте 'primary'.";
    background-color: #007bff;
  } @else {
    background-color: #333;
  }
}

.btn {
  @include theme-button("blue"); // Компиляция пройдет, но в консоли будет предупреждение
}
```

## 2. Главные отличия: @warn vs @error vs @debug

Понимание разницы между этими директивами критически важно для создания качественных библиотек и дизайн-систем.

| Директива | Останавливает билд? | Назначение | Контекст использования |
|---|---|---|---|
| **@error** | **Да** | Критические сбои | Неверные единицы измерения, отсутствие обязательных данных. |
| **@warn** | **Нет** | Уведомления | **Депрекация (устаревание)**, плохие практики, подозрительные настройки. |
| **@debug** | **Нет** | Отладка | Проверка значения переменной в процессе написания функции. |

## 3. Зачем использовать @warn?

### А. Уведомление об устаревании (Deprecation)

Это самый частый сценарий. Если вы обновляете свою библиотеку миксинов и меняете названия параметров, не ломайте код коллег сразу. Используйте @warn, чтобы дать им время на переход.

### Б. Контроль «чистоты» архитектуры

Если в вашей дизайн-системе есть правило «не использовать отступы больше 50px», вы можете добавить предупреждение:

```scss
@mixin section-padding($val) {
  @if $val > 50px {
    @warn "Отступ #{$val} превышает стандарт дизайн-системы. Убедитесь, что это согласовано.";
  }
  padding: $val;
}
```

### В. Проблемы с видимостью

Если миксин вызывается в странном контексте, где он может не сработать (например, расширение селекторов внутри @media), @warn поможет подсказать разработчику причину странного поведения CSS.

## 4. Особенности вывода

 * **Stack Trace:** В консоли будет указано не только сообщение, но и цепочка файлов/строк, которые привели к этому предупреждению.
 * **Тишина в CSS:** Директива @warn (как и другие проверочные директивы) **никогда не попадает в итоговый CSS**. Это исключительно инструмент командной строки.
 * **Подавление:** Многие инструменты сборки (webpack, vite) позволяют настроить игнорирование предупреждений Sass, но делать это не рекомендуется, так как можно пропустить важные изменения в API.

## Резюме

Используйте @warn как заботливый помощник. Он не наказывает за ошибки остановкой работы, но вежливо подсказывает, где код можно сделать лучше, современнее или безопаснее.
