# @use

Директива **@use** — это фундамент современной модульной системы Sass. Она пришла на смену устаревшему @import и привнесла в мир CSS то, чего ему долго не хватало: предсказуемость, инкапсуляцию и защиту от конфликтов имен.

Ниже представлено подробное руководство по работе с @use с примерами и объяснениями.

## 1. Зачем нужен @use? (Прощай, @import)

Раньше все файлы, загруженные через @import, становились «глобальными». Если вы импортировали 10 файлов, и в двух из них была переменная $size, один файл мог случайно перезаписать значение другого. Кроме того, было невозможно понять, откуда пришел конкретный миксин или переменная.

**@use решает эти проблемы:**

 * **Пространства имен (Namespaces):** Все переменные и функции теперь привязаны к имени файла.
 * **Однократная загрузка:** Файл компилируется только один раз, сколько бы раз вы его ни вызывали.
 * **Приватность:** Вы можете скрыть внутренние переменные модуля.

## 2. Как работает пространство имен

Когда вы загружаете файл через @use, Sass автоматически создает пространство имен на основе имени файла. Чтобы обратиться к переменной или миксину, нужно написать имя_файла.название.

**Пример:**

Представим файл _colors.scss:

```scss
$primary: #3498db;
$accent: #e74c3c;

```

И основной файл style.scss:

```scss
@use "colors";

.button {
  background-color: colors.$primary; // Обращаемся через префикс "colors"
  border-color: colors.$accent;
}
```

## 3. Настройка пространства имен (ключевое слово as)

Если имя файла слишком длинное или вы хотите избежать конфликтов, можно задать свой псевдоним с помощью as.

```scss
@use "themes/long-folder-name/theme-config" as config;

body {
  background: config.$bg-color;
}
```

### Загрузка без пространства имен (as *)

Если вы абсолютно уверены, что конфликтов не будет (например, в файле только переменные вашего проекта), можно использовать *. Это сделает все члены модуля доступными напрямую.

```scss
@use "colors" as *;

.card {
  color: $primary; // Префикс больше не нужен
}
```

## 4. Приватные члены модуля

В системе @use появилось понятие приватности. Если название переменной, миксина или функции начинается с **дефиса (-)** или **нижнего подчеркивания (_)**, они будут доступны только внутри своего файла. Другие файлы не смогут их «увидеть».

**Файл _tools.scss:**

```scss
$_local-padding: 10px; // Приватная переменная
$global-padding: 20px; // Публичная переменная

@mixin -private-helper { ... } // Приватный миксин
```

## 5. Конфигурация модулей (ключевое слово with)

Одна из самых мощных функций @use — возможность настраивать переменные модуля «на лету» при его загрузке. Для этого в исходном модуле переменные должны быть помечены флагом !default.

**Файл _library.scss:**

```scss
$border-radius: 4px !default; // Значение по умолчанию

.box {
  border-radius: $border-radius;
}
```

**Файл main.scss:**

```scss
// Загружаем библиотеку и меняем её настройки
@use "library" with (
  $border-radius: 10px
);
```

## Сравнение: @use против @import

| Особенность | @use (Рекомендуется) | @import (Устарело) |
|---|---|---|
| **Видимость** | Только в текущем файле (инкапсуляция) | Глобальная (везде) |
| **Конфликты имен** | Исключены (благодаря пространствам имен) | Постоянная проблема |
| **Производительность** | Загружает файл 1 раз | Загружает файл при каждом вызове (раздувает CSS) |
| **Приватность** | Поддерживается (_ или -) | Невозможна |
| **Место в файле** | Только в самом начале | В любом месте кода |

## Резюме для практики

 1. Всегда используйте @use вместо @import в новых проектах.
 2. Размещайте все директивы @use в самом верху файла (до любых стилей).
 3. Если вы создаете библиотеку, используйте !default для переменных, чтобы пользователи могли настраивать их через with.
 4. Используйте as * только для базовых настроек проекта (цвета, шрифты), чтобы не превращать код в «глобальную кашу».

Модульная система делает ваш код на Sass таким же структурированным, как в Java или JavaScript (ES Modules). Это стандарт профессиональной разработки сегодня.
