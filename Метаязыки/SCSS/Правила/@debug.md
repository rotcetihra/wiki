# @debug

Директива **@debug** в Sass — это ваш «взгляд под капот» процесса компиляции. Если миксины и функции — это строительные блоки, то @debug — это отладочный инструмент, аналогичный console.log() в JavaScript.

На основе официальной документации разберем, как использовать эту директиву для проверки ваших вычислений и структур данных.

## 1. Как работает @debug

Когда Sass встречает директиву @debug, он вычисляет значение выражения и выводит результат в стандартный поток вывода (обычно это ваш терминал или консоль редактора кода). Вместе со значением Sass всегда указывает **имя файла** и **номер строки**, чтобы вы могли быстро найти место проверки.

**Синтаксис:**

```scss
@debug <выражение>;
```

**Пример:**

```scss
$font-weights: ("regular": 400, "medium": 500, "bold": 700);

@debug $font-weights; // Выведет всю карту (map) в консоль
@debug map-get($font-weights, "medium"); // Выведет: 500
```

## 2. Зачем это нужно?

В отличие от CSS, Sass позволяет писать сложную логику. @debug незаменим в следующих случаях:

 1. **Проверка сложных математических расчетов:** Убедиться, что ваша функция возвращает 24px, а не 24.000001px.
 2. **Инспекция карт (Maps) и списков (Lists):** Когда данные генерируются динамически, полезно увидеть их текущую структуру.
 3. **Отладка условий:** Проверить, какое значение принимает переменная перед тем, как она попадет в @if.

## 3. Главные отличия: Светофор сообщений Sass

Важно не путать @debug с его «собратьями» — @warn и @error.

| Директива | Назначение | Прерывает билд? | Где отображается? |
|---|---|---|---|
| **@debug** | **Отладка** в процессе разработки. | Нет | Консоль / Терминал |
| **@warn** | **Предупреждение** (например, об устаревшем коде). | Нет | Консоль / Терминал |
| **@error** | **Критический сбой** (неверные данные). | **Да** | Консоль / Терминал |

## 4. Особенности использования

 * **Чистота CSS:** Как и @warn с @error, директива @debug **никогда не попадает в итоговый CSS-файл**. Она существует только в момент компиляции.
 * **Любые типы данных:** Вы можете «дебажить» что угодно: цвета, числа, строки, булевы значения и даже результаты функций.
 * **Временный характер:** Хорошим тоном считается удаление всех @debug из кода перед тем, как отправлять изменения в репозиторий (Git).

## Практический совет

Если вы работаете над сложной функцией конвертации единиц или генератором цветовой схемы, используйте @debug на каждом этапе трансформации данных. 

Например:

```scss
@function complex-calc($val) {
  $step1: $val * 2;
  @debug "Шаг 1: #{$step1}"; // Промежуточная проверка
  
  $result: $step1 + 10px;
  @debug "Итог: #{$result}";
  
  @return $result;
}
```

Это гораздо быстрее, чем компилировать CSS и гадать, почему итоговое значение в браузере выглядит не так, как ожидалось.
