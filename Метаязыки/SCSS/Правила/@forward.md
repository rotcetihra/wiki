# @forward

Директива **@forward** — это инструмент для создания «входных точек» (entry points) в архитектуре Sass. Если @use предназначен для того, чтобы использовать чужой код в текущем файле, то @forward нужен для того, чтобы передать этот код дальше — конечному пользователю вашей библиотеки или модуля.

Ниже подробное руководство по работе с @forward на основе официальной документации.

## 1. Что такое @forward и зачем он нужен?

В больших проектах стили часто разбиваются на десятки мелких файлов (например, _colors.scss, _variables.scss, _buttons.scss). Конечный пользователь не должен импортировать каждый из них по отдельности. Вместо этого создается один «индексный» файл, который собирает все эти модули и «пробрасывает» их дальше.

**Главное отличие от @use:**

 * **@use** делает переменные и миксины доступными **только внутри** того файла, где он написан.
 * **@forward** делает их доступными **тому, кто загрузит текущий файл**, но **не** текущему файлу.

## 2. Создание «Хаба» (Hub) модулей

Представьте, что у вас есть папка theme/, а в ней несколько файлов. Вы создаете файл theme/_index.scss:

```scss
// theme/_index.scss
@forward "colors";
@forward "typography";
@forward "spacing";
```

Теперь пользователь может просто написать:

```scss
@use "theme"; // Загружает всё, что было "проброшено" через @forward

.card {
  background-color: theme.$primary-color; // Доступно через пространство имен theme
}
```

## 3. Добавление префиксов (as \<prefix>-*)

Поскольку модули часто содержат простые имена переменных (например, $size), при объединении их в один большой пакет могут возникнуть конфликты или путаница. @forward позволяет добавить префикс ко всем членам модуля.

```scss
// src/_colors.scss -> содержит $primary
@forward "colors" as color-*;

// Пользователь увидит это как:
// theme.$color-primary
```

## 4. Управление видимостью (show и hide)

Иногда вы хотите передать только часть модуля или скрыть какие-то внутренние вспомогательные инструменты. Для этого используются ключевые слова show (показать только это) и hide (скрыть это, остальное показать).

```scss
// Пробрасываем только конкретные миксины
@forward "mixins" show reset-button, standard-flex;

// Пробрасываем всё, кроме технической переменной
@forward "variables" hide $internal-secret-debug-color;
```

## 5. Конфигурация пересылаемых модулей (with)

Вы можете настроить модуль в момент его пересылки. Это позволяет вам, как автору библиотеки, задать свои значения по умолчанию для «вышестоящих» модулей, при этом оставляя конечному пользователю возможность их переопределить.

```scss
// Настраиваем библиотеку кнопок при пересылке
@forward "buttons" with (
  $border-radius: 10px !default // !default позволяет пользователю изменить это позже
);
```

## 6. Комбинирование @forward и @use

Если вам нужно **и** использовать код модуля в текущем файле, **и** передать его дальше, вы можете написать обе директивы.

> **Важное правило:** Всегда пишите @forward **перед** @use. Это гарантирует, что если пользователь захочет настроить модуль через with, его настройки применятся до того, как текущий файл загрузит этот же модуль.

```scss
@forward "colors";
@use "colors"; // Теперь цвета доступны и в этом файле

.local-class {
  color: colors.$primary;
}
```

## Сравнение функционала

| Функция | @use | @forward |
|---|---|---|
| **Для кого доступен код?** | Для текущего файла | Для того, кто импортирует этот файл |
| **Пространство имен?** | Да (настраиваемое) | Нет (члены становятся частью текущего модуля) |
| **Добавление префикса?** | Нет | Да (as prefix-*) |
| **Фильтрация (show/hide)?** | Нет | Да |

## Резюме

Используйте @forward, когда строите структуру проекта «7-1» или создаете публичную библиотеку. Это позволяет скрыть внутреннюю кухню проекта и предоставить пользователю один чистый и понятный интерфейс для работы со всеми вашими стилями.
