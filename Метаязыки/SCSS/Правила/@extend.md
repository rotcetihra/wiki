# @extend

Директива **@extend** — это, пожалуй, одна из самых обсуждаемых функций Sass. Её часто называют «наследованием», потому что она позволяет одному селектору заимствовать стили другого.

В отличие от миксинов, которые *копируют* код в каждое место вызова, @extend работает иначе: он *объединяет* селекторы в итоговом CSS. Давайте разберемся, как использовать эту магию и не превратить свой код в лабиринт.

## 1. Как это работает: Магия объединения

Когда вы используете @extend, Sass не дублирует свойства. Вместо этого он добавляет ваш текущий селектор к тому правилу, которое вы расширяете.

**Пример:**

```scss
.error {
  border: 1px #f00;
  background-color: #fdd;
}

.serious-error {
  @extend .error;
  border-width: 3px;
}
```

**Результат в CSS:**

```css
.error, .serious-error {
  border: 1px #f00;
  background-color: #fdd;
}

.serious-error {
  border-width: 3px;
}
```

## 2. Заполнители (% placeholders) — лучший друг @extend

Как мы уже обсуждали ранее, чаще всего @extend используется вместе с селекторами-заполнителями. Это позволяет создавать «шаблоны» стилей, которые не появятся в итоговом CSS сами по себе, а только там, где вы их явно расширили.

> **Почему это круто?** Это помогает избежать «мусорных» классов в HTML и лишних правил в CSS, которые никто никогда не использует.

## 3. Флаг !optional

По умолчанию Sass выдаст ошибку, если вы попытаетесь расширить селектор, которого не существует. Если вы хотите, чтобы Sass просто проигнорировал расширение в случае отсутствия цели, используйте флаг !optional.

```scss
.button {
  @extend .non-existent-class !optional;
  color: blue;
}
```

## 4. Ограничения и опасности

При всей своей мощи, @extend — это инструмент, требующий осторожности. Вот главные «подводные камни»:

 * **Раздувание CSS:** Если вы расширяете селектор, который сам вложен в другие правила, Sass сгенерирует все возможные комбинации. Это может привести к гигантскому размеру файла.
 * **Ограничение @media:** Вы **не можете** использовать @extend для расширения селектора, который находится вне текущего медиа-запроса. Это связано с тем, что CSS не позволяет объединять селекторы из разных контекстов @media.

## 5. @extend или @mixin?

Это вечный спор. Вот краткая шпаргалка:

| Критерий | @extend | @mixin |
|---|---|---|
| **Дублирование кода** | Минимум (селекторы группируются) | Максимум (код копируется везде) |
| **Гибкость** | Низкая (не принимает аргументы) | Высокая (аргументы, логика) |
| **Связь в CSS** | Создает логическую связь между классами | Стили независимы друг от друга |
| **Медиа-запросы** | Имеет строгие ограничения | Работает везде без проблем |

## Резюме: Правило большого пальца

Используйте @extend, когда вы создаете иерархию элементов (например, .button-primary расширяет базовый .button). Используйте миксины, когда вам нужно передать параметры или когда стили должны работать внутри медиа-запросов.

**Важное напоминание от профессионалов:** Не злоупотребляйте расширением глубоко вложенных селекторов. Это верный способ превратить ваш CSS в «спагетти», в которых невозможно разобраться.
