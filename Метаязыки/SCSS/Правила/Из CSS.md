# Из CSS

Sass полностью поддерживает стандартные **CSS @-правила** (такие как @media, @keyframes, @font-face и другие), но значительно расширяет их возможности, делая их динамичными и удобными для вложенности.

Ниже разберем основные особенности работы с «чистыми» CSS-директивами в Sass.

## 1. Гибкость и интерполяция

Sass спроектирован так, чтобы быть совместимым с будущими версиями CSS. Вы можете использовать любое @-правило, даже если оно еще не описано в спецификации Sass.

В именах и значениях этих правил можно использовать **интерполяцию** (#{}).

```scss
$rule-name: "font-face";
@#{$rule-name} {
  font-family: "MyFont";
  src: url("font.woff2");
}
```

## 2. Вложенность и «всплытие» (Bubbling)

Это одна из самых мощных фишек. Вы можете писать CSS @-правила (например, @media или @supports) прямо внутри селекторов. При компиляции Sass автоматически «вывернет» их наружу, сохранив контекст селектора.

**Пример:**

```scss
.container {
  width: 100%;
  
  @media (max-width: 600px) {
    width: 50%; // Sass сам создаст @media { .container { width: 50%; } }
  }
}
```

## 3. Расширенные возможности @media

В отличие от чистого CSS, в Sass медиа-запросы обладают суперспособностями:

 * **SassScript напрямую:** Вы можете использовать переменные и результаты функций прямо в условиях (например, @media (min-width: $layout-breakpoint)), не используя интерполяцию.
 * **Объединение (Merging):** Если один @media вложен в другой, Sass автоматически объединит их с помощью оператора and.

**Пример объединения:**

```scss
@media screen {
  .sidebar {
    @media (orientation: landscape) {
      width: 500px;
    }
  }
}
// Результат: @media screen and (orientation: landscape) { .sidebar { ... } }
```

## 4. Специальные правила: @supports и @keyframes

 * **@supports**: Как и в случае с медиа-запросами, в @supports можно использовать переменные SassScript в условиях проверки деклараций.
 * **@keyframes**: Работает как обычное правило, но Sass следит за тем, чтобы внутри были только допустимые элементы: проценты (0%, 100%), а также ключевые слова from и to. В именах анимаций также отлично работает интерполяция.

```scss
$name: "slide";
@keyframes #{$name}-in {
  from { opacity: 0; }
  to { opacity: 1; }
}
```

## Сравнение: CSS vs Sass @-правила

| Функция | Обычный CSS | Sass |
|---|---|---|
| **Вложенность** | Не поддерживается (в большинстве случаев) | Полная поддержка (автоматическое «всплытие») |
| **Переменные** | Только CSS-переменные (var(--x)) | Любые переменные, функции и логика Sass |
| **Интерполяция** | Нет | Да (в именах и значениях) |
| **Сложные условия** | Статичные | Динамические вычисления |

## Резюме

Sass делает работу со стандартными CSS-директивами гораздо более интуитивной. Вам больше не нужно переписывать селекторы по десять раз внутри разных медиа-запросов — просто вложите @media в нужный блок, и Sass сделает всю грязную работу по реструктуризации кода за вас.
