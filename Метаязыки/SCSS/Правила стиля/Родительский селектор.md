# Родительский селектор

В мире Sass символ амперсанда (&) часто воспринимается как простой ярлык для экономии времени при написании вложенных стилей. Однако это гораздо больше, чем просто «копипаст» родительского имени. В руках опытного разработчика & превращается в мощный объект данных, позволяющий создавать по-настоящему умные и гибкие компоненты.

## 1. Ограничение суффиксов: Нет родителя — нет имени

Первое правило амперсанда: **ему нужен контекст**. Вы можете добавлять суффиксы к родительскому селектору (например, &__element), только если вы находитесь внутри вложенного правила.

Если вы попытаетесь использовать & на верхнем уровне или в блоке, который не вложен в другой селектор, Sass не сможет применить суффикс, так как ему буквально не к чему его «приклеить».

```scss
// Ошибка! Sass не знает, к чему добавлять -suffix
& {
  background-color: blue;
}
```

## 2. Амперсанд как объект SassScript

Мало кто знает, что & — это не просто текст, а полноценное выражение внутри SassScript. Когда вы используете его, Sass возвращает текущую структуру селекторов в виде сложного списка:

 * **Список списков:** Это разделенный запятыми список (все селекторы через запятую), который содержит списки, разделенные пробелами (составные селекторы).
 * **Строки без кавычек:** Конечные элементы — это обычные строки.

### Пример анализа:

```scss
.main aside:hover,
.sidebar p {
  // В итоговом CSS это свойство покажет структуру данных:
  parent-selector: &; 
  // Результат: ((".main" "aside:hover"), (".sidebar" "p"))
}
```

## 3. Умные миксины: Проверка контекста

Поскольку & вне правил стиля возвращает null (что в Sass является ложным значением / falsey), это можно использовать для создания миксинов, которые меняют поведение в зависимости от того, где они вызваны.

**Пример:** Создадим миксин для фона, который добавляет класс .app-background либо к самому себе, либо к родителю.

```scss
@mixin app-background($color) {
  // Если & существует, значит мы внутри селектора.
  // Используем интерполяцию для выбора правильного пути.
  #{if(&, '&.app-background', '.app-background')} {
    background-color: $color;
    color: rgba(#fff, 0.75);
  }
}

// Вызов на верхнем уровне -> селектор: .app-background
@include app-background(#036);

.sidebar {
  // Вызов внутри .sidebar -> селектор: .sidebar.app-background
  @include app-background(#c6538c);
}
```

## 4. Продвинутое объединение через selector.unify()

Используя & как обычное выражение, вы можете передавать его в функции модуля sass:selector. Одна из самых мощных — selector.unify(), которая объединяет два селектора в один, выбирающий элементы, подходящие под оба условия.

> **Важное предупреждение:** Когда Sass видит вложенность, он автоматически пытается добавить родителя к дочернему элементу. Если вы вручную используете & в интерполяции внутри вложенного правила, Sass может «продублировать» родителя. Чтобы этого избежать, используйте директиву **@at-root**.

### Пример динамического объединения:

```scss
@use "sass:selector";

@mixin unify-parent($child) {
  // @at-root говорит Sass: "Не добавляй родителя автоматически, я уже сделал это сам"
  @at-root #{selector.unify(&, $child)} {
    @content;
  }
}

.wrapper .field {
  @include unify-parent("input") {
    border: 1px solid red; // Результат: .wrapper .fieldinput (если валидно) или объединение
  }
}
```

## Итог

Амперсанд в Sass — это не просто символ. Это:

 1. **Логический переключатель:** Позволяет миксинам понимать, где они находятся.
 2. **Структура данных:** Позволяет программно анализировать путь вложенности.
 3. **Инструмент архитектора:** В сочетании с @at-root и функциями селекторов он позволяет строить сложнейшие CSS-конструкции, сохраняя чистоту исходного кода.

Используйте & осознанно, и ваш код станет на порядок чище и мощнее!
