# Селекторы-заглушки

В мире CSS мы привыкли, что каждое написанное правило рано или поздно оказывается в браузере. Sass нарушает это правило, предлагая «призрачный» инструмент — **селекторы-заполнители**.

Если вы когда-нибудь хотели создать «шаблон» стиля, который не замусоривает ваш итоговый файл лишними классами, то заполнители — это именно то, что вам нужно.

## Что такое селектор-заполнитель?

Селектор-заполнитель выглядит как обычный класс, но вместо точки он начинается с символа **%**.

> **Главный секрет:** Сам по себе он абсолютно невидим для итогового CSS. Если вы опишете %message-shared и ни разу его не используете, в скомпилированном файле не будет ни строчки кода. Более того, любой сложный селектор (через запятую), содержащий заполнитель, тоже будет удален из вывода, если его не «вызвать» специально.

### Пример «невидимости»:

```scss
.alert:hover, %strong-alert {
  font-weight: bold;
}

%strong-alert:hover {
  color: red;
}
```

> *Результат в CSS:* Будет пусто (если %strong-alert не расширен где-то еще), так как Sass понимает, что этот стиль предназначен только для внутреннего использования.

## Сила @extend: Оживляем призрака

Зачем же писать код, который не выводится? Весь смысл в директиве **@extend**. Она позволяет «подтянуть» свойства заполнителя в реальный CSS-класс. Это позволяет создавать чистые, модульные стили.

### Живой пример: Универсальный набор кнопок

Представьте, что вы создаете библиотеку компонентов. Вы не хотите навязывать пользователю конкретное имя класса для обертки кнопок, но хотите дать готовую логику.

**Sass (SCSS):**

```scss
%toolbelt {
  box-sizing: border-box;
  border-top: 1px rgba(#000, .12) solid;
  padding: 16px 0;
  width: 100%;

  &:hover { 
    border: 2px rgba(#000, .5) solid; 
  }
}

.action-buttons {
  @extend %toolbelt;
  color: #4285f4;
}

.reset-buttons {
  @extend %toolbelt;
  color: #cddc39;
}
```

**Что получится в CSS:**

```css
.action-buttons, .reset-buttons {
  box-sizing: border-box;
  border-top: 1px rgba(0, 0, 0, 0.12) solid;
  padding: 16px 0;
  width: 100%;
}
.action-buttons:hover, .reset-buttons:hover {
  border: 2px rgba(0, 0, 0, 0.5) solid;
}
.action-buttons { color: #4285f4; }
.reset-buttons { color: #cddc39; }
```

## Почему это лучше обычных классов?

 1. **Чистота HTML:** Вам не нужно вешать на один элемент пять классов (class="btn btn-large btn-primary btn-rounded"). Вы можете объединить всё это на стороне Sass.
 2. **Чистота CSS:** Если вы написали библиотеку из 100 заполнителей, а пользователь выбрал только 2, в его итоговый файл попадут только эти 2. Никакого «мертвого кода».
 3. **Гибкость:** Вы не привязаны к именам классов. Вы предоставляете функционал, а пользователь сам решает, как назвать свой селектор.

## Когда использовать %, а когда — обычный класс?

Здесь важно соблюдать баланс, чтобы не усложнять поддержку кода.

| Сценарий | Что использовать? | Почему? |
|---|---|---|
| **Библиотека / Фреймворк** | %placeholder | Чтобы не загромождать CSS пользователя неиспользуемыми стилями. |
| **Собственное приложение** | .class | Если у вас уже есть класс .button, проще расширить его напрямую. |
| **Повторяющаяся логика** | %placeholder | Если эти стили не имеют смысла как самостоятельный элемент в HTML. |

> **Совет от профи:** Если вы пишете стили только для своего проекта и точно знаете, что класс будет использоваться в HTML, не плодите заполнители — расширяйте обычные классы. Но если вы создаете универсальный инструмент «на экспорт», заполнители — ваш лучший друг.

Использование заполнителей — это признак того, что вы перешли от простого написания стилей к проектированию архитектуры. Это делает ваш код чище, а финальный бандл — легче.
