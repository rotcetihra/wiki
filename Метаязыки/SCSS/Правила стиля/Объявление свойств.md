# Объявление свойств

В современной веб-разработке мы часто используем CSS-переменные вместе с переменными Sass. Однако здесь кроется один из самых тонких нюансов работы препроцессора: Sass обрабатывает их совершенно иначе, чем обычные свойства.

Sass обычно старается быть «самым умным в комнате», вычисляя всё, что видит. Но когда он встречает двойное тире (--), он внезапно переходит в режим «пропускаю всё как есть». Давайте разберемся, почему так происходит и как с этим работать.

## 1. CSS Custom Properties: Режим «As-Is»

Когда вы пишете обычное свойство, например width: $size + 10px, Sass тут же бросается вычислять результат. Но с пользовательскими свойствами CSS этот номер не пройдет.

Sass парсит их **пассивно**. Все токены внутри декларации просто передаются в итоговый CSS в неизменном виде. Это сделано для того, чтобы CSS-переменные оставались максимально гибкими и могли использоваться в JavaScript.

> **Проблема:**
	Если вы просто напишете $variable внутри CSS-переменной, Sass воспримет это как обычный текст.

### Пример:

```scss
$primary: #81899b;

:root {
  // Правильно: используем интерполяцию
  --primary: #{$primary}; 

  // Ошибка (логическая): Sass не вычислит это, и в CSS уйдет текст "$primary"
  --consumed-by-js: $primary; 
}
```

## 2. Ловушка с кавычками: Как не потерять meta.inspect()

Интерполяция — это единственный способ заставить Sass «проснуться» внутри CSS-переменной. Но у неё есть побочный эффект: **она удаляет кавычки у строк**.

Это становится настоящей головной болью, когда вы передаете списки шрифтов. Если в названии шрифта есть пробелы (например, "Segoe UI"), CSS требует кавычек. Интерполяция их съест, и браузер не поймет шрифт.

> **Решение:** Используйте встроенную функцию meta.inspect(). Она принудительно сохраняет значение в том виде, в котором оно существует в Sass, включая кавычки.

### Пример с шрифтами:

```scss
@use "sass:meta";

$font-family-sans-serif: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto;

:root {
  // Без inspect кавычки вокруг Segoe UI исчезнут
  --font-family-sans-serif: #{meta.inspect($font-family-sans-serif)};
}
```

## 3. Новинка Dart Sass: CSS-правило @function

В последних версиях Dart Sass (начиная с 1.94.0) появилось интересное нововведение — нативная CSS-функция @function. Важно не путать её с обычными функциями Sass.

Это правило работает по тем же принципам, что и кастомные свойства:

 * Его свойство result ведет себя как CSS-переменная.
 * Оно доступно из JavaScript.
 * Для внедрения Sass-переменных в результат **обязательно** нужна интерполяция.

### Пример использования:

```scss
$highlight: #ddf;

@function --highlight() {
  // SassScript здесь не вычисляется напрямую, нужна интерполяция #{ }
  result: var(--highlight, #{$highlight});
}
```

## Главные выводы

 1. **Интерполяция — наше всё:** Внутри любого свойства, начинающегося на --, Sass-переменные работают только внутри #{}.
 2. **Sass не лезет в чужой монастырь:** Текст вроде $var внутри CSS-переменной считается валидным CSS-текстом и не заменяется значением.
 3. **Берегите кавычки:** Если ваше значение — это строка, которая должна остаться в кавычках (пути к файлам, шрифты), всегда оборачивайте её в meta.inspect().

Такой подход позволяет Sass сосуществовать с динамической природой CSS-переменных, не ломая их функциональность в браузере.
