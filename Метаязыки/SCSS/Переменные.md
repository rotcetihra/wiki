# Переменные

В мире программирования часто возникает соблазн сделать код максимально «динамичным». В Sass новички часто пытаются создать переменные на лету, используя интерполяцию — например, чтобы $color-primary превращался в $color-secondary в зависимости от контекста.

Однако у создателей Sass на этот счет есть четкое мнение: **динамические имена переменных запрещены.**

## Почему нельзя использовать \$var-\#{$name}?

Sass стремится к тому, чтобы код был **читаемым** и **предсказуемым**. Если бы мы могли создавать имена переменных динамически, было бы невозможно простым поиском по файлу (Ctrl+F) найти, где именно определена та или иная переменная. Это превратило бы поддержку больших проектов в кошмар.

> **Правило:** Имя переменной в Sass всегда должно быть статичным и явным.

## Решение: Используйте Sass Maps

Если вам нужно связать динамические ключи со значениями, вместо создания «виртуальных» переменных используйте **Карты (Maps)**. Это структуры данных, которые работают по принципу «ключ-значение», аналогично объектам в JavaScript или словарям в Python.

### Как это работает на практике

Вместо того чтобы пытаться вызвать несуществующую переменную $theme-color-warning, вы создаете одну карту и извлекаете из неё данные с помощью функции map.get.

**Пример (SCSS):**

```scss
@use "sass:map"; // Импортируем встроенный модуль для работы с картами

// 1. Создаем карту всех цветов темы
$theme-colors: (
  "success": #28a745,
  "info": #17a2b8,
  "warning": #ffc107,
);

.alert {
  // 2. Вместо динамической переменной используем map.get
  background-color: map.get($theme-colors, "warning");
}
```

## Преимущества использования карт перед переменными

| Критерий | Динамические переменные (запрещены) | Карты (рекомендуется) |
|---|---|---|
| **Поиск по коду** | Невозможен (имя генерируется) | Легко найти через поиск по ключу |
| **Перебор (Loops)** | Невозможен | Можно использовать @each для генерации классов |
| **Организация** | Хаос в глобальной области видимости | Все данные сгруппированы в одну структуру |
| **Безопасность** | Высокий риск ошибок при генерации имени | Можно добавить проверку на существование ключа |

### Бонус: Генерация классов через цикл

Карты особенно полезны, когда вам нужно создать целый набор похожих стилей. С динамическими переменными это было бы мучительно, а с картами — это пара строк кода:

```scss
@each $name, $color in $theme-colors {
  .alert-#{$name} {
    background-color: $color;
    border: 1px solid darken($color, 10%);
  }
}
```

## Итог

Если вы поймали себя на мысли «А как бы мне собрать имя переменной из кусочков?», остановитесь. Это сигнал к тому, что вам пора перенести эти данные в **Sass Map**. Это сделает ваш код профессиональным, масштабируемым и, что самое главное, понятным для ваших коллег.
