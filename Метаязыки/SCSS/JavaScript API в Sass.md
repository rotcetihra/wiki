# JavaScript API в Sass: Управление компиляцией программно

Если CLI — это молоток, то **JavaScript API** — это целый сборочный цех. Этот интерфейс позволяет встраивать Sass напрямую в ваши Node.js скрипты, инструменты сборки (как Vite или Webpack) или серверные приложения.

---

## 1. Установка и подключение

Для работы вам понадобится пакет `sass`. Он включает в себя чистую JavaScript-версию Dart Sass.

```Bash
npm install sass
```

Затем в вашем скрипте:

```JavaScript
const sass = require('sass');
// или в ESM:
// import * as sass from 'sass';
```

---

## 2. Современный API

Забудьте про старый `render()`. Современный API работает быстрее, поддерживает Promise и более интуитивен. Он разделен на два основных способа: компиляция **файла** и компиляция **строки кода**.

### Компиляция файла

Используйте `compile` (синхронно) или `compileAsync` (асинхронно).

```JavaScript
// Асинхронный пример (рекомендуется)
async function buildStyles() {
  try {
    const result = await sass.compileAsync("src/styles/main.scss", {
      style: "compressed",
      sourceMap: true
    });
    console.log(result.css); // Скомпилированный CSS
    console.log(result.loadedUrls); // Список всех файлов, участвовавших в сборке
  } catch (err) {
    console.error(err.message);
  }
}
```

### Компиляция строки

Если ваш SCSS хранится в переменной или приходит из базы данных:

```JavaScript
const result = sass.compileString('@use "theme"; .box { color: theme.$primary; }', {
  loadPaths: ['src/styles'] // Где искать "theme"
});
```

---

## 3. Объект настроек

Вторым аргументом в методы компиляции передается объект настроек. Вот самые важные:

|**Параметр**|**Описание**|
|---|---|
|**`style`**|`expanded` (красиво) или `compressed` (минифицировано).|
|**`sourceMap`**|Нужно ли генерировать карту кода (`boolean`).|
|**`loadPaths`**|Массив путей, где Sass будет искать файлы для `@use` и `@import`.|
|**`importers`**|Массив кастомных загрузчиков (для продвинутой логики).|
|**`functions`**|Объект с вашими JS-функциями, которые можно вызвать из Sass.|
|**`alertColor`**|Цветные сообщения об ошибках в терминале (`boolean`).|

---

## 4. Кастомные функции

Это «киллер-фича» JS API. Вы можете определить функцию на JavaScript и вызвать её прямо в `.scss`. Это позволяет Sass взаимодействовать с вашей файловой системой, API или конфигами.

**JS код:**

```JavaScript
const result = sass.compile("style.scss", {
  functions: {
    "get-version()": () => {
      return new sass.SassString("v1.2.3");
    },
    "pow($base, $exp)": (args) => {
      const base = args[0].assertNumber('base').value;
      const exp = args[1].assertNumber('exp').value;
      return new sass.SassNumber(Math.pow(base, exp));
    }
  }
});
```

**Sass код:**

```SCSS
.version::after {
  content: get-version(); // Выведет "v1.2.3"
}

.box {
  width: pow(2, 3) * 1px; // Выведет 8px
}
```

---

## 5. Кастомные импортеры

Импортеры позволяют вам переопределить то, как Sass ищет файлы. Например, вы можете научить Sass загружать стили напрямую из базы данных, облака или виртуальных файлов.

Существует два типа:

1. **`FileImporter`**: Перенаправляет на реальный файл на диске.
    
2. **`Importer`**: Позволяет вручную передать содержимое кода в виде строки.

---

## 6. Почему это лучше, чем CLI?

1. **Интеграция:** Вы можете запускать компиляцию как часть сложного конвейера (обработка CSS после компиляции через PostCSS, сохранение в БД и т.д.).
    
2. **Гибкость:** Через `functions` и `importers` вы можете расширить возможности Sass до бесконечности.
    
3. **Управление ресурсами:** Вы точно знаете, какие файлы были загружены (`loadedUrls`), что позволяет реализовать очень точный «hot reload».

---

### Итог

JavaScript API — это выбор для разработчиков инструментов и сложных enterprise-проектов. Если вам нужно просто «откомпилить файлик», CLI достаточно. Но если вы строите свою систему сборки или хотите, чтобы ваши стили знали о версии вашего приложения из `package.json`, — API ваш лучший друг.
