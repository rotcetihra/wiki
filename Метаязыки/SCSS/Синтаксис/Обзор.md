# Обзор

Sass поддерживает два различных вида синтаксиса. Оба они технически эквивалентны и предоставляют одинаковые возможности, но различаются визуальным оформлением и подходом к написанию кода. Большинство современных инструментов поддерживают оба формата одновременно.

---

## 1. SCSS (Sassy CSS)

**SCSS** — это наиболее распространенный синтаксис. Он является расширением стандартного CSS. Это значит, что любой валидный CSS-файл является валидным SCSS-файлом.

- **Файловое расширение:** `.scss`
    
- **Особенности:** Использует фигурные скобки `{}` для блоков и точки с запятой `;` для разделения свойств.
    
- **Преимущества:** Легко внедрять в существующие проекты, привычен для тех, кто уже знает CSS.

```SCSS
$color: #333;

.container {
  border: 1px solid $color;
  .content {
    background: lighten($color, 20%);
  }
}
```

---

## 2. Индентационный синтаксис (Sass)

Это оригинальный синтаксис Sass, который часто называют просто «Sass». Он ориентирован на краткость и чистоту кода.

- **Файловое расширение:** `.sass`
    
- **Особенности:** **Не использует** фигурные скобки и точки с запятой. Вместо этого структура кода определяется **отступами** (табуляцией или пробелами).
    
- **Преимущества:** Код занимает меньше строк, выглядит чище и быстрее пишется.
    

Фрагмент кода

```scss
$color: #333

.container
  border: 1px solid $color
  .content
    background: lighten($color, 20%)
```

---

## 3. Сравнение синтаксисов

|**Характеристика**|**SCSS**|**Sass (Индентационный)**|
|---|---|---|
|**Сходство с CSS**|Очень высокое|Низкое (свой уникальный стиль)|
|**Разделители блоков**|Фигурные скобки `{ }`|Отступы (Indentation)|
|**Конец строки**|Точка с запятой `;`|Перенос строки|
|**Популярность**|Самый популярный|Используется в специфических сообществах|
|**Вставка CSS**|Можно копировать CSS напрямую|Нужно переписывать под отступы|

---

## 4. Общие правила парсинга

Независимо от выбранного синтаксиса, Sass придерживается определенных правил обработки файлов:

- **Кодировка:** Sass всегда интерпретирует файлы как UTF-8. Если файл содержит BOM (Byte Order Mark), Sass удаляет его.
    
- **Комментарии:** * `//` — однострочные комментарии. Они **не попадают** в итоговый CSS.
    
    - `/* ... */` — многострочные комментарии. Они сохраняются в CSS (если не включен режим сжатия).
        
- **Специальные функции:** Некоторые функции CSS (например, `url()`) парсятся особым образом, чтобы внутри них можно было использовать переменные через интерполяцию `#{}`.

---

## 5. Смешивание синтаксисов

В рамках одного проекта вы можете использовать оба типа файлов. Файл `.scss` может импортировать файл `.sass` и наоборот. Компилятор автоматически определит тип синтаксиса по расширению файла.

## Резюме

Если вы работаете в команде или переводите проект с чистого CSS, **SCSS** будет лучшим выбором. Если же вы пишете проект в одиночку и цените минимализм и скорость печати — попробуйте **индентационный синтаксис**.
