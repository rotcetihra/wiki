# Комментарии

## Режимы вывода и искусство комментариев в Sass

Sass предлагает гибкость не только в написании кода, но и в том, как этот код будет выглядеть на «выходе» в браузере.

### 1. Комментарии: Громкие, тихие и «неубиваемые»

В Sass существует три основных типа комментариев, каждый из которых имеет свою задачу:

 * **Тихие комментарии (//)**: Используются для пояснений внутри кода. Они **не попадают** в итоговый CSS-файл. Это идеально подходит для внутренних заметок разработчиков.
 * **Громкие комментарии (/* ... */)**: Стандартные CSS-комментарии. Они сохраняются в итоговом файле, если только вы не используете сжатый режим (Compressed mode).

   > *Интересно:* Внутри таких комментариев можно использовать **интерполяцию**. Например, запись 1 + 1 = #{1 + 1} превратится в итоговом CSS в текст 1 + 1 = 2.

 * **Принудительные комментарии (/*! ... */)**: Если комментарий начинается с восклицательного знака, он будет включен в итоговый файл **даже в сжатом режиме**. Обычно так оформляют информацию о лицензиях и авторских правах.

### 2. Сжатый режим (Compressed Mode)

Для оптимизации производительности сайта Sass поддерживает режим сжатия. В этом режиме препроцессор удаляет все лишние пробелы, переносы строк и комментарии (кроме «принудительных»). Код превращается в одну длинную строку, что уменьшает размер файла.

### 3. Документирование кода (SassDoc)

Если вы создаете библиотеку стилей или работаете в большой команде, обычных комментариев недостаточно. Sass поддерживает формат **SassDoc** — это «документация как код».

Такие комментарии пишутся с тремя слешами (///) и поддерживают синтаксис **Markdown**, а также специальные аннотации (через символ @).

#### Пример документированной функции:

```scss
/// Вычисляет значение экспоненты.
///
/// @param {number} $base
///   Число, которое нужно умножить на само себя.
/// @param {integer (unitless)} $exponent
///   Степень (без единиц измерения).
/// @return {number} `$base` в степени `$exponent`.
@function pow($base, $exponent) {
  $result: 1;
  @for $_ from 1 through $exponent {
    $result: $result * $base;
  }
  @return $result;
}
```

**Зачем это нужно?**

 1. **Автоматизация:** Инструмент SassDoc может просканировать ваш проект и создать красивый HTML-сайт с описанием всех миксинов и функций.
 2. **Подсказки в IDE:** Современные редакторы кода (например, VS Code) считывают такие комментарии и показывают их в виде всплывающих подсказок при использовании функции.

### Итог: Правила хорошего тона

 * Используйте // для личных заметок.
 * Используйте /// для описания логики (миксинов и функций), чтобы ваши коллеги понимали, как их использовать.
 * Используйте /*! для сохранения копирайтов в «боевом» CSS.
