Класс Application в библиотеке GTK/GirCore предоставляет основу для создания приложений с графическим интерфейсом. Он отвечает за инициализацию приложения, управление его жизненным циклом и обработку событий, поддерживает подключение к сигналам, таким как запуск, завершение работы или активация приложения, позволяет создавать и управлять окнами приложения.

## Создание

Чтобы начать использовать приложение, нам надо создать объект класса Application. Для создания и инициализации объекта `Application` может применяться один из двух конструкторов:

```csharp
Application(params ConstructArgument[])
Application(ApplicationHandle)
```

Первая версия конструктора принимает массив объектов ConstructArgument, каждый из которых по сути представляет пару ключ-значение. Вторая версия конструктора принимает дескриптор приложения в виде объекта ApplicationHandle.

Но гораздо проще использовать более удобный статический метод New(), который выполняет роль конструктора:

```csharp
public static Application New(string? applicationId, ApplicationFlags flags)
```

Первый параметр представляет идентификатор приложения (по сути его имя), в качестве которого выступает строка - обычно это имя домена разработчика или другой идентификатор.

Второй параметр - флаги типа **ApplicationFlags**, которые управляют некоторыми возможностями приложения, например, как открывать файлы, указанные в командной строке, или как анализировать параметры командной строки. Есть следующие возможные значения:

- `AllowReplacement = 128`
- `CanOverrideAppId = 64`
- `DefaultFlags = 0`
- `FlagsNone = 0`
- `HandlesCommandLine = 8`
- `HandlesOpen = 4`
- `IsLauncher = 2`
- `IsService = 1`
- `NonUnique = 32`
- `Replace = 256`
- `SendEnvironment = 16`

Пример создания объекта Application:

```csharp
var app= Application.New("com.metanit", Gio.ApplicationFlags.DefaultFlags);
```

В данном случае идентификатор приложения - "com.metanit". Общий формат идентификаторов представляет "reverse-DNS", то есть имя домена наоборот.

В качестве же флага здесь передается флаг `FlagsNone` (он же `DefaultFlags`). Это флаг для общих случаев, который покрывает большинство стандартных ситуаций.

## Запуск

После создания приложения в виде объекта `Application` его можно запустить. Для этого применяется функция Run()

```csharp
public int Run(int argc, string[]? argv)
```

Обычно в метод передаются аргументы функции main: первый параметр представляет количество аргументов, а второй - сами аргументы в виде масства. Результатом функции является статусный код возврата, который можно возвратить из функции main в качестве результата.

Также для запуска приложения можно использовать другой метод - RunWithSynchronizationContext():

```csharp
public int RunWithSynchronizationContext(string[]? args)
```

В качестве параметра этот метод принимает обычно аргументы командной строки, как и метод `Run()`, но имеет некоторые преимущества. Это более современный способ запуска приложения, актуальный для GTK 4. В частности, метод `RunWithSynchronizationContext()` читывает синхронный контекст, что может быть важно при использовании async/await в UI-коде, и лучше интегрируется с новой архитектурой GTK4. Этот метод гарантирует, что обновления пользовательского интерфейса выполняются в правильном потоке, предотвращая состояния гонки и ошибки.

Принцип работы метода следующий. Когда необходимо выполнить операцию пользовательского интерфейса, она обычно оборачивается в `Task` или другую асинхронную операцию. Затем метод `RunWithSynchronizationContext` перехватывает задачу и обеспечивает выполнение окончательной операции (например, отображение окна, обновление метки) в потоке пользовательского интерфейса через `SynchronizationContext`. А объект `SynchronizationContext` используется для управления синхронизацией потоков. По сути, он действует как "диспетчер", который обеспечивает постановку обновлений пользовательского интерфейса в очередь и их выполнение контролируемым образом в основном потоке.

Что в итоге использовать: `Run()` и `RunWithSynchronizationContext`? Для небольших простых приложений, возможно, без разницы. А для более интенсивных приложений, возможно, метод `RunWithSynchronizationContext` будет оптимальным выбором.

Общий принцип работы:

```csharp
using Gtk;

// создаем объект приложения
var app= Application.New("com.metanit", Gio.ApplicationFlags.DefaultFlags);

app.RunWithSynchronizationContext(null); // запускаем приложение

app.Dispose();  // удаляем приложение
```

Этот код уже представляет самодостаточное приложение GTK, которое мы можем скомпилировать и запустить. Однако при запуске мы столкнемся с ошибкой:

```
eugene@Eugene:/dotnet/c#/gtkapp$ dotnet run

(gtkapp:22023): GLib-GIO-WARNING **: 28:41.041: Your application does not implement g_application_activate() and has no handlers connected to the 'activate' signal.  It should do one of these.
```

Но при запуске мы видим предупреждение, что наше приложение никак не применяет функцию `g_application_activate()` и не имеет никаких обработчиков для сигнала `activate`. В контексте же программы на C# это значит, что нам надо определить обработчик для события OnActivate:

```csharp
public event SignalHandler<Application> OnActivate
```

Это событие генерируется при запуске или активации приложения. Данное событие представляет делегат SignalHandler, которое по сути напоминает стандартный делегат для многих событий в .NET `EventHandler`:

```csharp
public delegate void SignalHandler<in TSender>(TSender sender, EventArgs args) where TSender : Object
```

То есть обработчик события `OnActivate` принимает два параметра, из которых первый параметр (`sender`) - это объект приложения `Application`, который генерирует событие. Второй параметр - `EventArgs args` — это дополнительная информация о событии, которая передается в обработчик..

Итак, добавим для приложения обработку события **OnActivate**:

```csharp
using Gtk;

// создание приложения
var app= Application.New("com.metanit", Gio.ApplicationFlags.DefaultFlags);

// при запуске приложения просто выводим строку на консоль
app.OnActivate += (_, _) => Console.WriteLine("Hello GTK");

app.RunWithSynchronizationContext(null);  // запускаем приложение
app.Dispose();  // очищаем память
```

Обработчик события `OnActivate` здесь представлен лямбда-выражением и в данном случае просто выводит на консоль некоторую строку.

В итоге когда приложение будет запущено с помощью `RunWithSynchronizationContext()`, будет сгенерировано событие `OnActivate`, а его обработчик выведет строку на консоль. Так, скомпилируем и запустим приложение:

```
eugene@Eugene:/dotnet/c#/gtkapp$ dotnet run
Hello GTK
eugene@Eugene:/dotnet/c#/gtkapp$
```
