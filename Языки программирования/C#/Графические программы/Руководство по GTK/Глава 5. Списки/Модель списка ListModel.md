В прошлых статьях было рассмотрено, как работать с элементами списка в видежте ListBox как с отдельными виджетами. Но для управления данными, особенно большими наборами однотипных данными предпочтительнее использовать Gio.ListModel или грубо говоря модель. Gio.ListModel представляет изменяемый список объектов `GObject.Object`. Хотя этот тип служит моделью для виджета ListBox и других списочных виджетов, но его также можно использовать как удобный способ возврата списков данных с поддержкой обновлений.

При этом сам тип ListModel представляет лишь интерфейс. Но в GTK существуют уже готовые типы моделей как конкретных ситуаций, например DirectoryList или StringList. Также существуют общие реализации моделей списков, такие как ListStore, которые позволяют создавать списки произвольных объектов. Но при необходимости разработчики могут создавать и свои собственные типы моделей, заточенные под какие-то специфические ситуации.

К основным моделям стоит отнести следующие:

- ListStore: в ее основе лежит сбалансированное дерево (balanced tree). Достаточно хорошо работает для наборов данных размером в диапазоне 0-1 000 000 и может обрабатывать вставки и удаления. Использует кэшированный итератор для ускорения линейного доступа к элементам.
- StringList: может обрабатывать только строки. В ее основе - динамически выделяемый массив. StringList хорошо подходит для любого места, где в противном случае использовался бы тип `string`, и лучше всего работает, если набор данных не очень динамичен.
- DirectoryList: она работает поверх объекта ListModel и асинхронно заполняет его данными типа `File`.

Если эти модели не соответствуют нужному варианту использования или требованиям масштабируемости, можно создать собственную реализацию ListModel. Это небольшой интерфейс, и его не очень сложно реализовать.

## Элементы модели

Каждый элемент в модели, то есть непосредственно отображаемые данные, представляет объект GObject.Object. При этом все элементы в ListModel имеют один и тот же тип (или являются производными от него). Каждый элемент в модели имеет позицию, которая является беззнаковым целым числом, описывающим, где в модели находится элемент. Первый элемент в модели находится в позиции 0. Позиция элемента может меняться по мере добавления или удаления других элементов из модели. Важно понимать разницу между элементами и позициями, поскольку сопоставление позиции элементу не является постоянным, что важно учитывать при отслеживании элементов по позиции при работе с моделями.

Каждый объект в списке может также сообщать об своих изменениях через некоторый механизм (обычно метод `GObject.Object.Notify`). А посредством метода `ItemsChanged` модель ListModel может уведомлять систему о произошедших изменениях среди элементов, таких как добавление или удаление элементов.

## Фабрика

Другая важная часть виджетов-списков — это фабрика. Каждая фабрика представляет собой реализацию **ListItemFactory**. Фабрика отвечает за сопоставление элементов модели с виджетами. Для это при отображении для каждого элемента создается объект **ListItem**. Для различных ситуаций есть различные типы фабрик.

## Модель выбора и активация

Виджеты поддерживают выбор элементов через модель выбора (selection model). Модель выбора — это реализация интерфейса SelectionModel поверх интерфейса ListModel, которая позволяет отмечать каждый элемент в модели как выбранный или невыбранный. Как и обычные модели, это можно реализовать либо путем прямой реализации SelectionModel, либо использования одной из моделей GTK, предоставленных для этих целей, например классы NoSelection или SingleSelection.

Модель выбора определяет процесс выбора элементов: можно выбирать только один элемент или же поддерживается множественный выбор. Состояние выбора элемента можно получить через свойство Selected объекта ListItem.

Семантика ListModel близка к семантике массива: GetNItems()() возвращает количество элементов в списке, а GetItem(uint position) возвращает элемент в позиции (от 0). Кроме того, с помощью функции GetItemType() можно получить тип элементов. Тип может быть интерфейсом, в этом случае все объекты в списке должны его реализовывать.

## Производительность

Для коротких списков могут создаваться экземпляры виджетов для каждого элемента в модели. Однако в случае с большими моделями (до тысяч или миллионов элементов) или по мере разрастания модели это становится менее осуществимым. Из-за этого списочные виджеты создают только ограниченное количество элементов списка и повторно используют их, привязывая к новым элементам. В целом виджеты-представления пытаются сохранить элементы списка доступными только для тех элементов, которые фактически можно увидеть на экране.

Хотя такое поведение позволяет представлениям легко масштабироваться до огромных списков, оно накладывает ряд ограничений. Например, невозможно запросить представление для элемента списка, используемого для определенной позиции — его может не быть, и даже если он есть, этот элемент списка может вскоре быть повторно использован для новой позиции.

Также при наличии состояния, которое необходимо сохранить, его стоит сохранять в элементах модели, а не полагаться на виджеты, которые отображают эти элементы. Поскольку эти виджеты могут быть повторно использованы для новой позиции в любое время, что приведет к потере любого состояния.

Рассмотрим использование модели ListModel на примере виджета ListBox.

## Установка модели

Для установки модели в ListBox применяется функция BindModel():

```csharp
public void BindModel(ListModel? model, ListBoxCreateWidgetFunc? createWidgetFunc)
```

Параметры метода:

- `model`: представляет объект ListModel, который будет привязан к виджету. Может принимать значение null.
- `createWidgetFunc`: представляет делегат ListBoxCreateWidgetFunc

```csharp
public delegate Widget ListBoxCreateWidgetFunc(Object item)
```

По сути это метод, который создает виджеты для элементов. Может принимать значение null.

Если виджет уже привязан к модели, то старая привязка уничтожается. Виджет очищается и заполняется новыми элементами из новой модели. Если же модель имеет значение null, то виджет остается пустым. Также стоит отметить, что виджет обновляется при каждом изменении модели.

Обратите внимание, что использование модели несовместимо с функциональностью фильтрации и сортировки в ListBox. При использовании модели фильтрация и сортировка должны быть реализованы моделью.

Для примера в качестве реализации модели возьмем тип StringList, который по сути представляет набор строк:

```csharp
using Gtk;

var app= Application.New("com.metanit", Gio.ApplicationFlags.DefaultFlags);

app.OnActivate += (sender, _) =>
{
    var window = new Window();
    window.Title = "METANIT.COM";
    window.DefaultWidth = 250;
    window.DefaultHeight = 200;

    // данные для списка
    string[] langs = {"C", "Python", "C++", "C#", "JavaScript", "Java"};
    // создаем StringList
    StringList model =  StringList.New(langs);

    var listBox = ListBox.New();
    listBox.BindModel(model, CreateRow);  // установка модели

    window.Child = listBox;
    window.Application = (Application) sender;
    window.Show();
};

app.RunWithSynchronizationContext(null);
```

// создаем виджет

```csharp
Widget CreateRow(Object item){

    StringObject strObj = (StringObject)item;
    // создаем строку для списка
    ListBoxRow row = ListBoxRow.New();
    // получаем текст из StringObject
    string text = strObj.GetString();
    // создаем метку для вывода в строке списка
    Label label = Label.New(text);
    label.Halign = Align.Start;
    // устанавливаем содержимое строки списка
    row.SetChild(label);
    return row;
}
```

Разберем основные моменты. Прежде всего создаем саму модель StringList:

```csharp
string[] langs = {"C", "Python", "C++", "C#", "JavaScript", "Java"};
StringList model =  StringList.New(langs);
```

Для создания модели применяется статический метод `StringList.New()`, в который передается массив строк.

Далее после создания виджета устанавливаем для него модель:

```csharp
var listBox = ListBox.New();
listBox.BindModel(model, CreateRow);
```

Второй параметр в `listBox.BindModel` в качестве фабрики элементов списка получает метод CreateRow. Так как каждый элемент виджета ListBox представляет объект ListBoxRow, а не простую строку. Соответственно нам нужна метод для конвертации типов:

```csharp
Widget CreateRow(Object item){

    StringObject strObj = (StringObject)item;
    // создаем строку для списка
    ListBoxRow row = ListBoxRow.New();
    // получаем текст из StringObject
    string text = strObj.GetString();
    // создаем метку для вывода в строке списка
    Label label = Label.New(text);
    label.Halign = Align.Start;
    // устанавливаем содержимое строки списка
    row.SetChild(label);
    return row;
}
```

Метод CreateRow принимает через параметр item принимает элемент модели. В нашем случае модель - StringList, поэтому объект представляет тип `StringObject` - по сути некоторая обертка над строкой string. И чтобы получить значение `string`, применяем метод `strObj.GetString()`. В остальном действия метода CreateRow своядятся в преобразование из полученной строки в объект типа ListBoxRow.
