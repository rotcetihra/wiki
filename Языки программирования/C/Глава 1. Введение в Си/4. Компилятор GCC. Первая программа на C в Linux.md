## 1. Введение

Операционная система Linux исторически и архитектурно неразрывно связана с языком Си — большая часть ядра Linux и утилит окружения написаны именно на нем. Поэтому Linux предоставляет, пожалуй, самую зрелую, стабильную и удобную экосистему для Си-разработчика.

Основным и стандартным компилятором в мире Linux является **GCC (GNU Compiler Collection)**. Он полностью поддерживает все современные стандарты языка, включая C17 и принятый эталон **C23** (ISO/IEC 9899:2024). Благодаря кроссплатформенности исходный код, написанный на Си, легко переносится между Linux, Windows и macOS, требуя лишь повторной компиляции под целевую архитектуру.

## 2. Шаг 1. Установка компилятора и пакета разработчика

Во многих дистрибутивах Linux компилятор GCC установлен по умолчанию. Однако для полноценной работы начинающему программисту требуется не просто компилятор, а полный мета-пакет инструментов сборки (включающий заголовочные файлы стандартной библиотеки, утилиту `make` для автоматизации и отладчик `gdb`).

Откройте Терминал и выполните команду, соответствующую вашему дистрибутиву:

### Для Ubuntu / Debian / Linux Mint:

```Bash
sudo apt update
sudo apt install build-essential
```

_Пакет `build-essential` автоматически установит `gcc`, `g++`, `make` и системные библиотеки разработки (`libc6-dev`)._

### Для Fedora / RHEL / CentOS:

```Bash
sudo dnf groupinstall "Development Tools"
```

### Для Arch Linux / Manjaro:

```Bash
sudo pacman -S base-devel
```

### Проверка установки

Чтобы убедиться, что компилятор успешно установлен и готов к работе, проверьте его версию:

```Bash
gcc --version
```

Терминал выведет информацию о версии GCC (в 2026 году актуальными являются версии GCC 14, 15 и выше), подтверждая успешную интеграцию в систему.

## 3. Шаг 2. Создание первой программы

Для написания исходного кода можно использовать любой инструмент: от простейших консольных редакторов (**Nano**, **Vim**) до полноценных сред разработки вроде **Visual Studio Code** или **CLion**.

1. Создайте в своей домашней директории папку для Си-проектов и перейдите в нее:
    
    ```Bash
    mkdir ~/c_projects
    cd ~/c_projects
    ```
    
2. Создайте файл с именем `hello.c`. Например, с помощью редактора Nano прямо в терминале:
    
    ```Bash
    nano hello.c
    ```
    
3. Введите в файл следующий код:
    
```C
#include <stdio.h>

int main(void)
{
    printf("Hello, Linux World!\n");
    return 0;
}
```

_Если вы использовали Nano, для сохранения файла нажмите `Ctrl + O`, затем `Enter`, а для выхода — `Ctrl + X`._

### Подробный разбор структуры кода

- **`#include <stdio.h>`** — директива препроцессора, подключающая заголовочный файл стандартной библиотеки ввода-вывода. Именно в нем объявлена функция `printf`, отвечающая за вывод текста на экран.
    
- **`int main(void)`** — главная функция, точка входа в программу. Выполнение любого Си-приложения всегда начинается с нее.
    
    - `int` (integer) указывает на то, что функция обязана вернуть целое число операционной системе при завершении работы.
        
    - `(void)` означает, что функция не принимает никаких аргументов на входе.
        
- **`{ ... }`** — фигурные скобки определяют границы тела функции `main`.
    
- **`printf("Hello, Linux World!\n");`** — встроенная функция, которая печатает строку в терминал. Комбинация символов `\n` служит для перевода курсора на новую строку.
    
- **`return 0;`** — оператор возврата. Возвращаемое значение `0` является общепринятым стандартом в программировании, сигнализирующим операционной системе о том, что программа завершилась успешно и без ошибок.
    

## 4. Шаг 3. Компиляция и запуск программы

В Linux управление процессом сборки традиционно происходит через интерфейс командной строки.

### Способ 1. Компиляция по умолчанию (a.out)

Если передать компилятору только имя исходного файла:

```Bash
gcc hello.c
```

В текущей папке создается бинарный исполняемый файл. По историческим причинам в Unix-подобных системах имя файла по умолчанию — **`a.out`**.

Чтобы запустить его, выполните команду:

```Bash
./a.out
```

> [!WARNING]
> Символы `./` перед именем файла обязательны. В целях безопасности Linux не ищет исполняемые файлы в текущей рабочей директории, если это явно не указано через префикс пути точка-слэш (`./`).

### Способ 2. Компиляция с явным указанием имени (`-o`)

На практике создавать файлы с именем `a.out` неудобно. С помощью флага `-o` вы можете назначить итоговой программе любое осмысленное имя. Обратите внимание, что в Linux исполняемые файлы, как правило, **не имеют расширения** (в отличие от `.exe` в Windows):

```Bash
gcc hello.c -o hello
```

После выполнения этой команды в каталоге появится файл `hello`. Запустите его:

```Bash
./hello
```

**Вывод в терминале:**

```Plaintext
Hello, Linux World!
```

## 5. Современные стандарты и флаги GCC в 2026 году

При написании профессионального кода на Си крайне важно приучать компилятор указывать на любые потенциальные ошибки, опечатки или небезопасные конструкции. Для этого в современном Си-сообществе принято использовать строгие флаги диагностики.

Рекомендуемый шаблон компиляции выглядит следующим образом:

```Bash
gcc -Wall -Wextra -std=c17 hello.c -o hello
```

- **`-Wall`** — включает базовый набор предупреждений компилятора о сомнительных участках кода (например, неиспользуемые переменные, несовпадение типов).
    
- **`-Wextra`** — активирует дополнительные, более строгие правила проверки, помогающие выявлять скрытые баги еще до запуска программы.
    
- **`-std=c17`** (или актуальный **`-std=c23`**) — принудительно заставляет компилятор следовать правилам конкретного стандарта ISO Си, предотвращая использование устаревших или специфичных для конкретного компилятора расширений.
    

### Быстрая сборка и запуск в одну строку

Чтобы не вводить команды сборки и запуска поочередно, используйте логический оператор `&&` (исполнять вторую команду только при успешном завершении первой):

```Bash
gcc -Wall -Wextra -std=c17 hello.c -o hello && ./hello
```

## 6. Резюме

Вы написали, скомпилировали и запустили первую программу на Си в операционной системе Linux. Исходный код остался практически идентичным коду для Windows, что подтверждает высокую переносимость программ на языке Си. Разница кроется лишь в инструментах: в Linux вы взаимодействуете с нативным компилятором GCC и запускаете файлы через терминал без расширения `.exe`, используя префикс пути `./`.
