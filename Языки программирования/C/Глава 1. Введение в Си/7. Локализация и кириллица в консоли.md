## 1. Введение

При выводе кириллицы в консоль мы можем столкнуться с ситуацией, когда вместо русских слов отображаются непонятные знаки («кракозябры»). Особенно это актуально для ОС Windows, где консоль и файлы исходного кода по умолчанию работают с разными кодовыми страницами.

В Си эта проблема решается функцией **setlocale()**, объявление которой находится в заголовочном файле `locale.h`.

> [!WARNING]
> Материал урока базируется на классических учебных курсах (Visual Studio / MSVC). Поведение на компиляторах MinGW GCC и Clang может отличаться — см. раздел «Современные подходы».

## 2. Причина проблемы: кодовые страницы

Символы кириллицы могут быть закодированы по-разному. На русской локали Windows используются в основном три кодировки:

|**Кодировка**|**Где используется**|**Пример кода буквы «П»**|
|---|---|---|
|**CP1251 (ANSI)**|Текстовые редакторы, системная локаль Windows|`0xCF`|
|**CP866 (OEM)**|Консоль `cmd` (наследие DOS)|`0xAF`|
|**UTF-8**|Linux/macOS, современное ПО, Windows 10+ (опционально)|`0xD0 0x9F`|

Консоль Windows (`cmd`) ожидает символы в кодовой странице **CP866** (OEM), а исходный файл и строковые литералы обычно сохранены в **CP1251** (ANSI) или **UTF-8**. При несовпадении кодировок консоль интерпретирует байты неверно, и на экране появляются «кракозябры».

Пример классического вывода с поврежденной кириллицей:

```DOS
c:\C>gcc hello.c -o hello && hello
╧ЁштхЄ ьшЁ!
```

## 3. Функция setlocale()

Функция **setlocale()** устанавливает или получает текущую локаль программы. Локаль описывает язык, территорию и правила форматирования (символы, даты, числа).

```c
#include <locale.h>

char *setlocale(int category, const char *locale);
```

Параметр `category` задает, какая группа правил локали затрагивается:

|**Категория**|**Что настраивает**|
|---|---|
|**`LC_ALL`**|Все категории сразу|
|**`LC_CTYPE`**|Кодировку и классификацию символов|
|**`LC_COLLATE`**|Правила сравнения и сортировки строк|
|**`LC_TIME`**|Формат даты и времени|
|**`LC_NUMERIC`**|Формат чисел (разделитель целой и дробной части)|
|**`LC_MONETARY`**|Формат денежных величин|

Особый аргумент `""` (пустая строка) предписывает использовать локаль, заданную в операционной системе (переменные окружения `LANG`, `LC_*`, региональные настройки Windows). Функция возвращает указатель на строку с названием установленной локали или `NULL` в случае ошибки.

## 4. Решение для Windows: установка локали

Измененный код программы:

```c
#include <stdio.h>
#include <locale.h>

int main(void)
{
    setlocale(LC_ALL, "");

    printf("Привет мир! \n");
    return 0;
}
```

Так как функция `setlocale` определена в файле `locale.h`, он подключается директивой `#include <locale.h>`.

После компиляции и запуска кириллица отображается корректно:

```DOS
c:\C>gcc hello.c -o hello && hello
Привет мир!
```

> [!NOTE]
> `setlocale(LC_ALL, "")` переводит функции стандартной библиотеки в режим системной локали (для русской Windows — кодировка CP1251). На платформах, где вывод и так корректен (Ubuntu, macOS), этот вызов не оказывает видимого влияния на вывод.

## 5. Кодировка исходного файла

Важное условие классического подхода: **файл с исходным кодом должен быть сохранен в кодировке ANSI (Windows-1251), а не UTF-8**.

```DOS
c:\C>gcc hello.c -o hello && hello
Привет мир!
```

> [!WARNING]
> Если сохранить исходник в UTF-8 (по умолчанию для большинства современных редакторов), строковые литералы будут в UTF-8, и классический трюк с `setlocale` может не сработать — вывод снова станет «кракозябрами».

## 6. Современные подходы

### Управление кодировкой компилятора (GCC, Clang)

Флаги компилятора позволяют задать кодировки явно, не полагаясь на локаль:

- **`-finput-charset=`** — кодировка исходного файла (по умолчанию UTF-8);
- **`-fexec-charset=`** — кодировка строковых литералов в исполняемом файле.

Для вывода в классическую консоль `cmd` (CP866):

```Bash
gcc -finput-charset=UTF-8 -fexec-charset=CP866 hello.c -o hello.exe
```

Для консоли UTF-8 (`chcp 65001`, Windows Terminal):

```Bash
gcc -finput-charset=UTF-8 -fexec-charset=UTF-8 hello.c -o hello.exe
chcp 65001
hello.exe
```

### Режим UTF-8 в современной консоли Windows

- **Windows Terminal** и обновленная консоль Windows 10+ (сборки 2019 года и новее) поддерживают UTF-8: достаточно выполнить `chcp 65001` перед запуском программы.
- В региональных настройках Windows 10/11 есть опция «Использовать Unicode (UTF-8) для поддержки языков во всем мире», после включения которой системная кодировка ANSI заменяется на UTF-8.
- Для вывода в консоль можно использовать функции WinAPI `SetConsoleOutputCP()` (заголовочный файл `windows.h`).

## 7. Linux и macOS

На этих платформах системной локалью почти всегда является **UTF-8**, а эмуляторы терминала корректно отображают кириллицу «из коробки». Проблема с выводом, как правило, не возникает, и вызов `setlocale(LC_ALL, "")` на отображение не влияет.

Тем не менее явная установка локали полезна и в Linux/macOS: от нее зависит корректная сортировка русских слов (`LC_COLLATE`), формат чисел (`LC_NUMERIC`), дат и времени (`LC_TIME`).

## 8. Резюме

1. Причина «кракозябр» — несовпадение кодировок строковых литералов и консоли.
2. Классическое решение — `setlocale(LC_ALL, "")` при условии сохранения исходника в ANSI (CP1251).
3. Современное решение — работать в UTF-8: сохранять исходники в UTF-8, включать режим UTF-8 в консоли (`chcp 65001`, Windows Terminal) и при необходимости задавать кодировки флагами `-finput-charset` / `-fexec-charset`.
4. На Linux/macOS проблема отсутствует, но явная установка локали все равно делает поведение программы предсказуемым.
