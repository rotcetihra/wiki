## Определение

```c
#include <setjmp.h>

typedef /* unspecified */ jmp_buf;
```

## Описание

Тип `jmp_buf` — это специальный тип данных (массив), служащий «точкой сохранения» состояния программы. Он хранит информацию о контексте процессора и стека (адрес текущей выполняемой инструкции, значение указателя стека и регистры общего назначения), необходимую для нелокального перехода.

`jmp_buf` применяется для аварийного выхода из глубоко вложенных функций или передачи управления при ошибках. Он используется совместно с двумя элементами:

1. `setjmp(buf)` — сохраняет текущее состояние программы в буфер `buf` (возвращает `0` при создании точки сохранения).
2. `longjmp(buf, code)` — мгновенно восстанавливает состояние из `buf` и передаёт управление обратно к `setjmp`, заставляя его вернуть значение `code` вместо `0`.

Одна переменная `jmp_buf` может использоваться повторно — например, для организации повторных попыток выполнения операций.

> [!NOTE]
> Размер и структура `jmp_buf` зависят от реализации компилятора и целевой архитектуры (x86, ARM и др.). Буфер должен быть достаточно большим, чтобы уместить все аппаратные регистры. На некоторых платформах его размер составляет от нескольких десятков до нескольких сот байтов.

> [!WARNING]
> 1. **Неопределённое поведение переменных:** Если значение автоматической (локальной) переменной изменилось между вызовами `setjmp` и `longjmp`, после восстановления контекста её значение становится неопределённым. Чтобы сохранить значение переменной, используйте модификатор `volatile`, либо объявляйте её как `static` или глобальную.
> 2. **Утечки ресурсов:** `longjmp` мгновенно прерывает выполнение функций и не вызывает освобождение ресурсов. Память, выделенная через `malloc`, и файлы, открытые через `fopen` между `setjmp` и `longjmp`, останутся неутилизированными.
> 3. **Время жизни контекста:** Нельзя вызывать `longjmp`, если функция, вызвавшая `setjmp`, уже завершила свою работу и вышла через `return`.

## Примеры

### Базовое использование

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf buf;

void deep_function(void)
{
    printf("2. Вызов deep_function: произошла ошибка, возвращаемся назад...\n");
    /* Переход к setjmp с передачей кода ошибки 404 */
    longjmp(buf, 404);
}

int main(void)
{
    /* Сохраняем точку контекста. При создании setjmp возвращает 0 */
    if (setjmp(buf) == 0) {
        printf("1. Точка сохранения создана, вызываем функцию\n");
        deep_function();
        printf("Эта строка никогда не выполнится\n");
    } else {
        /* Сюда попадаем только через longjmp */
        printf("3. Успешный возврат из longjmp\n");
    }
    return 0;
}
```

### Сохранение значения локальной переменной (volatile)

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf env;

void process(void)
{
    longjmp(env, 1);
}

int main(void)
{
    int regular_var = 10;
    volatile int volatile_var = 10;

    if (setjmp(env) == 0) {
        regular_var = 50;   /* Изменение может потеряться после longjmp */
        volatile_var = 50;  /* Изменение гарантированно сохранится */
        process();
    } else {
        /* regular_var содержит неопределённое значение */
        printf("Значение volatile-переменной: %d\n", volatile_var);
    }
    return 0;
}
```

### Паттерн повторной попытки (retry)

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf retry_buf;
volatile int attempt = 0;

int unreliable_operation(void)
{
    attempt++;
    if (attempt < 3) return -1; /* Первые 2 попытки сбойные */
    return 0;
}

int main(void)
{
    if (setjmp(retry_buf) == 0) {
        /* Первый вход */
    }

    if (unreliable_operation() != 0) {
        printf("Попытка %d не удалась. Повтор...\n", attempt);
        longjmp(retry_buf, 1);
    }

    printf("Операция успешно выполнена с попытки №%d\n", attempt);
    return 0;
}
```

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Позволяет выходить из глубоких цепочек вызовов без возврата значений через каждый `return` | Нарушает стандартный поток выполнения (сложнее отслеживать логику) |
| Позволяет имитировать механизм исключений (`try`/`catch`) в C | Пропускает очистку ресурсов, создавая риск утечек памяти и открытых файлов |
| Переменная `jmp_buf` может использоваться многократно | Локальные переменные без `volatile` теряют изменения (неопределённое поведение) |
| Прост в инициализации и не требует сторонних библиотек | Глобальный буфер `jmp_buf` не является потокобезопасным |
