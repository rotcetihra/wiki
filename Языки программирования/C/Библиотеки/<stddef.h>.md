## Описание

Заголовочный файл `<stddef.h>` определяет следующие макросы:

- `NULL` — константа нулевого указателя. Макрос раскрывается в целочисленное константное выражение со значением 0, приведённое к типу `void *`.
- `offsetof(type, member-designator)` — целочисленное константное выражение типа `size_t`, значение которого представляет смещение в байтах до члена структуры (`member-designator`) от начала его структуры (`type`).

Заголовочный файл `<stddef.h>` определяет следующие типы:

- `ptrdiff_t` — знаковый тип результата вычитания двух указателей.
- `wchar_t` — целочисленный тип, диапазон значений которого может представлять уникальные коды для всех членов самого широкого расширенного набора символов, указанного среди поддерживаемых локалей; нулевой символ должен иметь кодовое значение 0. Каждый член базового набора символов должен иметь кодовое значение, равное его значению при использовании в качестве отдельного символа в целочисленной символьной константе, если реализация не определяет `__STDC_MB_MIGHT_NEQ_WC__`.
- `size_t` — беззнаковый тип результата оператора `sizeof`.

Реализация должна поддерживать одну или несколько сред программирования, в которых ширина `ptrdiff_t`, `size_t` и `wchar_t` не больше ширины типа `long`. Имена этих сред программирования можно получить с помощью функции `confstr()` или утилиты `getconf`.

> [!NOTE]
> Стандарт ISO C не требует, чтобы макрос `NULL` включал приведение к типу `void *`, и определяет макрос `NULL` как определяемый реализацией. POSIX.1-2008 требует приведение, поэтому он не должен быть определён реализацией.

> [!NOTE]
> В GCC/glibc заголовок устроен так, чтобы другие заголовки могли «дозапросить» только нужный тип через макросы `__need_size_t`, `__need_ptrdiff_t` и т. п., не включая весь файл. Через `__need_wint_t` здесь может быть определён и `wint_t`, хотя по стандарту этот тип объявлен в `<wchar.h>`.

## Исключения

- **Установление `errno`:** не применимо — заголовок содержит только типы и макросы.
- **Поведение при передаче `NULL`:** не применимо.
- **Поведение при переполнении/нехватке памяти:** не применимо.
- **Граничные случаи:** не применимо.
- **Многопоточность:** не применимо — типы и макросы обрабатываются на этапе компиляции.
- **Реализация:** POSIX.1-2008 требует, чтобы `NULL` был определён как `(void *)0`. Стандарт ISO C позволяет определение, не включающее приведение.
