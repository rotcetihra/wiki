## Определение

```c
#include <errno.h>

extern int *__errno_location(void);
#define errno (*__errno_location()) // glibc
```

## Описание

`errno` — целочисленная lvalue, хранящая код последней ошибки. В стандарте C объявлена как модифицируемый lvalue типа `int`; в glibc реализована как макрос, раскрывающийся в обращение к функции `__errno_location()`, возвращающей адрес переменной потока (thread-local) — поэтому каждая нить имеет собственный `errno`.

Стандарт C определяет всего три кода: `EDOM`, `EILSEQ`, `ERANGE`; POSIX добавляет сотни. **Важно:** системный вызов или функция библиотеки не обнуляет `errno` при успехе — значение до вызова не определено. Программа должна проверять `errno` только сразу после неудачного вызова, возвращающего -1/`NULL`.

С 2001 года в POSIX разрешено `errno` как макрос (расширение); стандарт C допускает макрос только в объявлении. В glibc также определены `program_invocation_name`/`program_invocation_short_name` (имя вызванной программы).

## Примеры

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    errno = 0; // сброс перед вызовом
    FILE *f = fopen("no-such-file.txt", "r");
    if (f == NULL) {
        fprintf(stderr, "errno = %d: %s\n", errno, strerror(errno));
    }
    return 0;
}
```

## Ошибки и errno

Сам `errno` — объект хранения, ошибок не возвращает. Сброс в 0 перед потенциально неуспешным вызовом — общепринятая практика, т. к. вызовы не обнуляют его при успехе.

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Потокобезопасен (per-thread в glibc) | Устаревает (вызовы не сбрасывают при успехе) |
| Прост в использовании | Глобальное состояние в старых реализациях |
| Полная информация об ошибке системных вызовов | Код — «последняя» ошибка, предыдущая теряется |

## Альтернативы

- `strerror()`/`perror()` — текстовое описание кода
- `strerrorname_np()` (glibc) — имя макроса по коду
- `errno_location()` — прямой доступ к переменной потока (glibc)
