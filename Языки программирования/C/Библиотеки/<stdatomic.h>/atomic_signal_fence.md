## Определение

```c
#include <stdatomic.h>

void atomic_signal_fence(memory_order order);
```

## Описание

Функция `atomic_signal_fence` устанавливает барьер памяти между основным потоком и обработчиком сигналов, работающим в этом же потоке. В отличие от `atomic_thread_fence`, этот барьер гарантирует видимость только для обработчика того же процесса.

Барьер предотвращает переупорядочивание операций памяти компилятором, но не влияет на переупорядочивание на уровне процессора (в отличие от `atomic_thread_fence`).

> [!NOTE]
> Используйте `atomic_signal_fence` вместо `atomic_thread_fence`, если барьер нужен только для обработчиков сигналов в том же потоке. Это эффективнее, так как не требуетHardware-level барьеров.

## Пример

```c
#include <stdio.h>
#include <signal.h>
#include <stdatomic.h>

volatile sig_atomic_t flag = 0;
int data = 0;

void handler(int sig)
{
    (void)sig;
    atomic_signal_fence(memory_order_acquire);
    if (flag) {
        printf("Данные: %d\n", data);
    }
}

int main(void)
{
    signal(SIGINT, handler);
    data = 42;
    atomic_signal_fence(memory_order_release);
    flag = 1;
    raise(SIGINT);
    return 0;
}
```

## Параметры

| Параметр | Описание |
|---|---|
| `order` | Модель памяти для барьера |

## Возвращаемое значение

Функция ничего не возвращает.

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Барьер для обработчиков сигналов | Только для одного потока |
| Не требует Hardware-level барьеров | Не защищает от переупорядочивания процессором |
| Портативна (стандартная часть C11) | — |

## Обработка ошибок

- **Поведение при передаче NULL:** не применимо — функция не принимает указателей.
- **Установление errno:** функция не устанавливает `errno`.
- **Возвращаемое значение при ошибке:** не применимо — функция ничего не возвращает.
- **Многопоточность:** барьер действует только между основным потоком и обработчиками сигналов в этом же потоке. Для синхронизации между потоками используйте `atomic_thread_fence`.
- **Связанные функции:** `atomic_thread_fence` — барьер памяти между потоками; `kill_dependency` — разрыв цепочки зависимостей.
