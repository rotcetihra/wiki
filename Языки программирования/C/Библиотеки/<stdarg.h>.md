## Описание

Функция может быть вызвана с переменным количеством аргументов различных типов. Заголовочный файл `<stdarg.h>` объявляет тип `va_list` и определяет три макроса для перебора списка аргументов, количество и типы которых не известны вызываемой функции.

Вызываемая функция должна объявить объект типа `va_list`, который используется макросами `va_start()`, `va_arg()` и `va_end()`.

### va_start()

Макрос `va_start()` инициализирует `ap` для последующего использования `va_arg()` и `va_end()` и должен быть вызван первым.

Аргумент `last` — это имя последнего аргумента перед списком переменных аргументов, то есть последний аргумент, тип которого известен вызывающей функции.

Поскольку адрес этого аргумента может использоваться в макросе `va_start()`, он не должен быть объявлен как регистровая переменная или как функция или массив.

### va_arg()

Макрос `va_arg()` раскрывается в выражение, которое имеет тип и значение следующего аргумента в вызове. Аргумент `ap` — это `va_list ap`, инициализированный `va_start()`. Каждый вызов `va_arg()` изменяет `ap` так, чтобы следующий вызов возвращал следующий аргумент. Аргумент `type` — это имя типа, указанное так, чтобы тип указателя на объект указанного типа мог быть получен простым добавлением `*` к `type`.

Первое использование макроса `va_arg()` после макроса `va_start()` возвращает аргумент, следующий за `last`. Последующие вызовы возвращают значения оставшихся аргументов.

Если следующего аргумента нет, или если `type` несовместим с типом фактического следующего аргумента (как продвинутого в соответствии с продвижением аргументов по умолчанию), произойдут случайные ошибки.

Если `ap` передаётся в функцию, которая использует `va_arg(ap, type)`, то значение `ap` становится неопределяющим после возврата из этой функции.

### va_end()

Каждый вызов `va_start()` должен быть соответствующим образом сопоставлен вызовом `va_end()` в той же функции. После вызова `va_end(ap)` переменная `ap` не определена. Возможны множественные обходы списка, каждый из которых ограничен вызовами `va_start()` и `va_end()`. `va_end()` может быть макросом или функцией.

### va_copy()

Макрос `va_copy()` копирует (ранее инициализированный) список переменных аргументов `src` в `dest`. Поведение такое, как если бы `va_start()` был применён к `dest` с тем же последним аргументом, за которым следует та же последовательность вызовов `va_arg()`, которая использовалась для достижения текущего состояния `src`.

Каждый вызов `va_copy()` должен быть соответствующим образом сопоставлен вызовом `va_end()` в той же функции.

## Пример

```c
#include <stdio.h>
#include <stdarg.h>

void
foo(char *fmt, ...)   /* '...' — синтаксис C для variadic функции */
{
    va_list ap;
    int d;
    char c;
    char *s;

    va_start(ap, fmt);
    while (*fmt)
        switch (*fmt++) {
        case 's':              /* строка */
            s = va_arg(ap, char *);
            printf("строка %s\n", s);
            break;
        case 'd':              /* int */
            d = va_arg(ap, int);
            printf("int %d\n", d);
            break;
        case 'c':              /* char */
            /* здесь необходимо приведение типа, поскольку va_arg принимает
               только полностью продвинутые типы */
            c = (char) va_arg(ap, int);
            printf("char %c\n", c);
            break;
        }
    va_end(ap);
}
```

## Исключения

- **Установление `errno`:** не устанавливают.
- **Поведение при передаче `NULL`:** не применимо — аргументами являются переменные-списки и типы.
- **Поведение при переполнении/нехватке памяти:** не применимо — макросы работают со стеком вызова.
- **Граничные случаи:**
  - Если количество или тип аргументов в `va_arg()` не соответствует фактическим аргументам, поведение не определено.
  - Если `ap` передаётся в другую функцию и та вызывает `va_arg()`, значение `ap` в вызывающей функции не определено до повторного вызова `va_start()` или `va_copy()`.
  - Объявление параметра `argN` как `register`, функции или массива, или типа, несовместимого с результатом продвижения аргументов — неопределённое поведение.
- **Многопоточность:** MT-Safe. `va_arg()` — MT-Safe race:ap (только безопасно при доступе из одного потока).
- **Осторожность:** unlike historical `varargs` macros, `stdarg` macros не позволяют программисту кодировать функцию без фиксированных аргументов. Это создаёт трудности при конвертации `varargs` кода в `stdarg` и для variadic функций, которые хотят передать все аргументы другой функции, принимающей `va_list` (например, `vfprintf(3)`).

## Стандарты

`va_start()`, `va_arg()`, `va_end()`: C11, POSIX.1-2008.

`va_copy()`: C99, POSIX.1-2008.

## История

`va_start()`, `va_arg()`, `va_end()`: C89, POSIX.1-2001.

`va_copy()`: C99, POSIX.1-2001.
