## Определение

```c
#include <assert.h>

void assert(bool expression);
```

## Описание

Макрос `assert` может помочь программистам находить ошибки в своих программах или обрабатывать исключительные ситуации через аварийное завершение, которое генерирует ограниченный отладочный вывод.

Если `expression` ложно (то есть равно нулю), `assert()` выводит сообщение об ошибке в `stderr` и завершает программу вызовом `abort(3)`. Сообщение об ошибке содержит имя файла и функции, в которых находится вызов `assert()`, номер строки исходного кода и текст аргумента:

```
prog: some_file.c:16: some_func: Assertion `val == 0' failed.
```

Если на момент последнего включения `<assert.h>` определён макрос `NDEBUG`, макрос `assert()` не генерирует никакого кода и ничего не делает. Не рекомендуется определять `NDEBUG`, если `assert()` используется для обработки ошибок, поскольку программа может вести себя недетерминированно.

## Возвращаемое значение

Не возвращает значения.

## Атрибуты

| Интерфейс | Атрибут | Значение |
|---|---|---|
| `assert()` | Потоковая безопасность | MT-Safe |

## Исключения

- **Установление `errno`:** не устанавливает.
- **Поведение при передаче `NULL`:** не применимо — `assert` принимает выражение, а не указатель.
- **Поведение при переполнении/нехватке памяти:** не применимо.
- **Граничные случаи:** выражение должно быть скалярным типом (с C99). В C89 выражение должно быть типа `int` — неопределённое поведение, если это не так.
- **Многопоточность:** MT-Safe.
- **Побочные эффекты:** `assert()` реализован как макрос; если проверяемое выражение имеет побочные эффекты, поведение программы будет различаться в зависимости от того, определён ли `NDEBUG`. Это может создавать Heisenbugs.

## Стандарты

C11, POSIX.1-2008.

## История

C89, C99, POSIX.1-2001.

В C89 выражение должно быть типа `int`, но в C99 оно может быть любого скалярного типа.
