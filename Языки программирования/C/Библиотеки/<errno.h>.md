## Описание

Заголовочный файл `<errno.h>` определяет переменную (или макрос) `errno` — целочисленную lvalue, хранящую код последней ошибки, и макросы кодов ошибок `E*`.

### errno

Значение `errno` имеет смысл только тогда, когда возвращаемое значение вызова указывает на ошибку (то есть -1 для большинства системных вызовов; -1 или `NULL` для большинства библиотечных функций); функция, выполнившаяся успешно, может изменить `errno`. Значение `errno` никогда не устанавливается в ноль ни одним системным вызовом или библиотечной функцией.

Для некоторых системных вызовов и библиотечных функций (например, `getpriority(2)`) -1 является допустимым результатом при успехе. В таких случаях успешный результат можно отличить от результата с ошибкой, установив `errno` в ноль перед вызовом, а затем, если вызов вернул статус, указывающий на возможную ошибку, проверив, не установлен ли `errno` в ненулевое значение.

`errno` определён стандартом ISO C как изменяемое lvalue типа `int` и не должен быть явно объявлен; `errno` может быть макросом. `errno` является потоковой локальной переменной; установка его в одном потоке не влияет на его значение в любом другом потоке.

### perror()

Функция `perror()` выводит сообщение в `stderr`, описывающее последнюю ошибку, встретившуюся во время вызова системной или библиотечной функции.

Сначала (если `s` не `NULL` и `*s` не нулевой байт (`'\0'`)) печатается строка `s`, за двоеточием и пробелом. Затем сообщение об ошибке, соответствующее текущему значению `errno`, и символ новой строки.

Для максимальной полезности строка аргумента должна содержать имя функции, в которой произошла ошибка.

### strerror()

Функция `strerror()` возвращает указатель на строку, описывающую код ошибки, переданный в аргументе `errnum`, возможно, используя часть `LC_MESSAGES` текущей локали для выбора соответствующего языка. (Например, если `errnum` равен `EINVAL`, возвращаемое описание будет «Invalid argument»). Эта строка не должна изменяться приложением, и возвращаемый указатель будет недействителен при последующем вызове `strerror()` или `strerror_l()`, или если поток, получивший строку, завершится. Никакая другая библиотечная функция, включая `perror(3)`, не изменяет эту строку.

## Возвращаемое значение

**perror()** не возвращает значения.

**strerror()** возвращает указатель на строку с описанием ошибки или «Unknown error nnn», если номер ошибки неизвестен.

## Исключения

- **Установление `errno`:** `perror()` и `strerror()` не устанавливают `errno` при успешном вызове. POSIX.1-2001 и POSIX.1-2008 требуют, чтобы успешный вызов `strerror()` или `strerror_l()` оставлял `errno` без изменений.
- **Поведение при передаче `NULL`:** `perror(NULL)` — выводит только сообщение об ошибке без префикса. `strerror()` не принимает `NULL`.
- **Поведение при переполнении/нехватке памяти:** не применимо.
- **Граничные случаи:** значение `errno` не определено после успешного системного вызова или библиотечной функции — этот вызов может изменить эту переменную, даже если он успешен, например, потому что он внутренне использовал другую библиотечную функцию, которая завершилась неудачно. Поэтому, если неудачный вызов не следует немедленно вызовом `perror()`, значение `errno` следует сохранить.
- **Многопоточность:** `errno` является потоковой локальной переменной (MT-Safe). `perror()` — MT-Safe race:stderr. `strerror()` — MT-Safe (с glibc 2.32).
- **Предупреждение:** не используйте `sys_errlist[]` и `sys_nerr` — они устарели; используйте `strerror(3)` вместо них.

## Стандарты

`errno`, `perror()`: C11, POSIX.1-2008.

`strerror()`: C11, POSIX.1-2008.

`strerror_r()`, `strerror_l()`: POSIX.1-2008.

`sys_nerr`, `sys_errlist`: BSD.

## История

`errno`, `perror()`: POSIX.1-2001, C89, 4.3BSD.

`strerror()`: POSIX.1-2001, C89.

`strerror_r()`: POSIX.1-2001.

`strerror_l()`: glibc 2.6. POSIX.1-2008.

`strerrorname_np()`, `strerrordesc_np()`: glibc 2.32.

`sys_nerr`, `sys_errlist`: Удалены в glibc 2.32.
