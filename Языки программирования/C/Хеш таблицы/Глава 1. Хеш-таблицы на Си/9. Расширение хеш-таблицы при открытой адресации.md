Общий принцип изменения размера хеш-таблиц одинаков для разных стратегий. После каждой операции вставки или удаления сравниваем количество занятых ячеек с общим количеством ячеек хеш-таблицы. И если требуется изменение размера, выделяем память под новый массив ячеек, инициализируем его и копируем все элементы из старого массива в новый. Однако детали будут немного различаться между стратегией цепочки и открытой адресацией. Расширение хеш-таблицы при открытой адресации имеет сложность: удаленные элементы все еще занимают место в таблице, чтобы сохранить последовательность зондирования. Так, ранее в предыдыдущих темах для описания хеш-таблицы мы использовали следующие структуры:

```c
// ячейка хеш-таблицы
struct bin 
{
    unsigned int key;
    int in_probe : 1;   // является ли частью последовательности зондирования
    int is_empty : 1;   // пустая ли ячейка
};
// структура хеш-таблицы
struct hash_table 
{
    struct bin *bins;
    unsigned int size;
};
```

Структура bin имела два специальных флага: in_probe (является ли частью последовательности зондирования) и is_empty (пустая ли ячейка) При удалении элемента его ячейка помечается как "свободная" (`is_empty = 1`), но он все равно будет частью цепочки зондирования (`in_probe = 1`). Таким образом, при поиске свободной ячейки нагрузка уменьшается, так как нам не надо доходить до конца последовательности зондирования, чтобы найти свободную ячейку - эта ячейка внутри последовательности зондирования. Однако если мы ищем какой-то определенный ключ, то нагрузка не уменьшается. Таким образом, удаленные элементы замедляют поиск ключей, проверку из наличия в таблице, и, следовательно, операции вставки и удаления так же сильно, как и ключи, которые все еще находятся в таблице.

Основная проблема при изменении размера хеш-таблиц при открытой адресации состоит в том, что мы не можем уменьшать счетчик количества ключей при их удалении - так как эти ключи все еще являются частью последовательности зондирования. И чтобы определить, когда следует увеличивать размер таблицы для обеспечения хорошей производительности, нам надо учитывать как общее количество ключей в таблице, так и количество удаленных элементов:

```c
// ячейка хеш-таблицы
struct bin 
{
    unsigned int key;
    int in_probe : 1;   // является ли частью последовательности зондирования
    int is_empty : 1;   // пустая ли ячейка
};
// структура хеш-таблицы
struct hash_table 
{
    struct bin *bins;
    unsigned int size;      // общий размер таблицы
    unsigned int count;     // общее количество элементов (удаленных и неудаленных)
    unsigned int active;    // количество активных (неудаленных) элементов
};
```

Первый счетчик в структуре хеш-таблицы - count, подсчитывает, сколько ячеек входят в состав последовательности зондирования - либо потому, что ячейка содержит ключ, либо потому, что в ней хранится ранее удаленный ключ. Второй счетчик - active - указывает, сколько ячеек содержат фактический ключ.

### Создание и удаление хеш-таблицы

Для создания хеш-таблицы можно использовать следующую функцию:

```c
#define MIN_SIZE 4  // минимальный размер хеш-таблицы
// функция инициализации таблицы
init_table(struct hash_table* table, unsigned int size, struct bin* begin, struct bin* end);
// создание таблицы
struct hash_table* new_table()
{
    struct hash_table *table = malloc(sizeof *table);
    init_table(table, MIN_SIZE, NULL, NULL);
    return table;
}
```

При создании хеш-таблицы применяется функция `init_table()`, которая инициализирует хеш-таблицу и выделяет ячейки размером, указанным в качестве второго аргумента. Третий и четвертый аргументы используются при изменении размера таблицы. Поскольку эта функция зависит от других функций, то мы ее определим позже, а пока что будет достаточно указать прототип.

А для удаления следующую функцию:

```c
void free_table(struct hash_table *table)
{
    free(table->bins);
    free(table);
}
```

### Поиск ячеек

Функции поиска ячейки с определенным ключом и свободной ячейки остаются теми же, что и раньше:

```c
// функция зондирования - линейное зондирование
unsigned int p(unsigned int key, unsigned int i, unsigned int m)
{
    return (key + i) & (m - 1);
}

// поиск ячейки с определенным ключом
struct bin* find_key(struct hash_table* table, unsigned int key)
{
    // проходим по ячейкам таблицы
    for (unsigned int i = 0; i < table->size; i++) 
    {
        // получаем ячейку по индексу
        struct bin* bin = table->bins + p(key, i, table->size);

        // если хеш равен искомому, а яйчека не является пустой
        // возвращаем данную ячейку
        if (bin->key == key && !bin->is_empty) return bin;
    }
    return NULL;  // если ничего не нашли
}
// поиск пустой ячейки
struct bin* find_empty(struct hash_table* table, unsigned int key)
{
    // проходим по ячейкам таблицы
    for (unsigned int i = 0; i < table->size; i++) 
    {
        // получаем ячейку по индексу
        struct bin *bin = table->bins + p(key, i, table->size);
        // если ячейка пуста, возвращаем ее
        if (bin->is_empty) return bin;
    }
    // поскольку при добавлении таблица будет расширяться,
    // то невозможна ситуация, когда у нас не будет пустых ячеек
}
```

Поскольку заполнения таблицы теперь не происходит (при необходимости она расширяется), то при поиске в `find_empty()` мы всегда найдем пустую ячейку, потому нет смысла возвращать какое-либо альтернативное значение, типа NULL, или генерировать какую-либо ошибку.

Проверка наличия ключа будет выглядеть как и раньше - проверяем, что ячейка найдена и что она не равна NULL:

```c
int contains_key(struct hash_table* table, unsigned int key)
{
    return find_key(table, key);
    return bin != 0;
}
```

### Вставка ключей

При вставке ключа необходимо учитывать три случая:

-   Добавляемый ключ уже находится в таблице. В этом случае поля-счетчики в структуре (`count` и `active`) остаются без изменений. Также не требуется проверка необходимости изменения размера таблицы, поскольку с момента последнего обновления ничего не изменилось.
-   Добавляемый ключ вставляется в пустую ячейку. В этом случае возможны два варианта:

    -   Пустая ячейка является частью последовательности зондирования. В этом случае необходимо увеличить количество активных ячеек (`active`), но а общее количество используемых ячеек (`count`) остается неизменным - ячейка ведь уже использовалась.
    -   Пустая ячейка НЕ является частью последовательности зондирования. Тогда необходимо увеличить как количество активных (`active`), так и общее количество используемых ячеек (`count`).

Кроме того, после вставки ключа необходимо проверить, превышает ли загрузка половину, и если да, то увеличить размер таблицы вдвое. Для вставки мы могли бы определить следующую функцию:

```c
void insert_key(struct hash_table* table, unsigned int key)
{
    // если таблица содержит ключ, выходим из функции
    if (contains_key(table, key)) return;

    // иначе ищем пустую ячейку для вставки
    struct bin* key_bin = find_empty(table, key);
    // поскольку мы в любом случае найдем ячейку, увеличиваем количество активных ячеек
    table->active++;
    // если ячейка НЕ является частью последовательности зондирования
    if (!key_bin->in_probe) table->count++;  // значит, это ранее неиспользованная ячейка
    // устанавливаем содержимое ячейки
    *key_bin = (struct bin){.in_probe = 1, .is_empty = 0, .key = key};
    // при необходимости изменяем размер
    if (table->count > table->size / 2) resize(table, table->size * 2);
}
```

### Инициализация таблицы

Определим функцию инициализации ячеек хеш-таблицы:

```c
void init_table(struct hash_table *table, unsigned int size, struct bin* begin, struct bin* end)
{
    // выделяем память для новых ячеек и инициализируем поля структуры хеш-таблицы
    struct bin* bins = malloc(size * sizeof *bins);
    *table = (struct hash_table){.bins = bins, .size = size, .count = 0, .active = 0};

    // инициализируем ячейки (по умолчанию все ячейки пусты и не в последовательности зондирования)
    struct bin empty_bin = {.in_probe = 0, .is_empty = 1};
    for (unsigned int i = 0; i < table->size; i++) 
    {
        table->bins[i] = empty_bin;
    }

    // копируем данные из старых ячеек в новую таблицу
    for (struct bin *bin = begin; bin != end; bin++) 
    {
        // ячейка должна быть не пустой
        if (!bin->is_empty) 
        {
            insert_key(table, bin->key);
        }
    }
}
```

Функция `init_table()` выделяет ячейки и инициализирует их как пустые, а затем проходит по старым ячейкам и с помощью вызова `insert_key()` из каждой непустой ячейки копирует данные в новую таблицу. Поскольку таблица инициализируется значениями `count = 0` и `active = 0`, вставка ключей таким образом обеспечивает необходимый учет.

### Удаление ключа

При удалении, если ключ еще не находится в таблице, ничего не происходит. Иначе ключ удаляется, соответственнл необходимо уменьшить количество активных ячеек (`active`). Однако обшее количество ячеек (`count`) остается неизменным, поскольку ячейка с удаляемым ключом все еще является частью последовательности зондирвания:

```c
vvoid delete_key(struct hash_table* table, unsigned int key)
{
    // находим ячейку с удаляемым ключом
    struct bin* bin = find_key(table, key);

    // если таблица НЕ содержит ключ, выходим из функции
    if (!bin) return;

    printf("delete key %u\n", key);
    bin->is_empty = 1;  // ячейка теперь свободна
    table->active--;    // количество активных ячеек уменьшается
    // при необходимости уменьшаем размер
    if (table->active < table->size / 8 && table->size > MIN_SIZE) 
        resize(table, table->size / 2);
}
```

После удаления проверяем, не пора ли изменить размер таблицы - если нагрузка меньше 1/8, а размер таблицы превышает минимальный.

### Изменение размера

Функция изменения размера относительно проста, поскольку основная работа выполняется в функции `init_table()`:

```c
void resize(struct hash_table *table, unsigned int new_size)
{
    
    struct bin *old_bins_begin = table->bins,                   // указатель на начало старых ячеек
                *old_bins_end = old_bins_begin + table->size;   // указатель на конец старых ячеек
    // обновляем таблицу и копируем в нее старые данные
    init_table(table, new_size, old_bins_begin, old_bins_end);
    // освобождаем память старых ячеек
    free(old_bins_begin);
}
```

Эта функция получает диапазон старых ячеек и передает его в виде двух переменных в `init_table()`. А `init_table()` выполняет основную работу: выделяет новые ячейки и копирует в них данные из старых ячеек. И после копирования освобождаем память старых ячеек.

```c
// получаем хеш-значение из строки алгоритмом FNV-1a
unsigned int hash_fnv1a(const char *str) 
{
   unsigned int hash = 2166136261u;

    while (*str) {
        hash ^= (unsigned char)(*str++);
        hash *= 16777619;
    }

    return hash;
}

// вывод хеш-таблицы
void print_table(struct hash_table* table)
{
    for (unsigned int i = 0; i < table->size; i++) 
    {
        // получаем ячейку по индексу
        struct bin *bin = table->bins + i;
        // просто выводим все ключи из непустых ячеек в строчку
        printf("%u", bin->is_empty?0:bin->key);
        if(i < table->size-1) printf(" - ");
    }
    putchar(10);
}

int main(void)
{
    struct hash_table* dict = new_table();

    // строки для примера
    char* colors[] = {"red", "green", "blue", "yellow", "violet", "rose", "black", "white"};
    for(int i =0; i < sizeof(colors)/sizeof(colors[0]); i++)
    {
        // получаем хеш строк
        unsigned int hash = hash_fnv1a(colors[i]);
        // добавляем строки в хеш-таблицу
        insert_key(dict, hash);
    }
    // выводим содержимое
    print_table(dict);

    // получаем хеш строки `red`
    unsigned int red_hash = hash_fnv1a(colors[0]); 

    // проверим, есть ли строка red в таблице
    int is_present = contains_key(dict, red_hash);
    printf("string `red` is %s\n", is_present?  "present" : "absent");

    // удаляем строку `red` из хеш-таблицы
    printf("delete key %u\n", red_hash);
    delete_key(dict, red_hash);

    // снова проверяем, есть ли строка в хеш-таблице
    is_present = contains_key(dict, red_hash);
    printf("string `red` is %s\n", is_present?  "present" : "absent");

    // снова выводим содержимое для проверки
    print_table(dict);

    // удаляем всю хеш-таблицу
    free_table(dict);
    return 0;
}
```

В данном случае в качестве примера добавляем все строки массива colors в хеш-таблицу, выводим ее содержимое с помощью простейшей функции print_table и затем проверяем два раза наличие ключа в таблицы - до и после его удаления.
