В прошлых статьях была рассмотрена реализация хеш-таблиц на примере конкретных данных - строк (тип char\*). В приводимых примерах хеш-таблица хранила лишь хеш-ключи данных. Однако в реальности хеш-таблица также хранит множество других данных, начиная от самих данных, которые хешируются, и заканчивая различными служебными вспомогательными данными. И в принципе здесь нет какой-то большой проблемы - просто добавить определенные поля к структурам и сохранять нужные нам данные. Но проблема состоит в том, что при сохранении конкретных данных мы привязываем хеш-таблицу к определенному типу данных, и было бы неплохо иметь хеш-таблицу с неким универсальным функционалом наподобие того, что в других языках называют `generics` (обобщения или универсальные типы/шаблоны). В языке Си мы себе такую роскошь позволить не можем, и все придется делать практически с нуля. Поэтому посмотрим, как мы можем создавать универсальные хеш-таблицы на языке Си.

И в данном случае существуют разные подходы. В этой статье мы рассмотрим один из них, который подразумевает реализацию обощенных/универсальныъх структур данных через макросы. Но сразу надо сказать, что написание макросов для генерации кода - задача далеко не простая, и использование сгенерированного кода тоже не всегда просто. Такой подход чреват ошибками, а код сложно отлаживать. Мы должны быть осторожны, чтобы не генерировать один и тот же код дважды, иначе у нас будут дублированные символы, что не понравится компоновщику. Тем не менее это один из расспространенных подходов, который нельзя не рассмотреть.

Реализацию универсальных хеш-таблиц начнем с реализации универсальных (обобщенных) списков, то есть списков, которые можно создать с любым типом T, если вы сможете предоставить для них соответствующие операции. Для списков хеширование не требуется, но нам понадобятся операции сравнения на равенство и освобождения памяти. Реализацию списка начнем с макроса:

```c
#define GEN_LIST_STRUCTS(LIST_NAME, KEY_TYPE) \
    struct LIST_NAME##_node { \
        struct LIST_NAME##_node *next;  \
        KEY_TYPE key;   \
    };  \
    struct LIST_NAME##_list {   \
        struct LIST_NAME##_node *head;  \
    };
```

Этот макрос генерирует список с именем LIST_NAME, который содержит базовый тип ключа KEY_TYPE.

Макрос должен сгенерировать все необходимые структуры данных. Чтобы избежать конфликтов имен, структурам данных присваивается суффикс, а функциям - префикс, производный от LIST_NAME. Так, при определении списка с помощью `GEN_LIST(my_type, KEY_TYPE)` мы получим структуру данных с таким именем:

```c
struct my_type_node {
    struct my_type_node *next;
    KEY_TYPE key;
};
struct my_type_list {
    struct my_type_node *head;
};
```

Таким образом, структура узла списка будет содержать ключ в поле `key` и указатель на следующий узел - `next`. А список хранит указатель на начальный узел.

Для создания пустой структуры-списка, которая не имеет никаких данных, мы можем определить следующий макрос-конструктор:

```c
#define NEW_LIST() { .head = NULL }
```

А затем использовать его для создания пустого списка:

```c
struct my_type_list list = NEW_LIST();
```

Теперь для работы со списками определим несколько вспомогательных макросов. Первый из них позволит получить имя создаваемой структуры :

```c
#define LIST(LIST_NAME) struct LIST_NAME##_list
```

Имя создаваемой структуры передается через аргумент LIST_NAME и объединяется с суффиксом "\_list"

Остальные макросы предоставляют универсальный интерфейс для итератора для списков:

```c
// получаем тип элементов списка
#define ITR(LIST) typeof(LIST->head) *
// получаем из списка итерато
#define ITR_BEG(LIST)   (&((LIST)->head))
// проверяем, достигли ли мы конца списка
#define ITR_END(ITR)    (!*(ITR))
// получаем следующий элемент итератора
#define ITR_NEXT(ITR)   (&((*(ITR))->next))
// получаем текущий элемент итератора
#define ITR_DEREF(ITR) (*(ITR))
```

Макрос `ITR(LIST)` определяет тип элементов списка. Он использует оператор `typeof()` из стандарта C23. Если компилятор его не поддерживает, то можно заменить его следующим образом:

```c
#define ITR(LIST_NAME) struct LIST_NAME##_node **
```

Итератор - это просто указатель на указатель на элемент списка. `ITR_BEG` предоставляет итератор, который указывает на начало списка (путем разыменования указателя на список и получения адреса начального элемента), наподобие следующего:

```c
struct my_type_list *list ...;                  // некоторый список типа my type
struct my_type_node *head = list->head;      // первый узел списка
struct my_type_node **itr = &(list->head);   // ITR_BEG(list)
```

Макрос `ITR_END` проверяет, указывает ли итератор на NULL, что соответствует концу связанного списка. `ITR_NEXT` получает следующий элемент, а `ITR_DEREF` извлекает текущий элемент, на который указывает итератор. По сути макросы лишь предоставляют более удобный способ для перемещения по спискам.

### Добавление

Для добавления новых элементов в список определим следующий макрос:

```c
// макрос для создания нового элемента
#define PUSH_NEW_NODE(ITR) \
    do {  \
        typeof(**ITR) *node = malloc(sizeof *node); \
        node->next = *(ITR);    \
        *(ITR) = node;  \
    } while (0)

// макрос для создания функции для добавления одного элемента в список
#define GEN_LIST_ADD_KEY(LIST_NAME, KEY_TYPE)    \
    void LIST_NAME##_add_key(LIST(LIST_NAME) * list, KEY_TYPE key) {  \
        PUSH_NEW_NODE(ITR_BEG(list));   \
        ITR_DEREF(ITR_BEG(list))->key = key;    \
    }
```

Макрос `GEN_LIST_ADD_KEY` генерирует функцию. Имя функции представляет собой конкатенацию параметрам LIST_NAME и строки "\_add\_key". К примеру, при вызове `GEN_LIST_ADD_KEY(my_type, char *)` мы бы получили следующую функцию:

```c
void my_type_add_key(struct my_type_list *list, char *key);
```

Макрос `PUSH_NEW_NODE` выделяет память для нового узла и устанавливает указатель next на элемент, на который указывает итератор, а затем записывает адрес нового элемента в итератор. По сути, он помещает новый узел в начало списка, на который указывает ITR.

Опять же, если ваш компилятор еще не поддерживает оператор `typeof()`, можно сгенерировать тип итератора из `LIST_NAME`. Функция, генерируемая помощью макроса GEN\_LIST\_ADD\_KEY, будет содержать в своем теле развернутый PUSH\_NEW\_NODE, который поместит новый элемент в начало списка. А затем с помощью `ITR_DEREF(ITR_BEG(list))->key = key` запишет ключ в этот новый элемент. Но в принципе также можно было бы просто написать `list->head->key`.

### Удаление элементов списка

Для освобождения памяти списка и соответственно его удаления и его элементов определим следующие макросы:

```c
#define DELETE_NODE(ITR)                            \
    do {                                            \
        typeof(**ITR) *next = (*(ITR))->next;    \
        free(*(ITR));                               \
        *(ITR) = next;                              \
    } while (0)
#define GEN_LIST_FREE_LIST(LIST_NAME, KEY_TYPE, FREE_KEY) \
    void LIST_NAME##_free_list(LIST(LIST_NAME) * list)  \
    {                                       \
        ITR(list) itr = ITR_BEG(list);      \
        while (!ITR_END(itr))               \
        {                                   \
            FREE_KEY(ITR_DEREF(itr)->key);  \
            DELETE_NODE(itr);               \
        }                                   \
  }
```

Макрос `DELETE_NODE` генерирует код для освобождения начального элемента списка, на который указывает итератор. В нем мы получаем во временную переменную next значение поля next итератора. Затем освобождаем память элемента, на который указывает итератор. И далее устанавливаем ITR на элемент из переменной next.

Макрос `GEN_LIST_FREE_LIST` генерирует функцию `LIST_NAME##_free_list`, которая принимает список в качестве аргумента. Эта функция получает начало списка и освобождает узлы списка, пока начальный узел не будет равен NULL. Перед освобождением узла мы разыменовываем итератор (`ITR_DEREF(itr)`), чтобы получить удаляемый узел. Из него получаем ключ (`ITR_DEREF(itr)->key`) и вызываем FREE_KEY для освобождения ключа.

### Проверка наличия ключа

Для проверки наличия в списке ключа определим следующий макрос:

```c
#define GEN_LIST_CONTAINS_KEY(LIST_NAME, KEY_TYPE, IS_EQ) \
    int LIST_NAME##_contains_key(LIST(LIST_NAME) * list, const KEY_TYPE key) {      \
        for (ITR(list) itr = ITR_BEG(list); !ITR_END(itr); itr = ITR_NEXT(itr)) {   \
                if (IS_EQ(ITR_DEREF(itr)->key, key)) {                              \
                    return 1;                                                       \
                }                                                                   \
        }                                                                           \
        return 0;                                                                   \
    }
```

Макрос по сути создает функцию для проверки наличия элемента. В данном случае мы полагаемся на функцию, которая будет передаваться через параметр IS\_EQ, С помощью цикла и итераторов проходим по списку и разыменовываем его элементы для доступа к ключам. Затем с помощью функции IS\_EQ сравниваем найденные ключи с искомым ключом key.

### Удаление ключа

Для удаления определенного ключа необходимо сравнить и освободить ключи:

```c
#define GEN_LIST_DELETE_KEY(LIST_NAME, KEY_TYPE, IS_EQ, FREE_KEY) \
    void LIST_NAME##_delete_key(LIST(LIST_NAME) * list, const KEY_TYPE key) {       \
        for (ITR(list) itr = ITR_BEG(list); !ITR_END(itr); itr = ITR_NEXT(itr)) {   \
            if (IS_EQ(ITR_DEREF(itr)->key, key)) {                                  \
                FREE_KEY(ITR_DEREF(itr)->key);                                      \
                DELETE_NODE(itr);                                                   \
                return;                                                             \
            }                                                                       \
        }                                                                           \
    }
```

Здесь макрос для сравнения и освобождения ключей через параметры IS\_EQ и FREE\_KEY принимает соответствующие функции. В генерируемой макросом функции используем итераторы для линейного сканирования связанного списка и, чтобы определить, нашли ли мы нужный ключ, применяем функцию IS\_EQ к каждому ключу из списка. Если нужный ключ найден, то используем функцию FREE\_KEY для удаления ключа и DELETE\_NODE для удаления узла, который содержит данный ключ.

### Общий макрос для генерации обощенного списка

И в конце определим полный макрос для генерации обощенного списка, который по сути представляет собой просто комбинацию всех выше определенных макросов:

```c
#define GEN_LIST(LIST_NAME, KEY_TYPE, IS_EQ, FREE_KEY)          \
    GEN_LIST_STRUCTS(LIST_NAME, KEY_TYPE);                      \
    GEN_LIST_ADD_KEY(LIST_NAME, KEY_TYPE);                      \
    GEN_LIST_DELETE_KEY(LIST_NAME, KEY_TYPE, IS_EQ, FREE_KEY);  \
    GEN_LIST_CONTAINS_KEY(LIST_NAME, KEY_TYPE, IS_EQ)           \
    GEN_LIST_FREE_LIST(LIST_NAME, KEY_TYPE, FREE_KEY);
```

Для генерации кода достаточно указать имя списка, базовый тип и два параметра - IS\_EQ и FREE\_KEY. Это могут быть макросы или функции.

Например, если вам нужны списки целых чисел, подходящим сравнением будет просто операция `==,` и вам не нужно освобождать их, поскольку они будут встроены в узлы, которые вы уже освобождаете в коде списка. Таким образом, вы можете определить связанный список целых чисел следующим образом:

```c
#define EQ_CMP(A, B) ((A) == (B))
#define NOP_DESTRUCTOR(KEY) // пустой деструктор, так как целые числа не надо удалять
GEN_LIST(integer,           // имя списка
         unsigned int       // тип списка
         EQ_CMP,            // как сравниваются ключи
         NOP_DESTRUCTOR)    // как удаляются ключи
```

Если же вы работаете с указателями на целые числа, вам следует разыменовывать их перед сравнением, и, вероятно, вам потребуется вызвать функцию `free()` для них при удалении:

```c
// для указателей на целые числа
#define DEREF_EQ_CMP(A, B) (*(A) == *(B))
GEN_LIST(intp, unsigned int *, DEREF_EQ_CMP, free);
```

При работе со строками также освобождаем их, а при сравнении, например, можно проверять, возвращает ли функция `strcmp()` 0:

```c
#define STR_EQ(A, B) (strcmp(A, B) == 0)
GEN_LIST(str, char *, STR_EQ, free);
```

### Реализация Hash Set

Теперь перейдем к реализации хеш-множества (на основе алгоритма цепочки). Вначале определим следующие макросы:

```c
#define BIN(HASH_NAME) struct HASH_NAME##_bin_list
#define HTABLE(HASH_NAME) struct HASH_NAME##_hash_table
#define LIST_FN(HASH_NAME, FUNC_NAME) HASH_NAME##_bin##_##FUNC_NAME
#define HASH_FN(HASH_NAME, FUNC_NAME) HASH_NAME##_##FUNC_NAME
```

Все четыре макроса в качестве параметра принимают `HASH_NAME` - это имя, которое определяет хеш-структуру и функции. Так, макрос `BIN(HASH_NAME)` задает производное имя для связанных списков корзины хеш-таблицы. Это имя будет использоваться при генерации кода для списков.

Макрос `HTABLE(HASH_NAME)` определяет имя для кода хеш-таблицы. А макросы `LIST_FN` и `HASH_FN` используются для получения сгенерированных имен функций из списков и хеш-таблиц соответственно.

Также определим минимальный размер для хеш-таблиц:

```c
#define MIN_SIZE 8
```

При создании структур сначала генерируется код связанного списка с операциями сравнения и деструктора, соответствующими типу ключа, а затем генерируется структура хеш-таблицы. Последняя будет содержать массив списков, представленный в виде указателя на `BIN(HASH_NAME)`, а также поля для хранения размера хеш-таблицы и количества элементов. Для этого определим следующий макрос:

```c
#define GEN_HASH_STRUCTS(HASH_NAME, KEY_TYPE, KEY_CMP, KEY_DESTRUCTOR) \
GEN_LIST(HASH_NAME##_bin, KEY_TYPE, KEY_CMP, KEY_DESTRUCTOR) \
HTABLE(HASH_NAME) {         \
    BIN(HASH_NAME) * bins;  \
    unsigned int size;      \
    unsigned int count;      \
};
```

#### Создание хеш-таблиц

Далее определим макрос для создания таблицы:

```c
// макрос для создания хеш-таблицы
#define GEN_NEW_TABLE(HASH_NAME)                                \
    HTABLE(HASH_NAME) * HASH_FN(HASH_NAME, new_table)()         \
    {                                                           \
        HTABLE(HASH_NAME) *table = malloc(sizeof *table);       \
        BIN(HASH_NAME) *bins = malloc(MIN_SIZE * sizeof *bins); \
        *table = (HTABLE(HASH_NAME)){.bins = bins,              \
                                     .size = MIN_SIZE,          \
                                     .count = 0};                \
        for (BIN(HASH_NAME) *bin = table->bins;                 \
             bin < table->bins + table->size;                   \
             bin++) {                                           \
                bin->head = NULL;                               \
        }                                                       \
    return table;                                               \
    }
```

Здесь мы выделяем память для структуры таблицы и ее ячеек, затем проходим по ячейкам и инициализируем из поле `head` (первый элемент в списке корзины) значением NULL.

#### Удаление хеш-таблиц

А для удаления хеш-таблицы и ее ячеек определим следующий макрос:

```c
#define GEN_FREE_TABLE(HASH_NAME)   \
    void HASH_FN(HASH_NAME, free_table)(HTABLE(HASH_NAME) *table)   \
    {                                                               \
        for (BIN(HASH_NAME) *bin = table->bins;                     \
             bin < table->bins + table->size;                       \
             bin++) {                                               \
          LIST_FN(HASH_NAME, free_list)(bin);                       \
        }                                                           \
        free(table->bins);                                          \
        free(table);                                                \
    }
```

При удалении вызывается функция free\_list списка (используя `LIST_FN(HASH_NAME, free_list)`, чтобы получить правильное имя). Она позаботится об освобождении ключей.

#### Основные операции с элементами хеш-таблицы

Для работы с корзинами нам потребуется функция, которая возвращает корзину хеш-таблицы(т.е. связанный список) на основе хеш-ключа:

```c
#define GEN_GET_KEY_BIN(HASH_NAME)                              \
    BIN(HASH_NAME) *                                            \
    HASH_FN(HASH_NAME, get_key_bin)(HTABLE(HASH_NAME) *table,   \
                                    unsigned int hash_key)      \
    {                                                           \
        unsigned int mask = table->size - 1;                    \
        unsigned int index = hash_key & mask;                   \
        return &table->bins[index];                             \
    }
```

Макросы для генерации функций для основых операций с ключами будут во многом аналогичны тем, что рассматривались в прошлых статьях, только теперь для их определения используем макросы:

```c
// добавление ключа
#define GEN_INSERT_KEY(HASH_NAME, KEY_TYPE, HASH)                               \
    void HASH_FN(HASH_NAME, insert_key)(HTABLE(HASH_NAME) *table, KEY_TYPE key) \
    {                                                                           \
        BIN(HASH_NAME) *bin = HASH_FN(HASH_NAME, get_key_bin)(table, HASH(key)); \
        if (!LIST_FN(HASH_NAME, contains_key)(bin, key))                        \
        {                                                                       \
            LIST_FN(HASH_NAME, add_key)(bin, key);                              \
            table->count++;                                                      \
            if (table->size == table->count)                                     \
            {                                                                   \
                HASH_FN(HASH_NAME, resize)(table, 2*table->size);               \
            }                                                                   \
        }                                                                       \
    }

// проверка наличия ключа
#define GEN_CONTAINS_KEY(HASH_NAME, KEY_TYPE, HASH)                                 \
    int HASH_FN(HASH_NAME, contains_key)(HTABLE(HASH_NAME) *table, KEY_TYPE key)    \
    {                                                                               \
        BIN(HASH_NAME) *bin = HASH_FN(HASH_NAME, get_key_bin)(table, HASH(key));    \
        return LIST_FN(HASH_NAME, contains_key)(bin, key);                          \
    }

// удаление ключа
#define GEN_DELETE_KEY(HASH_NAME, KEY_TYPE, HASH)                                   \
    void HASH_FN(HASH_NAME, delete_key)(HTABLE(HASH_NAME) *table, KEY_TYPE key)     \
    {                                                                               \
        BIN(HASH_NAME) *bin = HASH_FN(HASH_NAME, get_key_bin)(table, HASH(key));    \
        if (LIST_FN(HASH_NAME, contains_key)(bin, key))                             \
        {                                                                           \
            LIST_FN(HASH_NAME, delete_key)(bin, key);                               \
            table->count--;                                                          \
```

#### Изменение размера хеш-таблиц

И последняя функциональность, которую можно было бы добавить, - это изменение размера таблицы. Для этого определим следующие макросы:

```c
// перемещение узла в новую корзину
#define MOVE_NODE(FROM, TO)                 \
    do {                                    \
        typeof(**FROM) *node = *FROM;       \
        *FROM = node->next;                 \
        node->next = *TO;                   \
        *TO = node;                         \
    } while (0)
// изменение размера
#define GEN_RESIZE(HASH_NAME, HASH)                                                     \
    void HASH_FN(HASH_NAME, resize)(HTABLE(HASH_NAME) *table, unsigned int new_size)    \
    {                                                                                   \
        BIN(HASH_NAME) *old_bins = table->bins,                                         \
                        *old_from = old_bins,                                           \
                        *old_to = old_from + table->size;                               \
        table->bins = malloc(new_size * sizeof *table->bins);                           \
        table->size = new_size;                                                         \
        for (BIN(HASH_NAME) *bin = table->bins; bin < table->bins + table->size; bin++) \
        {                                                                               \
            bin->head = NULL;                                                           \
        }                                                                               \
        for (BIN(HASH_NAME) *bin = old_from; bin < old_to; bin++)                       \
        {                                                                               \
            for (ITR(bin) itr = ITR_BEG(bin); !ITR_END(itr);)                           \
            {                                                                           \
                unsigned int hash_key = HASH(ITR_DEREF(itr)->key);                      \
                MOVE_NODE(itr, ITR_BEG(HASH_FN(HASH_NAME, get_key_bin)(table, hash_key)));   \
            }                                                                           \
        }                                                                               \
        free(old_bins);                                                                 \
    }
```

Первый макрос - `MOVE_NODE` с помощью итераторов перемещает элемент из одного списка в другой. Этот макрос используется во втором макросе - `GEN_RESIZE`, который генерирует функцию для изменения размера таблицы. Поскольку хранимые данные не представляют ключи, то через параметр HASH в макрос передается функция хеширования, чтобы вычислить ключи хеша и получить ячейки, в которые перемещаем элементы старых ячеек. Если бы хеши данных хранились бы в списках, то можно было бы повторно использовать ранее вычисленное значение.

#### Общий макрос

И в конце определим финальный общий макрос, который будет генерировать всю выше описанную функциональность:

```c
#define GEN_HASH_TABLE(HASH_NAME, KEY_TYPE, KEY_CMP, HASH, KEY_DESTRUCTOR)     \
  GEN_HASH_STRUCTS(HASH_NAME, KEY_TYPE, KEY_CMP, KEY_DESTRUCTOR)               \
  GEN_GET_KEY_BIN(HASH_NAME)                                                   \
  GEN_NEW_TABLE(HASH_NAME)                                                     \
  GEN_FREE_TABLE(HASH_NAME)                                                    \
  GEN_RESIZE(HASH_NAME, HASH)                                                  \
  GEN_INSERT_KEY(HASH_NAME, KEY_TYPE, HASH)                                    \

  GEN_DELETE_KEY(HASH_NAME, KEY_TYPE, HASH)
```

Допустим, в качестве типа данных, которые будут храниться в таблице, используются строки (`char*`), а в качестве хеш-функции - алгоритм FNV-1a:

```c
// получаем хеш-значение из строки алгоритмом FNV-1a
unsigned int hash_fnv1a(const char *str) 
{
   unsigned int hash = 2166136261u;

    while (*str) {
        hash ^= (unsigned char)(*str++);
        hash *= 16777619;
    }

    return hash;
}
// генерируем все макросы и через них все основные функции для работы с хеш-множествами на основе строк
#define STR_EQ(A, B) (strcmp(A, B) == 0)
GEN_HASH_TABLE(str, char *, STR_EQ, hash_fnv1a, free);
```

```c
struct str_bin_node { struct str_bin_node *next; char * key; }; 

struct str_bin_list { struct str_bin_node *head; };

void str_bin_add_key(struct str_bin_list * list, char * key) { 
    do { 
        typeof(**(&((list)->head))) *node = malloc(sizeof *node); 
        node->next = *((&((list)->head))); 
        *((&((list)->head))) = node; 
    } while (0); 
    (*(((&((list)->head)))))->key = key; 
}; 

void str_bin_delete_key(struct str_bin_list * list, const char * key) { 
    for (typeof(list->head) * itr = (&((list)->head)); !(!*(itr)); itr = (&((*(itr))->next))) { 
        if ((strcmp((*(itr))->key, key) == 0)) { 
            free((*(itr))->key); 
            do { 
                typeof(**itr) *next = (*(itr))->next; 
                free(*(itr)); 
                *(itr) = next; 
            } while (0); 
            return; 
        } 
    } 
}; 

int str_bin_contains_key(struct str_bin_list * list, const char * key) { 
    for (typeof(list->head) * itr = (&((list)->head)); !(!*(itr)); itr = (&((*(itr))->next))) { 
        if ((strcmp((*(itr))->key, key) == 0)) { 
            return 1; 
        } 
    } 
    return 0; 
} 

void str_bin_free_list(struct str_bin_list * list) { 
    typeof(list->head) * itr = (&((list)->head)); 
    while (!(!*(itr))) { 
        free((*(itr))->key); 
        do { 
            typeof(**itr) *next = (*(itr))->next; 
            free(*(itr)); *(itr) = next; 
        } while (0); 
    } 
}; 

struct str_hash_table { struct str_bin_list * bins; unsigned int size; unsigned int count; }; 

struct str_bin_list * str_get_key_bin(struct str_hash_table *table, unsigned int hash_key) { 
    unsigned int mask = table->size - 1; 
    unsigned int index = hash_key & mask; 
    return &table->bins[index]; 
} 

struct str_hash_table * str_new_table() { 
    struct str_hash_table *table = malloc(sizeof *table); 
    struct str_bin_list *bins = malloc(8 * sizeof *bins); 
    *table = (struct str_hash_table){.bins = bins, .size = 8, .count = 0}; 
    for (struct str_bin_list *bin = table->bins; bin < table->bins + table->size; bin++) { 
        bin->head = ((void *)0); 
    } 
    return table; 
} 

void str_free_table(struct str_hash_table *table) { 
    for (struct str_bin_list *bin = table->bins; bin < table->bins + table->size; bin++) { 
        str_bin_free_list(bin); 
    } 
    free(table->bins); 
    free(table); 
} 

void str_resize(struct str_hash_table *table, unsigned int new_size) { 
    struct str_bin_list *old_bins = table->bins, 
                        *old_from = old_bins, 
                        *old_to = old_from + table->size; 
    table->bins = malloc(new_size * sizeof *table->bins); 
    table->size = new_size; 
    for (struct str_bin_list *bin = table->bins; bin < table->bins + table->size; bin++) { 
        bin->head = ((void *)0); 
    } 
    for (struct str_bin_list *bin = old_from; bin < old_to; bin++) { 
        for (typeof(bin->head) * itr = (&((bin)->head)); !(!*(itr));) { 
            unsigned int hash_key = hash_fnv1a((*(itr))->key); 
            do { 
                typeof(**itr) *node = *itr; 
                *itr = node->next; 
                node->next = *((&((str_get_key_bin(table, hash_key))->head)); 
                *((&((str_get_key_bin(table, hash_key))->head)) = node; 
            } while (0); 
        } 
    } 
    free(old_bins); 
} 

void str_insert_key(struct str_hash_table *table, char * key) { 
    struct str_bin_list *bin = str_get_key_bin(table, hash_fnv1a(key)); 
    if (!str_bin_contains_key(bin, key)) { 
        str_bin_add_key(bin, key); 
        table->count++; 
        if (table->size == table->count) { 
            str_resize(table, 2*table->size); 
        } 
    } 
} 

int str_contains_key(struct str_hash_table *table, char * key) { 
    struct str_bin_list *bin = str_get_key_bin(table, hash_fnv1a(key)); 
    return str_bin_contains_key(bin, key); 
} 

void str_delete_key(struct str_hash_table *table, char * key) { 
    struct str_bin_list *bin = str_get_key_bin(table, hash_fnv1a(key)); 
    if (str_bin_contains_key(bin, key)) { 
        str_bin_delete_key(bin, key); 
        table->count--; 
        if (table->size > 8 && table->count < table->size / 4) { 
            str_resize(table, table->size / 2); 
        } 
    } 
};
```
