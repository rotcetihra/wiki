В прошлой теме была рассмотрена концепция хеш-функций, теперь же перейдем к определению хеш-таблиц на основе выбранной хеш-функции. Прежде всего необходимо определиться, а какие именно значения будет хранить хеш-таблица. Обычно это специфические для приложения данные. Кроме того, элемент хеш-таблицы может хранить некоторую вспомогательную — служебную информацию. Для упрощения примера возьмем структуру, которая содержит только хеш-ключ:

```c
struct bin
{
  unsigned int key;
};
```

В общем случае хеш-таблица состоит из массива, в котором можно хранить ключи, и числа, которое определяет размер таблицы и которое далее будем обозначать как m, для этого можно определить следующую структуру:

```c
struct bin
{
    unsigned int key;
};
struct hash_table
{
    struct bin* bins;
    unsigned int size;
};
```

Таким образом, у нас поле bins для хранения массива bin и поле size для хранения размера — количества bins.

Для создания подобной хеш-таблицы мы могли бы определить следующую функцию:

```c
#include <stdlib.h>

struct hash_table* new_table(unsigned int size)
{
    // Выделяем память под таблицу и массив бинов
    struct hash_table *table = malloc(sizeof *table);
    table->size = size;
    table->bins = malloc(size * sizeof *table->bins);
    return table;
}
```

В данном случае не учитываются ошибки выделения памяти (когда malloc() возвращает NULL), поскольку в данном случае основной упор делается на работе с хеш-таблицами, а не обработке ошибок. Но это можно легко сделать. Например:

```c
#include <stdlib.h>

struct hash_table* new_table(unsigned int size)
{
    // Выделяем память под таблицу и массив бинов
    struct hash_table* table = malloc(sizeof *table);
    struct bin* bins = malloc(size * sizeof *bins);
    if (!table || !bins) goto error;
    *table = (struct hash_table){.size = size, .bins = bins};
    return table;

error:
    free(table);
    free(bins);
    return NULL;
}
```

В данном случае для обработки ошибок применяется стандартный паттерн с применением goto. Однако, по мере изменения размера таблиц, работа с ошибками выделения памяти становится гораздо сложнее. Особенно когда каждая ошибка выделения памяти потенциально должна распространяться из глубоко вложенных вызовов функций, а в C нет удобного механизма для распространения ошибок. Поэтому, чтобы избежать усложнения кода и сосредоточится непосредственно на разных аспектах реализации хеш-таблиц, обработка ошибок далее будет опускаться.

Стоит отметить еще один момент относительно выделения памяти: если можно упаковать данные в меньшее количество выделений памяти, с ними будет проще работать. Так, это можно было бы сделать, поместив ячейки в так называемый гибкий массив:

```c
struct hash_table
{
  unsigned int size;
  struct bin bins[];    // гибкий динамический массив
};
```

Гибкий динамический массив — это массив, который объявляется в конце структуры без указания его длины. Если у вас есть такой элемент, вы можете выделить память для хеш-таблицы и ячеек за один вызов функции malloc():

```c
struct hash_table* new_table(unsigned int size)
{
    // Выделяем память под таблицу и массив бинов
    struct hash_table *table = malloc(sizeof *table + size * sizeof *table->bins);
    return table;
}
```

Суть данного приема в том, чтобы выделить достаточно памяти в вызове функции malloc() как для структуры, так и для элементов, которые надо поместить в массив. Здесь мы просто добавляем размер структуры к размеру массива bins.

Однако, хотя гибкий массив часто бывает полезен, он может усложнить задачу, если нужно перераспределить память для увеличения или уменьшения размера таблиц. Предположим, мы выделяем один блок памяти для таблицы плюс ячейки. В этом случае мы не сможем легко добавлять или удалять ячейки позже, потому что надо обновлять каждый указатель на таблицу, чтобы он указывал на вновь выделенную версию. Если же у нас есть указатель на таблицу, и у нее есть указатель на ее ячейки, то мы можем обновить указатель на ячейки один раз, и все будут иметь к нему доступ. Поэтому далее мы не будем использовать гибкий массив.

## Освобождение памяти

Чтобы освободить память таблицы, необходимо освободить как структуру таблицы, так и массив бинов. Для версии с негибким массивом это может выглядеть так:

```c
void delete_table(struct hash_table *table)
{
    free(table->bins);
    free(table);
}
```

Для версии с гибким массивом это может выглядеть так:

```c
void delete_table(struct hash_table *table)
{
    free(table);
}
```

Либо даже просто вызвать функцию free(), не определяя отдельную функцию.
