Размер хеш-таблицы может сыграть большую роль при работе с таблицами. В качестве размера хеш-таблицы нередко выбирают либо степень двойки (например, 64, 1024 и т.д.), либо простое число. У обоих способов есть свои преимущества и недостатки. Рассмотрим их.

## Степень двойки (2n)

Этот вариант часто выбирают ради максимальной скорости. Его преимущества:

- **Быстрота:** операция взятия остатка (hash % size) заменяется на поразрядную операцию (hash & (size - 1)), которая выполняется процессором за один такт.
- **Удобство:** таблицу легко расширять ровно в два раза, что упрощает рехеширование.

Однако у этого способа есть и недостатки. В частности, чувствительность к хеш-функции: используются только младшие биты хеша. Если хеш-функция распределяет значения неравномерно в нижних битах, возникнет огромное количество коллизий (совпадающих значений).

## Простое число

Этот подход ориентирован на минимизацию коллизий. Его преимущества:

- **Стойкость к плохим хешам:** даже если применяемая хеш-функция выдает значения с определенным шагом (например, все хеши кратны 10), взятие остатка по простому числу "размажет" их по таблице равномерно.
- **Эффективность двойного хеширования:** простое число гарантирует, что шаг при двойном хешировании будет взаимно простым с размером таблицы, и вы обойдете все ячейки.

К недостаткам стоит отнести:

- **Медлительность:** операция деления по модулю (%) является одной из самых затратных для процессора.
- **Сложность:** нужно заранее хранить список подходящих простых чисел для изменения размера таблицы.

Чтобы проиллюстрировать проблему выбора размера, рассмотрим пример. Предположим, что все хеш-ключи можно записать как h = n ⋅ k. На первый взгляд это выглядит искусственно, но такая схема распространена. Если, например, вы хотите использовать хеш-указатели, их младшие биты часто равны нулю, поскольку разные типы данных часто должны располагаться по определенным смещениям адреса. Целые числа, например, часто должны располагаться по смещениям, кратным четырем или восьми, и это сделало бы целочисленные указатели типом хеш-ключа вида n ⋅ 4 или n ⋅ 8. Если размер таблицы m имеет общий простой множитель с h, скажем, m = m′ ⋅ k, то операция h mod m будет принимать только значения, кратные этому общему множителю, в данном случае k. Если k = 4 и m = 8, то мы бы получили:

```
0 mod 8 = 0
4 mod 8 = 4
8 mod 8 = 0
12 mod 8 = 4
16 mod 8 = 0
и так далее...
```

В итоге, в этом случае мы используем только две из восьми ячеек хеш-таблицы.

Если же размер таблицы равен простому числу, вероятность совпадения снижается. Это не обязательно будет равномерным распределением — оно все еще будет зависеть от распределения хеш-ключей, но распределение в самой хеш-таблице будет более равномерным.

Но как было отмечено выше, использование простых чисел имеет недостатки. Часто потребуется изменять размер таблиц, если количество ключей заранее неизвестно. Если вы хотите использовать простые числа, вам понадобится таблица простых чисел, из которой можно выбирать при увеличении или уменьшении размера таблицы. Если же вы выберете размеры таблиц, которые являются степенями двойки, их легко увеличивать и уменьшать.

Но можно легко комбинировать модуль простых чисел с этой идеей: если вы выберете простое число p > m, вы сможете индексировать ячейки как h(x) mod p mod m. Модуль p уменьшает проблему регулярности ключей, и если m является степенью двойки, вы можете легко увеличивать и уменьшать размеры таблиц. Это также отделяет вычисление хеш-ключа от использования хеш-ключей для индексации таблиц. Таким образом, будет двухэтапное решение, где мы начинаем с хешей в [N], отображаем их с помощью модуля на [p], а затем продолжаем так, как если бы хеш-ключи изначально были равномерно распределены в [p].

## Сопоставление хеш-ключей с ячейками и индексами хеш-таблицы

Наиболее простой подход сопоставления ключа хеша из [N] с диапазоном индексов в массиве [m] представляет получение остатка от деления на m, используя оператор деления по модулю:

```c
unsigned int hash_bin_index(struct hash_table *table, unsigned int key)
{
    return key % table->size;
}
```

Это решение отображает из [N] в [m] и будет работать для всех m < N. Однако, даже при равномерном распределении хеш-ключей в [N] (то есть хеш-функция для разных значений генерирует в целом разные хеш-ключи или с очень редкими повторениями), это отображение не обязательно гарантирует, что в результате выполнения операции key % table->size мы получим также равномерно распределенные ключи в [m].

Использование операции по модулю отобразит равномерное распределение по [N] в равномерное распределение по [m] только тогда, когда N mod m = 0. Иначе некоторые значения будут встречаться чаще, чем другие, хотя и незначительно. Если бы мы отобразили все числа 0…N − 1 в [m], то некоторые полученные значения для [m] встречались бы чаще, чем другие, если m не делится на N нацело.

## Реализация для степени двойки

Если размер хеш-таблицы (m) представляет степень двойки (m = 2k), то взятие остатка от деления на m эквивалентно маскированию младших k бит ключа:

```c
unsigned int hash_bin_index(struct hash_table *table, unsigned int key)
{
    unsigned int mask = table->size - 1;
    unsigned int index = key & mask;
    return index;
}
```

Вычитание единицы из размера таблицы (m = 2k) даст младшие k бит, а маскирование с помощью этого значения даст индекс. Маскирование — более быстрая операция по сравнению с получением остатка от деления. Компиляторы, конечно, могут оптимизировать операцию взятия остатка от деления, если они знают, что m является степенью двойки, но если m — простое число (и больше двух), это мало помогает.

## Реализация для простых чисел

Если размер хеш-таблицы (m) должен представлять простое число, то можно воспользоваться простыми числами Мерсенна (Mersenne primes) — это числа вида 2s - 1. Например, это может быть число 261 - 1, которое может быть хорошим выбором для 32-битных значений. Поскольку в этом случае мы можем уйти от операции получения остатка в пользу более быстрых операций. Для этого рассмотрим следующий процесс:

Пусть p = 2s - 1 (p — выбранное нами простое число Мерсенна), а x (хеш-ключ, которое надо поместить в хеш-таблицу) может быть больше p. Соответственно, чтобы вписать x в пространство чисел [0..p] нам надо получить остаток от деления x mod p.

Представим x в виде a*2s + b (b < 2s). Таким образом, мы получим:
- b = x mod 2s
- a = x / 2s (целочисленное деление)

(b — это остаток от деления на 2s (младшие биты), а a — результат деления на 2s (старшие биты)).

На основании того, что b = x mod 2s и a = x / 2s, мы получаем:

x mod p = (a*2s + b) mod p = (x / 2s * 2s + x mod 2s) mod p

По свойствам модульной арифметики, операцию модуля можно применять к отдельным частям выражения. И поскольку 2s mod p = 1, мы имеем:

(x / 2s * 2s + x mod 2s) mod p = (x / 2s + x mod 2s) mod p

Полученное выше выражение мы можем разбить на два этапа:

```
y = x / 2s + x mod 2s;
result = y mod p;
```

Поскольку операция x mod 2s эквивалентна маскированию x на s разрядов, а операция x/2s эквивалентна сдвигу x вправо на s разрядов, мы можем вычислить остаток от деления следующим образом:

```
p = 1 << s - 1;
y = (x & p) + (x >> s);
result = y mod p;
```

В зависимости от того, больше ли y чем p или меньше, вместо деления по модулю мы можем перейти к условной конструкции:

```
p = 1 << s - 1;
y = (x & p) + (x >> s);
result = (y > p) ? y - p : y; // y mod p
```

Пример для наглядности: пусть s = 3, тогда p = 2^3 - 1 = 7. Возьмем x = 19.
Обычный расчет: 19 mod 7 = 5.
Расчет через формулу:

1. Разделим 19 на 2^s (т.е. на 8):
   - a = 19 / 8 = 2
   - b = 19 mod 8 = 3
2. Сложим их: y = a + b = 2 + 3 = 5

Если перевести на код C, то мы можем определить вычисление значения в виде следующей функции:

```c
uint64_t mod_Mersenne(uint64_t x, uint8_t s) {
    uint64_t p = (uint64_t)(1 << s) - 1;
    uint64_t y = (x & p) + (x >> s);
    return (y > p) ? y - p : y;
}
```

Это позволяет избежать умножения и деления по модулю и использует только быстрые поразрядные операции, что будет намного быстрее, чем деление по модулю.

## Получение корзины хеш-таблицы

Получив индекс в хеш-таблице (вне зависимости от способа получения индекса), мы можем получить указатель на ячейку/корзину (bin) хеш-таблицы, которая собственно и должна хранить данные. Так, мы могли бы просто прибавить индекс и получить указатель на память, где будет храниться указатель на данные корзины:

```c
struct bin* hash_bin(struct hash_table *table, unsigned int key)
{
    return table->bins + hash_bin_index(table, key);
}
```

## Полный пример

Для общей картины приведу вкратце пример кода от хеширования строк до получения корзин для этих строк:

```c
#include <stdio.h>
#include <stdint.h>
#include <stdlib.h>

// структура корзины в хеш-таблице
struct bin
{
    unsigned int key;
};

// структура хеш-таблицы
struct hash_table
{
    struct bin* bins;
    unsigned int size;
};

// создание хеш-таблицы
struct hash_table* new_table(unsigned int size);
// удаление хеш-таблицы
void delete_table(struct hash_table *table);

// получаем хеш-ключ из строки
unsigned int hash_fnv1a(const char *str);

// получение индекса корзины в хеш-таблице
unsigned int hash_bin_index(struct hash_table *table, unsigned int key);
// получение указателя на корзину из хеш-таблицы table по индексу key
struct bin* hash_bin(struct hash_table *table, unsigned int key);

int main(void)
{
    // берем две строки и получаем их хеш
    char* red = "red";
    char* green = "green";

    unsigned int red_hash = hash_fnv1a(red);
    unsigned int green_hash = hash_fnv1a(green);

    printf("String: %s \thash: %u \n",red, red_hash);
    printf("String: %s \thash: %u \n",green, green_hash);

    // создаем хеш-таблицу
    const unsigned int table_size = 1024;
    struct hash_table* table = new_table(table_size);
    printf("Hash table located at: %p \n", table);

    // получаем индексы для хеш-значений строк в рамках хеш-таблицы
    unsigned int red_index = hash_bin_index(table, red_hash);
    unsigned int green_index = hash_bin_index(table, green_hash);
    printf("String: %s \tindex: %u \n",red, red_index);
    printf("String: %s \tindex: %u \n",green, green_index);

    // получаем сами корзины для хеш-значений в хеш-таблице
    struct bin* red_bin = hash_bin(table, red_hash);
    struct bin* green_bin = hash_bin(table, green_hash);
    printf("String: %s \taddress in table: %p \n",red, red_bin);
    printf("String: %s \taddress in table: %p \n",green, green_bin);

    // удаляем таблицу
    delete_table(table);

    return 0;
}

// получаем хеш-ключ из строки
unsigned int hash_fnv1a(const char *str)
{
   unsigned int hash = 2166136261u;

    while (*str)
    {
        hash ^= (unsigned char)(*str++);
        hash *= 16777619;
    }

    return hash;
}

// создание хеш-таблицы
struct hash_table* new_table(unsigned int size)
{
    struct hash_table *table = malloc(sizeof *table);
    table->size = size;
    table->bins = malloc(size * sizeof *table->bins);
    return table;
}

// удаление хеш-таблицы
void delete_table(struct hash_table *table)
{
    free(table->bins);
    free(table);
}

// получение индекса корзины в хеш-таблице
unsigned int hash_bin_index(struct hash_table *table, unsigned int key)
{
    unsigned int mask = table->size - 1;
    unsigned int index = key & mask;
    return index;
}

// получение указателя на корзину из хеш-таблицы table по индексу key
struct bin* hash_bin(struct hash_table *table, unsigned int key)
{
    return table->bins + hash_bin_index(table, key);
}
```

Пример консольного вывода:

```

String: green 	hash: 18738364

Hash table located at: 0x59aa481616b0

String: red 	index: 220
String: green 	index: 188

String: red 	address in table: 0x59aa48161a40
String: green 	address in table: 0x59aa481619c0
```
