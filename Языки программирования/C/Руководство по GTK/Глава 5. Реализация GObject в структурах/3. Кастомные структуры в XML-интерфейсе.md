По умолчанию GTK позволяет нам использовать в определении xml-интерфейса широкий диапазон встроенных типов, в частности, виджетов. Однако может возникнуть необходимость использовать в xml какие-то свои кастомные типы/структуры. В этой статье рассмотрим использование кастомных классов в XML-интерфейсе.

## Подготовка приложения

Прежде всего надо понимать, что, чтобы использовать объект в xml, этот объект должен представлять тип GObject. В прошлых статьях уже был рассмотрен принцип реализации для структуры функционала GObject. Поэтому я не буду на этом останавливаться. Итак, определим следующее приложение:

```c
#include <gtk/gtk.h>

typedef struct _Person {
    GObject parent_instance;
    char *name;
    int age;
} Person;

typedef struct _PersonClass {
    GObjectClass parent_class;
} PersonClass;

#define PERSON_TYPE person_get_type()
G_DEFINE_TYPE(Person, person, G_TYPE_OBJECT)  // Определяем новый тип GObject

// Функция инициализации объекта Person
static void person_init(Person *person) {
    person->name = NULL;
    person->age = 0;
}

// Функция финализации (удаления) объекта Person
static void person_finalize(GObject *object) {
    Person *person = (Person *)object;

    if (person->name) {
        g_free(person->name);  // освобождаем память
    }

    G_OBJECT_CLASS(person_parent_class)->finalize(object);
}
// идентификаторы свойств
enum {
    PROP_NAME=1,
    PROP_AGE,
    N_PROPERTIES
};
// определение свойств
static GParamSpec* obj_properties[N_PROPERTIES] = { NULL, };


// установка свойств
static void person_set_property(GObject* object, guint prop_id, const GValue* value, GParamSpec* pspec) {
    Person* self = (Person*)object;

    switch (prop_id) {
        case PROP_NAME:
            g_free(self->name);
            self->name = g_value_dup_string(value);
            break;
        case PROP_AGE:
            self->age = g_value_get_int(value);
            break;
        default:
            G_OBJECT_WARN_INVALID_PROPERTY_ID(object, prop_id, pspec);
            break;
    }
}

// получение свойств
static void person_get_property(GObject* object, guint prop_id, GValue* value, GParamSpec* pspec) {
    Person* self = (Person*)object;

    switch (prop_id) {
        case PROP_NAME:
            g_value_set_string(value, self->name);
            break;
        case PROP_AGE:
            g_value_set_int(value, self->age);
            break;
        default:
            G_OBJECT_WARN_INVALID_PROPERTY_ID(object, prop_id, pspec);
            break;
    }
}

// инициализация класса
static void person_class_init(PersonClass *class) {

    GObjectClass* object_class = G_OBJECT_CLASS(class);

    // переопределяем функции set_property и get_property для GObject
    object_class->set_property = person_set_property;
    object_class->get_property = person_get_property;

    // определяем свойства
    obj_properties[PROP_NAME] = g_param_spec_string(
        "name", "Name", "Person name", NULL, G_PARAM_READWRITE);
    obj_properties[PROP_AGE] = g_param_spec_int(
        "age", "Age", "Person age", 0, G_MAXINT, 0, G_PARAM_READWRITE);

    g_object_class_install_properties(object_class, N_PROPERTIES, obj_properties);

    G_OBJECT_CLASS(class)->finalize = person_finalize;
}

// Функция-конструктор для объекта Person
Person* person_new(const char *name, int age) {
    Person *person = g_object_new(PERSON_TYPE, NULL);
    person->name = g_strdup(name);  // копируем строку
    person->age = age;
    return person;
}


static void app_activate (GtkApplication *app, gpointer *user_data) {

    // гарантируем, что все типы для использования в xml определены
    g_type_ensure(PERSON_TYPE);
    // берем определение интерфейса из person.ui
    GtkBuilder *builder = gtk_builder_new_from_file("person.ui");

    GObject* window = gtk_builder_get_object (builder, "window");
    gtk_window_set_application (GTK_WINDOW (window), app);
    gtk_window_present (GTK_WINDOW (window));
}

int main (int argc, char **argv)
{
    GtkApplication *app = gtk_application_new ("com.metanit", G_APPLICATION_DEFAULT_FLAGS);
    g_signal_connect (app, "activate", G_CALLBACK (app_activate), NULL);
    int status = g_application_run (G_APPLICATION (app), argc, argv);
    g_object_unref(app);

    return status;
}
```

Основная часть кода - это реализации GObject для структуры Person, которая рассматривалась в прошлых статьях. Поэтому рассмотрим непосредственно определение интерфейса в функции `app_activate`.

## Определение интерфейса

Прежде всего здесь вызываем функцию:

```c
g_type_ensure(PERSON_TYPE);
```

Эта функция позволяет гарантировать, что тип, который передается в качестве параметра (в нашем случае - PERSON_TYPE, то есть фактически структура Person), будет определена, приложение будет видеть этот тип.

Далее мы загружаем файл интерфейса "person.ui":

```c
GtkBuilder *builder = gtk_builder_new_from_file("person.ui");
```

## XML-интерфейс

Теперь определим сам файл person.ui:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<interface>
    <object class="Person" id="tom">
        <property name="name">Tom</property>
        <property name="age">40</property>
    </object>
  <object class="GtkWindow" id="window">
    <property name="visible">True</property>
    <property name="title">METANIT.COM</property>
    <property name="default-width">250</property>
    <property name="default-height">200</property>
    <child>
      <object class="GtkBox">
        <property name="orientation">GTK_ORIENTATION_VERTICAL</property>
        <property name="spacing">10</property>
        <child>
            <object class="GtkLabel">
            <property name="xalign">0</property>
            <property name="label" 
                    bind-source="tom"
                    bind-property="name"
                    bind-flags="sync-create" />
            </object>
        </child>
        <child>
            <object class="GtkLabel">
                <property name="xalign">0</property>
                <property name="label"
                        bind-source="tom"
                        bind-property="age"
                        bind-flags="sync-create" />
            </object>
        </child>
      </object>
      </child>
  </object>
</interface>
```

Прежде всего мы определяем объект Person (как другие объекты GObject, например, виджеты):

```xml
<object class="Person" id="tom">
    <property name="name">Tom</property>
    <property name="age">40</property>
</object>
```

У объекта установлены оба свойства. И здесь как раз неявно вызывается инфраструктура свойств, которая определена для типа Person. Кроме того, для объекта определен идентификатор "tom", через который мы сможем к нему обращаться в других местах приложения.

## Привязка свойств

Далее определен GtkBox с двумя метками, которые выводят значения свойств name и age. Например, возьмем свойство label первой метки, которое определяет текст метки:

```xml
<property name="label" 
    bind-source="tom"
    bind-property="name"
    bind-flags="sync-create" />
```

Здесь применяются три атрибута:

- `bind-source`: идентификатор объекта, к которому идет привязка. То есть здесь мы привязываемся к объекту tom
- `bind-property`: свойство объекта, к которому идет привязка. Здесь привязка идет к свойству name
- `bind-flags`: флаги привязки. Флаг `sync-create` при создании объекта Label выполнит привязку свойства name объекта tom к свойству label метки

Вторая метка однотипна, только привязка идет к свойству age.

В итоге при выполнении приложения метки отобразят значения соответствующих свойств объекта Person.
