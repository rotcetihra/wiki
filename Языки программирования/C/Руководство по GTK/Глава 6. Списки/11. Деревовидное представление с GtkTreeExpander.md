Виджет GtkTreeExpander позволяет создать древовидное представление элементов. Обычно GtkTreeExpander не используется сам по себе, а размещается как самый нижний дочерний элемент в GtkListView, чтобы пользователи могли разворачивать и сворачивать дочерние элементы в списке.

Для создания виджета применяется функция-конструктор `gtk_tree_expander_new()`, которая не принимает параметров:

```c
GtkWidget* treeView =  gtk_tree_expander_new();
```

Для GtkTreeExpander доступно немного свойств:

- `child`: дочерний виджет с фактическим содержимым.
- `hide-expander`: указывает, надо ли скрывать узел дерева.
- `indent-for-depth`: отступ дочернего элемента в соответствии с его глубиной.
- `indent-for-icon`: отступ дочернего элемента на ширину значка, если он не может быть развернут.
- `item`: элемент строки.
- `list-row`: строка GtkTreeListRow для каждого элемента списка.

Для управления этими свойствами GTK предоставляет следующие функции:

- `gtk_tree_expander_get_child`: возвращает дочерний виджет, создаваемый для каждого элемента дерева.
- `gtk_tree_expander_get_hide_expander`: возвращает значение, которое указывает, следует ли скрывать узел дерева.
- `gtk_tree_expander_get_indent_for_depth`: возвращает отступ глубины.
- `gtk_tree_expander_get_indent_for_icon`: возвращает отступ дочернего виджета на ширину значка расширения, если он не может быть развернут.
- `gtk_tree_expander_get_item`: возвращает набор элементов в GtkTreeListRow.
- `gtk_tree_expander_get_list_row`: возвращает строку списка - GtkTreeListRow.
- `gtk_tree_expander_set_child`: устанавливает виджет для отображения элементов дерева.
- `gtk_tree_expander_set_hide_expander`: устанавливает, должен ли значок расширителя быть видимым в GtkTreeListRow.
- `gtk_tree_expander_set_indent_for_depth`: устанавливает отступ дочернего элемента в соответствии с его глубиной.
- `gtk_tree_expander_set_indent_for_icon`: устанавливает отступ дочернего элемента на ширину значка расширителя, когда он не может быть развернут.
- `gtk_tree_expander_set_list_row`: устанавливает строку списка - GtkTreeListRow, которая создается для каждого элемента.

## GtkTreeListModel

Неотъемлемый компонент при работе с древовидными виджетами - это тип GtkTreeListModel - модель данных, специально заточенная под древовидные представления. Данный тип реализует интерфейс GListModel.

Для создания модели применяется функция-конструктор `gtk_tree_list_model_new()`:

```c
GtkTreeListModel*
gtk_tree_list_model_new (
  GListModel* root,
  gboolean passthrough,
  gboolean autoexpand,
  GtkTreeListModelCreateModelFunc create_func,
  gpointer user_data,
  GDestroyNotify user_destroy
)
```

Она принимает следующие параметры:

- `root`: объект GListModel для использования в качестве корневой модели
- `passthrough`: логическое значение, которое указывает, надо ли передавать элементы из дочерних моделей (true для передачи элементов из моделей).
- `autoexpand`: логическое значение, которое указывает, надо ли раскрывать узлы корневой модели и наполнять их данными (true для раскрытия узлов)
- `create_func`: функция типа GtkTreeListModelCreateModelFunc для создания моделей GListModel для дочерних элементов.
- `user_data`: данные для передачи в `create_func`, может быть NULL.
- `user_destroy`: функция типа GDestroyNotify для освобождения `user_data`.

Приведу типовое создание объекта этой модели:

```c
GtkStringList* categories =  gtk_string_list_new((const char *[]) {"Категория 1", "Категория 2", NULL});
GtkTreeListModel* list = gtk_tree_list_model_new(G_LIST_MODEL(categories), FALSE, FALSE, create_func, NULL, NULL);
```

Здесь сначала определяется корневая модель - `categories` в виде объекта GtkStringList - модели, которая хранит набор строк. И эта модель передается в качестве первого параметра в функцию-конструктор `gtk_tree_list_model_new()`.

Второй (`passthrough`) и третий (`autoexpand`) параметры равны FALSE. То есть нам не надо передавать данные из дочерних моделей и не надо раскрывать узлы корневой модели. Последние два параметра (`user_data` и `user_destroy`) равны NULL, так как данные мы никакие не передаем и соответственно явным образом освобождать ресурсы от нас не требуется.

Теперь рассмотрим четвертый аргумент - функцию `create_func`. Эта функция представляет указатель на функцию GtkTreeListModelCreateModelFunc:

```c
GListModel*
(* GtkTreeListModelCreateModelFunc) (
  GObject* item,
  gpointer user_data
)
```

Она принимает два параметра:

- `item`: элемент, который будет раскрываться и наполняться некоторыми данными.
- `user_data`: дополнительные данные, которые передаются в функцию.

Рассмотрим пример такой функции, отталкиваясь от ранее определенной в предыдущем листинге кода корневой модели `categories`:

```c
GListModel* create_func (void* item, gpointer user_data){

    // получаем элемент из корневой модели
    GtkStringObject* strobj = (GtkStringObject *)item;
    // получаем сам текст
    const char* parent = gtk_string_object_get_string(strobj);

    // дочерняя модель для каждого элемента корневой модели
    GtkStringList *child_list = gtk_string_list_new(NULL);

    // Добавляем дочерние элементы в зависимости от родителя
    if (g_str_equal(parent, "Категория 1")) {
        gtk_string_list_append(child_list, "Подкатегория 1.1");
        gtk_string_list_append(child_list, "Подкатегория 1.2");
    } 
    else if (g_str_equal(parent, "Категория 2")) {
        gtk_string_list_append(child_list, "Подкатегория 2.1");
        gtk_string_list_append(child_list, "Подкатегория 2.2");
        gtk_string_list_append(child_list, "Подкатегория 2.3");
    }
    else return NULL; // если для элемента не нужна дочерняя модель и у него нет вложенных элементов

    return G_LIST_MODEL(child_list);
}
```

Напомню, что наша корневая модель `categories` содержит строки (две строки) и представляет по сути объект GtkStringList. Поэтому параметр `item` этой функции `create_func` представляет GtkStringObject (то есть по сути строку). И вначале получаем эту строку и ее текст:

```c
GtkStringObject* strobj = (GtkStringObject *)item;
const char* parent = gtk_string_object_get_string(strobj);
```

Цель функции `create_func` - возвратить (создать) модель с вложенными данными для элемента `item`, то есть дочернюю модель для каждого текущего элемента модели. В нашем случае дочерняя модель также будет представлять набор строк:

```c
GtkStringList *child_list = gtk_string_list_new(NULL);
```

Далее добавляем дочерние элементы в зависимости от родителя:

```c
if (g_str_equal(parent, "Категория 1")) {
    gtk_string_list_append(child_list, "Подкатегория 1.1");
    gtk_string_list_append(child_list, "Подкатегория 1.2");
} 
else if (g_str_equal(parent, "Категория 2")) {
    gtk_string_list_append(child_list, "Подкатегория 2.1");
    gtk_string_list_append(child_list, "Подкатегория 2.2");
    gtk_string_list_append(child_list, "Подкатегория 2.3");
}
else return NULL; // если для элемента не нужна дочерняя модель и у него нет вложенных элементов

return G_LIST_MODEL(child_list);
```

Здесь с помощью встроенной в GTK функции `g_str_equal()` сравниваем, для какого именно элемента надо создать модель, и зависимости от этого наполняем модель данными. Следует учитывать, что нередко элементы не имеют дочерних элементов, соответственно для них не нужна дочерняя модель. И в этом случае мы можем просто возвратить NULL. Далее мы увидим действие этой функции на полном примере.

Рассмотрим базовый функционал типа GtkTreeListModel. Свойства GtkTreeListModel:

- `autoexpand`: логическое значение, которое указывает, надо ли раскрывать корневую модель и наполнять ее данными (TRUE для раскрытия модели).
- `item-type`: тип элементов
- `model`: отображаемая корневая модель.
- `n-items`: количество элементов
- `passthrough`: логическое значение, которое указывает, надо ли передавать элементы из дочерних моделей (TRUE для передачи элементов из моделей)

Для управления этими свойствами для GtkTreeListModel доступны следующие функции:

- `gtk_tree_list_model_get_autoexpand`: указывает, настроена ли модель на автоматическое развертывание новых добавляемых строк.
- `gtk_tree_list_model_get_child_row`: возвращает элемент строки, соответствующий дочернему элементу в индексной позиции для корневой модели.
- `gtk_tree_list_model_get_model`: возвращает корневую модель
- `gtk_tree_list_model_get_passthrough`: возвращает значение свойства `passthrough`.
- `gtk_tree_list_model_get_row`: возвращает объект определенной строки.
- `gtk_tree_list_model_set_autoexpand`: устанавливает, должна ли модель автоматически развертываться.

> [!NOTE]
> Обратите внимание, что большую часть свойств можно установить только с помощью функции-конструктора.

## GtkTreeListRow

Еще один важный аспект, который надо учитывать при работе с типом GtkTreeListModel, это тип GtkTreeListRow, который представляет тип элемента, используемый моделью GtkTreeListModel.

Объекты GtkTreeListRow создаются GtkTreeListModel только в том случае, если свойство GtkTreeListModel:passthrough равно FALSE.

GtkTreeListRow имеет следующие свойства:

- `children`: модель с дочерними элементами строки.
- `depth`: глубина в дереве для этой строки.
- `expandable`: может ли быть раскрыта ли эта строка
- `expanded`: раскрыта ли эта строка в данный момент
- `item`: элемент, который содержится в этой строке

Для GtkTreeListModel не существует функций-конструкторов. Для управления свойствами GTK предоставляет следующие функции:

- `gtk_tree_list_row_get_child_row()`: возвращает дочернюю строку GtkTreeListRow по определенной позиции. Если текущая строка не развернута или переданная позиция больше, чем количество дочерних элементов, возвращается NULL.
- `gtk_tree_list_row_get_children()`: если строка развернута, возвращает модель GListModel, которая содержит все дочерние строки GtkTreeListRow.
- `gtk_tree_list_row_get_depth()`: возвращает глубину строки.
- `gtk_tree_list_row_get_expanded()`: возвращает TRUE, если строка развернута в данный момент, или FALSE - если не развернута.
- `gtk_tree_list_row_get_item()`: возвращает элемент - собственно данные этой строки
- `gtk_tree_list_row_get_parent()`: возвращает родительскую строку для текущей строки.
- `gtk_tree_list_row_get_position()`: возвращает позицию в GtkTreeListModel, которую текущая строка занимает в данный момент.
- `gtk_tree_list_row_is_expandable()`: проверяет, можно ли развернуть строку.
- `gtk_tree_list_row_set_expanded()`: разворачивает или сворачивает строку.

Таким образом, чтобы получить данные из строки, надо использовать функцию `gtk_tree_list_row_get_item()`. Например:

```c
#include <gtk/gtk.h>

// Определяем функцию для создания дочерних элементов
GListModel* create_func (void* item, gpointer user_data){

    GtkStringObject* strobj = (GtkStringObject *)item;
    const char* parent = gtk_string_object_get_string(strobj);

    GtkStringList *child_list = gtk_string_list_new(NULL);

    // Добавляем дочерние элементы в зависимости от родителя
    if (g_str_equal(parent, "Категория 1")) {
        gtk_string_list_append(child_list, "Подкатегория 1.1");
        gtk_string_list_append(child_list, "Подкатегория 1.2");
    } 
    else if (g_str_equal(parent, "Категория 2")) {
        gtk_string_list_append(child_list, "Подкатегория 2.1");
        gtk_string_list_append(child_list, "Подкатегория 2.2");
        gtk_string_list_append(child_list, "Подкатегория 2.3");
    }
    else return NULL;

    return G_LIST_MODEL(child_list);
}

int main (int argc, char **argv)
{
    // определяем модель
    GtkStringList* categories =  gtk_string_list_new((const char *[]) {"Категория 1", "Категория 2", NULL});
    GtkTreeListModel* list = gtk_tree_list_model_new(G_LIST_MODEL(categories), FALSE, FALSE, create_func, NULL, NULL);

    // получаем все элементы из модели list
    GtkTreeListRow* row = NULL;
    for(size_t i=0; row = gtk_tree_list_model_get_child_row(list, i); ++i){

        // для каждой строки получаем ее элемент
        GtkStringObject* strobj = (GtkStringObject *)gtk_tree_list_row_get_item(row);
        const char* item = gtk_string_object_get_string(strobj);
        puts(item);
    }

    return 1;
}
```

Для краткости примера здесь определено консольное приложение. В цикле с помощью функции `gtk_tree_list_model_get_child_row()` получаем из модели `list` (GtkTreeListModel) каждый элемент по индексу в виде объекта GtkTreeListRow. Далее у этого объекта с помощью функции `gtk_tree_list_row_get_item()` получаем собственно данные. В нашем случае это строки, обернутые в объект GtkStringObject. В итоге на консоль будет выведено:

```
Категория 1
Категория 2
```

Но у нас для каждой категории функция `create_func` определяет несколько подкатегорий. Получим эти подкатегории:

```c
#include <gtk/gtk.h>

// Определяем функцию для создания дочерних элементов
GListModel* create_func (void* item, gpointer user_data){

    GtkStringObject* strobj = (GtkStringObject *)item;
    const char* parent = gtk_string_object_get_string(strobj);

    GtkStringList *child_list = gtk_string_list_new(NULL);

    // Добавляем дочерние элементы в зависимости от родителя
    if (g_str_equal(parent, "Категория 1")) {
        gtk_string_list_append(child_list, "Подкатегория 1.1");
        gtk_string_list_append(child_list, "Подкатегория 1.2");
    } 
    else if (g_str_equal(parent, "Категория 2")) {
        gtk_string_list_append(child_list, "Подкатегория 2.1");
        gtk_string_list_append(child_list, "Подкатегория 2.2");
        gtk_string_list_append(child_list, "Подкатегория 2.3");
    }
    else return NULL;

    return G_LIST_MODEL(child_list);
}

int main (int argc, char **argv)
{
    // определяем модель
    GtkStringList* categories =  gtk_string_list_new((const char *[]) {"Категория 1", "Категория 2", NULL});
    GtkTreeListModel* list = gtk_tree_list_model_new(G_LIST_MODEL(categories), FALSE, FALSE, create_func, NULL, NULL);


    // получаем все элементы из модели list
    GtkTreeListRow* row = NULL;
    for(size_t i=0; row = gtk_tree_list_model_get_child_row(list, i); ++i){

        // для каждой строки получаем ее элемент
        GtkStringObject* strobj = (GtkStringObject *)gtk_tree_list_row_get_item(row);
        const char* item = gtk_string_object_get_string(strobj);
        puts(item);

        // раскрываем узел дерева
        gtk_tree_list_row_set_expanded(row, TRUE);
        // получаем вложенные элементы для каждой категории
        GListModel* children = gtk_tree_list_row_get_children(row);

        // получаем количество элементов
        guint count = g_list_model_get_n_items(children);    
        printf("count: %u \n", count);

        // проходим по всем этим элементам
        for(guint j =0; j < count; ++j){

            GtkStringObject* childStrobj = (GtkStringObject *)g_list_model_get_object(children, j);
            const char* childItem = gtk_string_object_get_string(childStrobj);
            puts(childItem);
        }
        putchar(10);
    }

    return 1;
}
```

Итак, `create_func` для каждой категории определяет модель GtkStringList, которая состоит из нескольких подкатегорий. Эту модель для каждой строки можно получить с помощью функции `gtk_tree_list_row_get_children()`. Единственное надо помнить, что перед получением нам надо раскрыть строку с помощью функции `gtk_tree_list_row_set_expanded()`:

```c
gtk_tree_list_row_set_expanded(row, TRUE);
GListModel* children = gtk_tree_list_row_get_children(row);
```

Для их получения в функции `main` для каждой категории добавляется вложенный цикл, где получаем все вложенные подкатегории, которые также представляют строки:

```c
guint count = g_list_model_get_n_items(children);    
printf("count: %u \n", count);

for(guint j =0; j < count; ++j){

    GtkStringObject* childStrobj = (GtkStringObject *)g_list_model_get_object(children, j);
    const char* childItem = gtk_string_object_get_string(childStrobj);
    puts(childItem);
}
```

Консольный вывод программы:

```

count: 2 
Подкатегория 1.1
Подкатегория 1.2

Категория 2
count: 3
```

## Построение графического дерева

Итак, выше была описана базовая механика создания представления дерева в виде модели. Теперь посмотрим, как нам все это использовать в полноценном графическом приложении:

```c
#include <gtk/gtk.h>

// Определяем функцию для создания дочерних элементов
GListModel* create_func (void* item, gpointer user_data){

    GtkStringObject* strobj = (GtkStringObject *)item;
    const char* parent = gtk_string_object_get_string(strobj);

    GtkStringList *child_list = gtk_string_list_new(NULL);

    // Добавляем дочерние элементы в зависимости от родителя
    if (g_str_equal(parent, "Категория 1")) {
        gtk_string_list_append(child_list, "Подкатегория 1.1");
        gtk_string_list_append(child_list, "Подкатегория 1.2");
    } 
    else if (g_str_equal(parent, "Категория 2")) {
        gtk_string_list_append(child_list, "Подкатегория 2.1");
        gtk_string_list_append(child_list, "Подкатегория 2.2");
        gtk_string_list_append(child_list, "Подкатегория 2.3");
    }
    else return NULL;

    return G_LIST_MODEL(child_list);
}


static void setup_listitem (GtkListItemFactory *factory, GtkListItem *listitem)
{
    GtkWidget *expander = gtk_tree_expander_new();
    GtkWidget *label = gtk_label_new(NULL);
    
    gtk_tree_expander_set_child(GTK_TREE_EXPANDER(expander), label);

    gtk_list_item_set_child (listitem, expander);
}

static void bind_listitem (GtkListItemFactory *factory, GtkListItem *listitem)
{
    // получаем текущую строку
```

Рассмотрим основные моменты. Прежде всего определяем модель для древовидного списка:


Элементы модели также представляют строки, которые обернуты в список GtkStringList. По этому списку создана модель GtkTreeListModel. Но так как мы будем использовать виджет GtkListView, то нам нужна модель GtkSelectionModel, поэтому дополнительно обертываем модель GtkTreeListModel в GtkSingleSelection (модель одиночного выбора - подтип GtkSelectionModel).

Далее определяем фабрику GtkSignalListItemFactory и сигналы, которые будут генерировать виджеты для GtkListView:

```c
GtkListItemFactory *factory = gtk_signal_list_item_factory_new();

g_signal_connect (factory, "bind", G_CALLBACK (bind_listitem), NULL);
```

В обработчике сигнала `setup` создаем виджет GtkTreeExpander, который будет представлять отдельный элемент модели:

```c
static void setup_listitem (GtkListItemFactory *factory, GtkListItem *listitem)
```

В реальности для вывода данных (в нашем случае строк) GtkTreeExpander будет использовать виджет GtkLabel.

В обработчике сигнала `bind` создаем виджет GtkTreeExpander, который будет представлять отдельный элемент модели, и прикрепляем данные из строки модели - объекта GtkTreeListRow - к виджету GtkLabel:

В итоге мы получим древовидное представление с разворачиванием категорий.

Аналогичным образом можно было бы создавать деревья с более глубокой вложенностью. Например, пусть у нас будет следующая функция `create_func` для определения модели:

```c
GListModel* create_func (void* item, gpointer user_data){

    GtkStringObject* strobj = (GtkStringObject *)item;
    const char* parent = gtk_string_object_get_string(strobj);

    GtkStringList *child_list = gtk_string_list_new(NULL);

    // Добавляем дочерние элементы в зависимости от родителя
    if (g_str_equal(parent, "Категория 1")) {
        gtk_string_list_append(child_list, "Подкатегория 1.1");
        gtk_string_list_append(child_list, "Подкатегория 1.2");
    } 
    else if (g_str_equal(parent, "Категория 2")) {
        gtk_string_list_append(child_list, "Подкатегория 2.1");
        gtk_string_list_append(child_list, "Подкатегория 2.2");
        gtk_string_list_append(child_list, "Подкатегория 2.3");
    }
    else if (g_str_equal(parent, "Подкатегория 1.2")) {
        gtk_string_list_append(child_list, "Подподкатегория 1.2.1");
        gtk_string_list_append(child_list, "Подподкатегория 1.2.2");
        gtk_string_list_append(child_list, "Подподкатегория 1.2.3");
    }
    else return NULL;

    return G_LIST_MODEL(child_list);
}
```

Тогда вторая подкатегория первой категории также будет представлять разворачиваемый узел.

Естественно, вместо динамического наполнения дерева элементами можно использовать хранилища или базы данных, и соответственно в зависимости от характера источника данных будет различаться и логика наполнения моделей данными. Например, возьмем простейший источник данных - массивы указателей на символы:

```c
#include <gtk/gtk.h>

// Условные таблицы данных
const char* level1[] = {"Microsoft", "Google", NULL};
const char* level1_1[] = {"C#", "F#", "TypeScript", NULL};
const char* level1_2[] = {"Go", "Dart", NULL};
const char** level2[] = {level1_1, level1_2};

// Определяем функцию для создания дочерних элементов
GListModel* create_func (void* item, gpointer user_data){

    GtkStringObject* strobj = (GtkStringObject *)item;
    const char* parent = gtk_string_object_get_string(strobj);

    size_t level1_size = sizeof(level1)/sizeof(level1[0])-1;
    // ищем индекс категории
    for(size_t i = 0; i < level1_size; ++i){

        if(g_str_equal(parent, level1[i])){
            return G_LIST_MODEL(gtk_string_list_new(level2[i]));
        }
    }
    return NULL;
}
```
