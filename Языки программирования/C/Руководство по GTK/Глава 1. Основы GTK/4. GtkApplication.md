Для удобного создания и инициализации приложения во фреймворке GTK предназначен тип GtkApplication. В реальности для создания приложения GTK нам необязательно использовать этот тип, как было продемонстрировано в предыдущих статьях. Так, для создания окна приложения нам достаточно типа GtkWindow. Однако GtkApplication упрощает работу с приложением. В частности, этот тип обрабатывает инициализацию GTK, управляет сеансами, списком окон верхнего уровня и т.д.

## Создание

При использовании GtkApplication основная задача функции `main()` в коде программы как раз и состоит в создании и запуске объекта GtkApplication. Для создания и инициализации объекта GtkApplication применяется функция `gtk_application_new()`, которая выполняет роль конструктора:

```c
GtkApplication* gtk_application_new (const char* application_id, GApplicationFlags flags)
```

Первый параметр представляет идентификатор приложения (по сути его имя), в качестве которого обычно выступает строка. Второй параметр — флаги типа GApplicationFlags, которые управляют некоторыми возможностями приложения, например, как открывать файлы, указанные в командной строке, или как анализировать параметры командной строки.

Пример создания объекта GtkApplication:

```c
GtkApplication *app = gtk_application_new ("com.metanit", G_APPLICATION_DEFAULT_FLAGS);
```

В данном случае идентификатор приложения — `"com.metanit"`. Общий формат идентификаторов представляет "reverse-DNS", то есть имя домена наоборот.

В качестве же флага здесь передается флаг `G_APPLICATION_DEFAULT_FLAGS`. Это флаг для общих случаев, который покрывает большинство стандартных ситуаций.

## Запуск

После создания приложения в виде объекта GtkApplication его надо запустить, для этого применяется функция `g_application_run()`:

```c
int g_application_run (GApplication* application, int argc, char** argv)
```

Первый параметр представляет само запускаемое приложение, а второй и третий — параметры функции `main`. Результатом функции является статусный код возврата, который можно возвратить из функции `main` в качестве результата. Например:

```c
#include <gtk/gtk.h>

int main (int argc, char **argv)
{
    GtkApplication *app = gtk_application_new ("com.metanit", G_APPLICATION_DEFAULT_FLAGS);
    int status = g_application_run (G_APPLICATION (app), argc, argv);

    return status;
}
```

Поскольку функция `g_application_run()` принимает объект `GApplication*`, а наше приложение представляет объект `GtkApplication*`, то нам надо выполнить необходимые преобразования с помощью макроса `G_APPLICATION`.

## Удаление

Для полноценной работы с приложением в примере выше не хватает одной детали — освобождения памяти приложения. Для этого применяется функция `g_object_unref()`, которой передается объект приложения:

```c
#include <gtk/gtk.h>

int main (int argc, char **argv)
{
    // создание приложения
    GtkApplication *app = gtk_application_new ("com.metanit", G_APPLICATION_DEFAULT_FLAGS);
    // запуск приложения
    int status = g_application_run (G_APPLICATION (app), argc, argv);
    // освобождение памяти
    g_object_unref(app);

    return status;
}
```

Этот код уже представляет самодостаточное приложение GTK, которое мы можем скомпилировать и запустить:

```bash
gcc $(pkg-config --cflags gtk4) -o app app.c $(pkg-config --libs gtk4)
./app
```

Но при запуске мы видим предупреждение, что наше приложение никак не применяет функцию `g_application_activate()` и не имеет никаких обработчиков для сигнала `activate`. Теперь рассмотрим сигналы.

## Сигналы

Сигнал (событие) возникает, когда в системе что-то происходит. Например, создается окно, уничтожается окно и т. д. Так, выше упомянутый сигнал `activate` генерируется, когда происходит активация/запуск приложения. Если сигнал подключен к функции, которая называется обработчиком сигнала или просто обработчиком, то эта функция вызывается при генерации сигнала.

Для подключения сигналов к функциям-обработчикам применяется макрос `g_signal_connect`:

```c
#define g_signal_connect (
  instance,
  detailed_signal,
  c_handler,
  data
)
```

Макрос принимает 4 параметра:

- Объект, которому принадлежит сигнал.
- Имя сигнала.
- Функция обработчика, которую необходимо преобразовать с помощью макроса G_CALLBACK.
- Данные для передачи обработчику. Если данные не требуются, передается NULL.

Следует отметить, что функция-обработчик должна по сигнатуре соответствовать сигналу. Так, сигнал `activate` имеет следующую сигнатуру:

```c
void activate (GApplication* self, gpointer user_data)
```

Первый параметр — `self` — это объект, которому принадлежит сигнал. Второй параметр — `user_data` — это данные, определенные в четвертом аргументе функции `g_signal_connect`. Если он равен NULL, то можно проигнорировать и опустить второй параметр.

Итак, добавим для приложения обработку сигнала `activate`:

```c
#include <gtk/gtk.h>

static void app_activate (GApplication *app, gpointer *user_data) {
    g_print ("Hello METANIT.COM from GTK.\n");
}

int main (int argc, char **argv)
{
    // создание приложения
    GtkApplication *app = gtk_application_new ("com.metanit", G_APPLICATION_DEFAULT_FLAGS);
    // установка обработчика для сигнала activate приложения
    g_signal_connect (app, "activate", G_CALLBACK (app_activate), NULL);
    // запуск приложения
    int status = g_application_run (G_APPLICATION (app), argc, argv);
    // освобождение памяти
    g_object_unref(app);

    return status;
}
```

Рассмотрим, как выглядит здесь подключение и обработка сигнала. Сначала подключаем сигнал к функции-обработчику:

```c
g_signal_connect (app, "activate", G_CALLBACK (app_activate), NULL);
```

Первый аргумент функции — наше приложение. Второй аргумент — название сигнала `"activate"`. Третий аргумент — функция-обработчик. Название обработчика произвольное, но в нашем случае это `"app_activate"`. Четвертый параметр нам не нужен, поэтому передаем NULL.

Функция-обработчик `app_activate` соответствует определению сигнала `activate` (принимает те же параметры) и в данном случае просто выводит на консоль некоторую строку. Для вывода на консоль применяется встроенная функция `g_print()`:

```c
static void app_activate (GApplication *app, gpointer *user_data) {
    g_print ("Hello METANIT.COM from GTK.\n");
}
```

В итоге когда приложение будет запущено с помощью `g_application_run()`, будет отправлен сигнал `activate`, в результате чего сработает функция `app_activate`. Так, скомпилируем и запустим приложение:

```bash
gcc $(pkg-config --cflags gtk4) -o app app.c $(pkg-config --libs gtk4)
./app
Hello METANIT.COM from GTK.
```
