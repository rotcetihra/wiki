## 1. Введение

Если в арифметических операциях участвуют значения разных типов, компилятор **неявно** пытается привести их к одному типу. Кроме того, когда мы присваиваем переменной какое-либо значение, оно всегда приводится к типу переменной.

Преобразования не всегда безопасны: разные типы имеют разное внутреннее представление, и переход от одного представления к другому без потери точности данных возможен не всегда.

## 2. Неявные преобразования в арифметических операциях

```c
#include <stdio.h>

int main(void)
{
    int number1 = 10;
    double number2 = 4;
    double result = number1 + number2; // 14.000000
    printf("result = %f \n", result);  // result = 14.000000
    return 0;
}
```

В выражении `number1 + number2` один из операндов имеет тип `double`, поэтому число `number1` автоматически приводится к типу `double`. Результат операции сложения также имеет тип `double`.

Правила, которые применяет компилятор при арифметических операциях (обычные арифметические преобразования). Каждый следующий пункт применяется, только если предыдущий не выполняется:

|**Условие**|**Действие**|
|---|---|
|один из операндов имеет тип `long double`|второй операнд приводится к `long double`|
|один из операндов имеет тип `double`|второй операнд приводится к `double`|
|один из операндов имеет тип `float`|второй операнд приводится к `float`|
|один из операндов имеет тип `unsigned long long`|второй операнд приводится к `unsigned long long`|
|один из операндов имеет тип `long long`|второй операнд приводится к `long long`|
|один из операндов имеет тип `unsigned long`|второй операнд приводится к `unsigned long`|
|один из операндов имеет тип `long`|второй операнд приводится к `long`|
|один из операндов имеет тип `unsigned int`|второй операнд приводится к `unsigned int`|
|иначе|оба операнда приводятся к типу `int`|

> [!NOTE]
> Перед выполнением операции применяются целочисленные продвижения: значения типов `char`, `short` и их беззнаковые варианты преобразуются к `int` (или `unsigned int`). Поэтому в выражении `char + char` оба операнда приводятся к `int`, и результат имеет тип `int`.

## 3. Присваивание

Когда мы присваиваем переменной какое-либо значение, оно всегда приводится к типу переменной:

```c
char c = 6;
int d = c;
```

Переменной `d`, которая представляет тип `int`, присваивается значение типа `char`, поэтому компилятор выполняет приведение значения от типа `char` к типу `int`.

## 4. Явное преобразование (операция приведения)

С помощью специальной операции преобразования можно **явно** привести данные к нужному типу. Для этого в скобках перед выражением указывается целевой тип:

```
(тип) выражение
```

```c
int a = 10;
int b = 4;
int c = a / b;                    // 2
double d = a / b;                 // 2.0
double e = (double)a / (double)b; // 2.5

printf("c = %d \n", c);
printf("d = %f \n", d);
printf("e = %f \n", e);
```

В выражении `int c = a / b` результат деления целочисленный — 2, дробная часть отбрасывается, так как оба операнда представляют целые числа.

В выражении `double d = a / b` оба операнда тоже целые, поэтому результат деления — целое число 2, и только после выполнения деления происходит присвоение результата переменной `d` с приведением значения 2 от типа `int` к типу `double`. Поэтому `d` равно 2.0, а не 2.5.

В выражении `double e = (double)a / (double)b` применяется явное преобразование операндов к типу `double`, поэтому и результат деления — вещественное число 2.5.

> [!NOTE]
> Достаточно явно привести только один операнд: выражение `(double)a / b` дает тот же результат, поскольку второй операнд будет приведен к `double` неявно.

Пример приведения числа к символу:

```c
int number = 70;
char symbol = (char)number;
printf("symbol = %c \n", symbol);          // F
printf("symbol (int code) = %d \n", symbol); // 70
```

## 5. Безопасные и небезопасные преобразования

Без потери информации проходят следующие цепочки преобразований:

- `char` → `short` → `int` → `long` → `long long`;
- `unsigned char` → `unsigned short` → `unsigned int` → `unsigned long` → `unsigned long long`;
- `float` → `double` → `long double`.

Все остальные преобразования, которые не входят в эти цепочки, могут сопровождаться потерей точности данных. Так, преобразование от `int` к `char` не является безопасным:

```c
int number1 = 300;
char code = number1; // потеря точности: число усекается до 1 байта
printf("code = %d \n", code); // code = 44
```

Почему получается 44? Число 300 в двоичной системе — `0000000100101100`. При усечении до одного байта остается только младший байт `00101100`, что соответствует числу 44 в десятичной системе.

Аналогично усекается до двух байт число, не помещающееся в тип `short`:

```c
short number2 = 100000; // потеря точности: число усекается до 2 байт
printf("number2 = %d \n", number2); // number2 = -31072
```

> [!WARNING]
> К преобразованиям, не входящим в безопасные цепочки, следует относиться с осторожностью. Результат сужения значения, не помещающегося в целевой тип, по стандарту зависит от реализации (implementation-defined), поэтому полагаться на конкретное значение нельзя.

## 6. Резюме

1. При арифметических операциях с операндами разных типов компилятор неявно приводит их к одному типу по правилам обычных арифметических преобразований; перед операциями выполняются целочисленные продвижения.
2. При присваивании значение всегда приводится к типу переменной-приемника.
3. Явное преобразование выполняется операцией приведения: `(тип) выражение`.
4. Безопасные цепочки преобразований: `char → short → int → long`, `unsigned char → ... → unsigned long`, `float → double → long double`.
5. Прочие преобразования могут терять точность, а их результат зависит от реализации.
