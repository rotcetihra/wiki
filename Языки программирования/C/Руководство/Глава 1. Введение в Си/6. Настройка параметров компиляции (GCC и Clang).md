## 1. Введение

Флаги (опции) компилятора позволяют управлять процессом сборки программы на Си: изменять уровень оптимизации, регулировать строгий контроль ошибок, выбирать версию стандарта языка и генерировать промежуточные файлы (ассемблерный код или препроцессированный текст).

Разработчики компилятора **Clang** сделали его интерфейс командной строки максимально совместимым с **GCC**. Поэтому подавляющее большинство флагов компиляции для обоих инструментов совпадает.

## 2. Предупреждения и строгий контроль кода (Warnings)

По умолчанию компиляторы GCC и Clang выводят минимальное количество ошибок (только синтаксические и фатальные). Добавление флагов предупреждений позволяет выявить потенциальные баги (например, неиспользуемые переменные, выход за пределы массива, некорректные типы) до запуска программы.

|**Флаг**|**Описание**|
|---|---|
|**`-Wall`**|Включает базовый и самый необходимый набор предупреждений компилятора.|
|**`-Wextra`**|Активирует дополнительные предупреждения, не входящие в `-Wall` (например, о неиспользуемых параметрах функций).|
|**`-Werror`**|Превращает все предупреждения в ошибки (компиляция прервется при наличии любого предупреждения).|
|**`-pedantic`**|Выводит предупреждения при строгом несоблюдении выбранного стандарта ISO C.|
|**`-pedantic-errors`**|Превращает предупреждения несоответствия стандарту в фатальные ошибки компиляции.|

### Пример компиляции со строгой проверкой

```Bash
gcc -Wall -Wextra -pedantic app.c -o app
```

или для Clang:

```Bash
clang -Wall -Wextra -pedantic app.c -o app
```

## 3. Выбор стандарта языка C

Язык C постоянно развивается. Флаг `-std=` указывает компилятору, синтаксис и возможности какого стандарта языка необходимо использовать при сборке.

- **`-std=c99`** — Стандарт C99 (объявления переменных в произвольном месте, однострочные комментарии `//`, тип `bool`).
    
- **`-std=c11`** — Стандарт C11 (поддержка потоков `<threads.h>`, анонимных структур и `_Generic`).
    
- **`-std=c17`** — Стандарт C17 (исправление недоработок C11, стабильный индустриальный стандарт).
    
- **`-std=c23`** — Современный стандарт C23 (добавление ключевых слов `true`/`false`, `nullptr`, `auto`, атрибутов и `constexpr`).
    
- **`-std=gnu17` / `-std=gnu23`** — Использует стандарт с расширениями GNU (включается по умолчанию, если параметр `-std=` не указан).
    

### Пример с указанием стандарта и строгого контроля

```Bash
gcc -std=c23 -Wall -Wextra -pedantic source.c -o source.exe
```

## 4. Оптимизация и промежуточные файлы

### Генерация ассемблерного кода (`-S`)

Флаг **`-S`** останавливает процесс компиляции на этапе генерации ассемблерного кода и сохраняет его в файл с расширением `.s`.

```Bash
gcc -S app.c
```

- В результате будет создан файл `app.s`, содержащий код на ассемблере с синтаксисом **GAS** (GNU Assembler).
    

### Препроцессинг (`-E`)

Флаг **`-E`** выполняет только этап работы препроцессора (раскрывает директивы `#include`, макросы `#define` и подставляет условия `#ifdef`).

```Bash
gcc -E app.c -o app.i
```

### Уровни оптимизации (`-O`)

Оптимизация ускоряет выполнение программы и уменьшает размер исполняемого файла:

- **`-O0`** — Без оптимизации (по умолчанию, рекомендуется для отладки).
    
- **`-O1` / `-O2`** — Базовая и стандартная оптимизация (баланс скорости сборки и работы).
    
- **`-O3`** — Максимальная агрессивная оптимизация скорости.
    
- **`-Os`** — Оптимизация по размеру итогового исполняемого файла.
    

## 5. Отладка и санитайзеры

Чтобы отлаживать программу с помощью отладчика (**GDB** или **LLDB**), необходимо передать отладочные символы:

```Bash
gcc -g -O0 app.c -o app
```

### Использование санитайзеров (AddressSanitizer)

И GCC, и Clang поддерживают встроенные инструменты для поиска утечек памяти и выходов за границы массивов в рантайме:

```Bash
gcc -fsanitize=address -g app.c -o app
```

## 6. Именование и автоматический запуск

По умолчанию компилятор создает файл `a.out` (в Linux/macOS) или `a.exe` (в Windows). Флаг **`-o`** задает имя выходящего файла.

### Автоматический запуск после успешной компиляции

Для экономии времени компиляцию и запуск скомпилированной программы связывают в одну команду с помощью оператора `&&` (запуск выполняется только при успешной сборке):

- **В Linux / macOS / Windows CMD:**
    
    ```DOS
    gcc -std=c17 -Wall -pedantic app.c -o app.exe && app.exe
    ```
    
- **В PowerShell:**
    
    ```PowerShell
    gcc -std=c17 -Wall -pedantic app.c -o app.exe; if ($?) { .\app.exe }
    ```
    

## 7. Рекомендуемые конфигурации сборки

### Для разработки и учебы (Development Build)

Максимальный контроль за ошибками, отладка и поддержка современного стандарта:

```Bash
gcc -std=c23 -Wall -Wextra -pedantic -g -O0 main.c -o main
```

### Для релизной сборки (Release Build)

Максимальная производительность программы с отключением отладочной информации:

```Bash
gcc -std=c23 -O2 -Wall main.c -o main_release
```
