## 1. Введение

Ранее мы рассмотрели, что строка по сути является набором символов, окончанием которого служит нулевой символ `'\0'`. Фактически строку можно представить в виде массива:

```c
char hello[] = "Hello";
```

В данном случае из символов строки формируется массив из 6 символов. То есть фактически мы могли бы написать:

```c
char hello[] = {'H', 'e', 'l', 'l', 'o', '\0'};
```

Обратите внимание: в строке 5 символов, но массив содержит 6. Так как строковые литералы завершаются по умолчанию нулевым байтом, последний символ в массиве будет представлять нулевой байт, а сам массив будет содержать 6 символов.

## 2. Длина массива и строка

В примере выше длина массива устанавливалась автоматически на основании присваиваемого значения. Если для массива явным образом определена длина, то все немного сложнее. Можно присвоить такому массиву строку, в которой символов меньше или больше, чем ожидает массив. Рассмотрим разные варианты.

Если массиву передается то количество символов, которое имеет строка:

```c
char abc[4] = "abc";
```

Массив имеет длину в 4 символа, и ему присваивается строка с 4 символами (включая завершающий нулевой байт). Фактически мы получим:

```c
char abc[4] = {'a', 'b', 'c', '\0'};
```

Если длина массива соответствует длине строки без учета нулевого байта:

```c
char abc[3] = "abc";
```

Массив имеет длину в 3 символа, в этом случае завершающий нулевой байт **не** добавляется в массив. Фактически мы получим:

```c
char abc[3] = {'a', 'b', 'c'};
```

Если размер массива больше размера строки, то оставшееся место в массиве заполняется нулевыми байтами:

```c
char abc[5] = "abc";
// эквивалентно
char abc[5] = {'a', 'b', 'c', '\0', '\0'};
```

Если же массиву присваивается строка, в которой больше символов, чем длина массива (без учета завершающего нулевого байта), тогда многое зависит от реализации. Например:

```c
char abc[2] = "abc";
```

Компилятор GCC успешно скомпилирует данный пример и определит массив с двумя первыми символами из строки `"abc"`, но при этом выведет предупреждение. Другие компиляторы могут посчитать это ошибкой.

> [!NOTE]
> В более строгом виде это нарушение ограничений стандарта: строка не помещается в массив. Полагаться на поведение конкретного компилятора не стоит — такой код следует избегать.

## 3. Указатель на char

В языке Си для представления строк также можно использовать указатели на тип `char`:

```c
#include <stdio.h>

int main(void)
{
    char *hello = "Hello METANIT.COM!"; // указатель на char - фактически строка
    printf("%s", hello);
    return 0;
}
```

С точки зрения обращения к строке оба определения — с помощью массива и с помощью указателя — равнозначны. Тем не менее здесь есть различие. Для понимания этого различия сначала рассмотрим такой процесс, как интернирование строк.

## 4. Интернирование строк

В языке Си для работы со строками применяется механизм **интернирования строк** (string interning). В этом случае строковые литералы сохраняются в приложении в секции `.rodata` (read-only data), предназначенной для данных только для чтения, а строковые литералы рассматриваются как неизменяемые данные. Например, возьмем следующую программу:

```c
#include <stdio.h>

char *str1 = "Hello";
char *str2 = "World";

int main(void)
{
    printf("str1 = %p \n", (void *)&str1[0]);
    printf("str2 = %p \n", (void *)&str2[0]);

    return 0;
}
```

Здесь определены две строки — `str1` и `str2`, в функции `main` выводится адрес первого символа каждой из этих строк. Возможный вывод:

```
str1 = 00007FF75E674000
str2 = 00007FF75E674006
```

По выводу видно, что первый символ второй строки расположен через 6 байт от начала первой строки. То есть строки расположены в памяти рядом друг с другом.

Но теперь сделаем строки одинаковыми:

```c
#include <stdio.h>

char *str1 = "Hello World";
char *str2 = "Hello World";

int main(void)
{
    printf("str1 = %p \n", (void *)&str1[0]);
    printf("str2 = %p \n", (void *)&str2[0]);

    return 0;
}
```

Теперь вывод будет другим:

```
str1 = 00007FF75F674000
str2 = 00007FF75F674000
```

Оба адреса одинаковые, потому что обе переменные в реальности указывают на одну и ту же строку. Интернирование строк позволяет избежать дублирования строк и более эффективно использовать память. Причем здесь не важно, что переменные являются глобальными: они могут быть и локальными, но все равно будут указывать на один и тот же адрес в `.rodata`:

```c
#include <stdio.h>

int main(void)
{
    char *str1 = "Hello World";
    char *str2 = "Hello World";
    printf("str1 = %p \n", (void *)&str1[0]);
    printf("str2 = %p \n", (void *)&str2[0]);

    return 0;
}
```

Стоит отметить, что адрес, по которому располагается строка, можно получить и сразу:

```c
#include <stdio.h>

int main(void)
{
    char *str1 = "Hello World";
    char (*str2)[] = &"Hello World";
    printf("str1 = %p \n", (void *)&str1[0]);
    printf("str2 = %p \n", (void *)str2);

    return 0;
}
```

В данном случае `str2` представляет указатель на массив символов и хранит адрес строки `"Hello World"`. В итоге значения `&str1[0]` и `str2` совпадут.

> [!NOTE]
> Объединение одинаковых строковых литералов — не гарантия стандарта, а оптимизация компиляторов (обычно включенная по умолчанию). Разные компиляторы и их версии могут вести себя по-разному, поэтому полагаться на равенство адресов одинаковых литералов нельзя.

## 5. Изменение строк

Сохранение строки по указателю в секцию `.rodata` означает, что мы не сможем изменить эту строку:

```c
#include <stdio.h>

int main(void)
{
    char *text = "Hello";
    text[1] = 'a';
    printf("New text: %s\n", text);
    return 0;
}
```

Здесь мы пытаемся изменить второй символ (символ по индексу 1) на `'a'`. При попытке запуска программы мы получим ошибку. В случае с GCC это segmentation fault.

То же самое касается изменения строки через синтаксис указателей:

```c
char *text = "Hello";
*text = 'a';  // ошибка
```

> [!WARNING]
> Изменение строкового литерала — неопределенное поведение: литерал хранится в памяти только для чтения, и попытка записи приводит к аварийному завершению программы.

Теперь вместо указателя используем массив:

```c
#include <stdio.h>

int main(void)
{
    char text[] = "Hello";
    text[1] = 'a';
    *text = 'B';
    *(text + 2) = 'b';
    printf("%s\n", text); // Bablo
    return 0;
}
```

Теперь все нормально выполнится, а на консоль будет выведена строка `"Bablo"`. Причем для изменения, как видно из примера, можно применять как синтаксис массивов, так и синтаксис указателей: в этом случае массив инициализируется копией литерала в изменяемой памяти.

## 6. Пустая строка и NULL

Указателю на символы можно присваивать значение `NULL`, как и другим указателям:

```c
char *text = NULL;
if (!text) puts("text is null");
```

Однако этот случай надо отличать от пустой строки: пустая строка имеет один символ — нулевой байт:

```c
char *text1 = NULL;      // строка не инициализирована
char *text2 = "\0";      // пустая строка
char text3[5];           // строка формально неинициализирована, но содержит мусор
char text4[5] = {'\0'};  // пустая строка
```

`text1` не ссылается ни на какую строку, `text2` и `text4` — пустые строки, а `text3` содержит неопределенный «мусор» и не является корректной строкой.

> [!WARNING]
> Вызов `printf("%s", text1)` при `text1 == NULL` приведет к аварийному завершению — в отличие от пустых строк `"\0"`, которые выводятся без ошибок.

## 7. Резюме

1. Строка — массив символов, завершающийся `'\0'`; массив может быть больше строки (лишнее место заполняется нулями) или точно под размер (без завершающего нуля — тогда это уже не корректная строка).
2. Строка может храниться по указателю `char *`, что равнозначно массиву с точки зрения обращения.
3. Строковые литералы хранятся в секции только для чтения (интернирование) — изменять их нельзя; массив `char text[]` хранит копию литерала и доступен для изменения.
4. `NULL` — не пустая строка, а указатель на отсутствующие данные; выводить его через `%s` нельзя.
