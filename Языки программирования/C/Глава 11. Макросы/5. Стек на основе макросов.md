## 1. Введение

Рассмотрим, как с помощью макросов реализовать стек — структуру данных, работающую по принципу LIFO (последним пришел — первым вышел). В этой реализации стек строится на массиве и указателе, а операции над ним описываются через макросы:

```c
#define SIZE 8  // размер стека

int stack[SIZE];

int* sp = &stack[-1];  // указатель на верхушку стека (на позицию перед стеком)

#define STACK_FULL()  (((sp-stack) + 1) >= SIZE)    // полный стек
#define STACK_EMPTY()  (((sp-stack) + 1) == 0)    // пустой стек

#define STACK_USED() ((sp-stack) + 1)  // сколько мест в стеке использовано
#define CLEAR_STACK (sp = stack - 1)    // сбрасываем стек
#define PUSH(n) (*++sp = (n))   // добавляем в стек
#define POP() (*sp--)       // получаем значение из стека


int main(void)
{
    // добавляем в стек числа от 10 и далее, пока стек не заполнится
    int i = 10;
    while (!STACK_FULL())
    {
        PUSH(i);
        i++;
    }
    // выводим содержимое стека
    for (size_t i = 0; i < SIZE; ++i)
    {
        printf("stack[%lu]: %d\n", i, stack[i]);
    }
    // извлекаем данные из стека
    while (!STACK_EMPTY())
    {
        printf("%d\n", POP());
    }

    return 0;
}
```

## 2. Основные компоненты

Сначала идет описание основных компонентов:

```c
#define SIZE 8
int stack[SIZE];
int* sp = &stack[-1];
```

Константа `SIZE` задает максимальный размер стека (до 8 элементов).

`stack` — массив, который хранит элементы стека.

`sp` — указатель на текущую вершину стека. Изначально он указывает на позицию перед началом массива, то есть стек пуст.

## 3. Макросы для работы со стеком

Далее определяются макросы для работы со стеком:

- `STACK_FULL()` — проверяет, заполнен ли стек;
- `STACK_EMPTY()` — проверяет, пуст ли стек;
- `STACK_USED()` — возвращает количество элементов в стеке;
- `CLEAR_STACK` — очищает стек (сбрасывает `sp` в начальное состояние);
- `PUSH(n)` — добавляет элемент в стек;
- `POP()` — извлекает элемент из вершины стека.

Проверка заполненности и пустоты построена на разности указателей: выражение `sp - stack` показывает, на сколько позиций указатель `sp` удален от начала массива; добавляя единицу, получаем количество занятых элементов. Если оно достигло `SIZE`, стек полон, если равно нулю — пуст.

Добавление элемента `PUSH(n)` увеличивает указатель `sp` и записывает значение по новому адресу: `*++sp = (n)`. Извлечение `POP()` возвращает значение по текущей вершине и сдвигает указатель назад: `*sp--`.

## 4. Логика функции main

Основная логика функции `main` разбивается на три части.

Заполнение стека:

```c
int i = 10;
while (!STACK_FULL())
{
    PUSH(i);
    i++;
}
```

В цикл добавляются числа, начиная с 10, до тех пор, пока стек не заполнится (максимум 8 элементов).

Вывод содержимого стека (внутри массива):

```c
for (size_t i = 0; i < SIZE; ++i)
{
    printf("stack[%lu]: %d\n", i, stack[i]);
}
```

Это просто просмотр содержимого массива `stack` — он уже содержит 8 элементов.

Извлечение из стека:

```c
while (!STACK_EMPTY())
{
    printf("%d\n", POP());
}
```

Здесь идет последовательное извлечение и печать значений из стека — происходит в обратном порядке по сравнению с тем, как они были добавлены.

## 6. Примечание о манипуляциях с указателями

Таким образом, мы можем определить стек через указатели и макросы без использования структур или динамической памяти. Этот подход полезен для понимания работы с памятью на низком уровне и принципов работы стека.

> [!WARNING]
> Манипуляции с указателями вне границ массива, как `&stack[-1]`, потенциально опасны и формально являются неопределенным поведением по стандарту C. Такой код допустим только при особом контроле, как в этом случае, и полагаться на него в переносимых программах не стоит.

## 7. Резюме

1. Стек реализуется массивом `stack` и указателем вершины `sp` без структур и динамической памяти.
2. Макросы `PUSH`/`POP` выполняют добавление и извлечение элементов, `STACK_FULL`/`STACK_EMPTY` — проверки состояния стека.
3. Извлечение данных из стека происходит в обратном порядке их добавления (принцип LIFO).
4. Адресация перед началом массива (`&stack[-1]`) небезопасна и допустима лишь при строгом контроле.
