## Определение

```c
#include <assert.h>

#define assert(expr)      // реализация
#define assert(expr, msg) // в C23
```

## Описание

Макрос — утверждение: проверяет выражение во время выполнения. Если выражение ложно, макрос выводит диагностическое сообщение (файл, строка, выражение и необязательное сообщение в C23) в поток ошибок и вызывает `abort()`. Если до включения `<assert.h>` определено `NDEBUG`, макрос разворачивается в пустоту, и проверка исчезает полностью (включая побочные эффекты выражения!).

Утверждения — инструмент отладки и документирования инвариантов: предусловий функций, границ индексов, невозможных веток. Для обработки ожидаемых ошибок их использовать нельзя — для этого нужны `errno`, коды возврата или другие механизмы.

> [!WARNING]
> `assert(expr)` с побочными эффектами при компиляции с `-DNDEBUG` перестанет выполняться — код с `assert(i++)` сломается без проверки. Побочные эффекты следует выносить из утверждений.

## Примеры

```c
#include <assert.h>
#include <stdio.h>

int divide(int a, int b)
{
    assert(b != 0); // предусловие
    return a / b;
}

int main(void)
{
    divide(10, 2);

    // divide(10, 0); // завершит программу с сообщением

    return 0;
}
```

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Быстрая локализация ошибок программиста | Исчезает при `-DNDEBUG` — не годится для проверки в продакшене |
| Наглядно документирует инварианты кода | Выражение с побочными эффектами «ломает» код |

## Альтернативы

- **`static_assert`** — проверка на этапе компиляции
- `errno` и коды возврата — для ожидаемых ошибок
