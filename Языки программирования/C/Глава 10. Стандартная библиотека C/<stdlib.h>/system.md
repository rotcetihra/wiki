## Прототип

```c
#include <stdlib.h>

int system(const char *command);
```

## Параметры

| Параметр | Описание |
|---|---|
| `command` | Командная строка для выполнения (или `NULL` для проверки доступности командного интерпретатора) |

## Возвращаемое значение

- `NULL`-аргумент: ненулевое значение, если командный интерпретатор доступен;
- при выполнении команды: статус завершения интерпретатора (в POSIX — через `wait()`; значение закодировано как код возврата `main` в младших 8 битах) или `-1` при ошибке запуска.

## Что делает

Передаёт строку `command` командному интерпретатору хоста для выполнения (в POSIX-системах — `/bin/sh -c command`). Программа приостанавливается до завершения команды. `system(NULL)` возвращает информацию о доступности интерпретатора. Потокобезопасность не гарантируется.

>[!WARNING]
>Не передавайте пользовательский ввод в `system()` без экранирования — это классическая уязвимость внедрения команды. Если можно, используйте `exec*()`-функции POSIX, `posix_spawn()` или API без shell.

## Примеры

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    if (system(NULL) == 0) {
        printf("Командный интерпретатор недоступен\n");
        return 1;
    }

    int status = system("echo hello from shell");
    printf("Статус: %d\n", status);

    return 0;
}
```

## Ошибки и errno

При неудаче запуска интерпретатора возвращает `-1` (и может установить `errno` — детали зависят от платформы).

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Простой способ запустить внешнюю команду | Зависит от интерпретатора хоста — непереносимо |
| Не нужно управлять процессами и потоками | Риск внедрения команд при пользовательском вводе |

## Альтернативы

- **`exec*()` / `posix_spawn()`** — запуск процессов без shell (POSIX)
- `popen()` — выполнение и чтение вывода команды (POSIX)
