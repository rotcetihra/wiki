## Прототип

```c
#include <stdlib.h> // POSIX XSI

int grantpt(int fd);
```

## Параметры

| Параметр | Описание |
|---|---|
| `fd` | Дескриптор master-устройства псевдо-терминала (от `posix_openpt()`) |

## Возвращаемое значение

0 при успехе, -1 при ошибке.

## Что делает

Устанавливает владельца и права доступа на slave-устройство псевдо-терминала: владелец — реальный UID вызывающего процесса, права — режим, определённый реализацией (на Linux — только для чтения обеими сторонами, с последующей дальнейшей настройкой через `unlockpt()`). В современных glibc на Linux функция практически не выполняет работы — права выставляются ядром при открытии. Нужна после `posix_openpt()` перед открытием slave-устройства.

## Примеры

```c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int master = posix_openpt(O_RDWR | O_NOCTTY);
    if (master < 0) {
        return 1;
    }

    if (grantpt(master) != 0 || unlockpt(master) != 0) {
        return 1;
    }

    const char *slave = ptsname(master);
    printf("%s\n", slave ? slave : "(нет имени)");

    close(master);
    return 0;
}
```

## Ошибки и errno

При неудаче возвращает -1 и устанавливает `errno` (`EINVAL` — `fd` не master-устройство, `EBADF`/`ENOTTY` — не псевдо-терминал).

## Плюсы и минусы

| Преимущество | Недостаток |
|---|---|
| Переносимый доступ к slave-устройству | На классических системах может требовать привилегий |
| Обязательный шаг POSIX-протокола | На современных ядрах Linux — формальная операция |

## Альтернативы

- **Открыть slave-устройство напрямую** — после того как ядро само выставило права (Linux) — не переносимо
- `ioctl()` с `TIOCSPTLCK` — низкоуровневый способ в Linux
