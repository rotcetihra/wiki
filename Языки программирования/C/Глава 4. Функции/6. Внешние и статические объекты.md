## 1. Введение

Переменные, используемые в программе, могут быть не только глобальными, локальными или статическими, но также могут представлять **внешние объекты**: такие объекты определены в каком-то внешнем файле. Кроме того, функции также могут быть внешними по отношению к другим функциям, то есть могут быть определены в других файлах. В этом случае встает вопрос организации взаимодействия между ними. Рассмотрим пример такого взаимодействия.

Пусть в программе будет два файла: главный файл `app.c` и вспомогательный файл `main.c`.

## 2. Внешние объекты

Пусть файл `main.c` будет содержать следующий код:

```c
#include <stdio.h>

char message[] = "Hello METANIT.COM";

void print()
{
    printf("Hello from extern function\n");
}

int sum(int x, int y)
{
    return x + y;
}
```

Здесь определена одна переменная — `message` — и две функции — `print()` и `sum()`.

Используем этот функционал в файле `app.c`, который будет представлять главный файл программы:

```c
#include <stdio.h>

extern char message[];      // переменная message из файла main.c
void print(void);           // функция print из main.c
int sum(int, int);          // функция sum из main.c

int main(void)
{
    // выводим на консоль внешнюю переменную message
    printf("%s \n", message);
    // вызываем внешнюю функцию print
    print();
    // вызываем другую внешнюю функцию - sum
    printf("4 + 5 = %d \n", sum(5, 4));
    return 0;
}
```

Если переменная определена во внешнем файле, то перед ее использованием должно идти ее **описание** с ключевым словом `extern`. В частности, в файле `main.c` определена переменная `message`. Чтобы к ней обращаться, в файл `app.c` надо поместить ее описание с ключевым словом `extern`:

```c
extern char message[];
```

Описание переменной в принципе совпадает с ее определением, только при описании ей нельзя присваивать какое-либо значение.

Если мы хотим использовать внешние функции, то перед их использованием надо определить их прототип. Так, в файле `main.c` определены функции `print()` и `sum()`, поэтому в файле `app.c` перед вызовом этих функций помещается их прототип:

```c
void print(void);           // функция print из main.c
int sum(int, int);          // функция sum из main.c
```

То же самое касается использования любых других переменных и функций, которые определены во внешних файлах.

> [!NOTE]
> На практике описания внешних объектов (прототипы функций и объявления `extern` для переменных) выносят в заголовочные файлы с расширением `.h`, которые затем подключаются через `#include`. Это избавляет от дублирования описаний в каждом файле.

## 3. Компиляция нескольких файлов

При компиляции через GCC компилятору надо последовательно через пробел передать имена файлов:

```
gcc app.c main.c -o app.exe
```

Здесь файлы `app.c` и `main.c` будут компилироваться в один файл `app.exe`.

В некоторых средах разработки (например, в Visual Studio) среда автоматически скомпилирует оба файла в одну программу.

## 4. Статические объекты

По умолчанию любая глобальная переменная, константа или функция из одного файла доступна в другом файле при совместной компиляции, как в примере выше. Однако иногда возникает необходимость, наоборот, скрыть переменную или функцию, чтобы внешние файлы не могли их использовать. В этом случае к подобным переменным и функциям можно применить оператор `static`, сделав их статическими. Например, определим следующий файл `main.c`:

```c
#include <stdio.h>

static char message[] = "Hello METANIT.COM";

static void print()
{
    printf("%s\n", message);
}

void hello()
{
    print();
}
```

Теперь ни переменная `message`, ни функция `print()` не доступны из внешних файлов, потому что они определены как статические. А вот функция `hello()` доступна, и только ее мы можем использовать в других файлах, например, в файле `app.c`:

```c
#include <stdio.h>

// extern char message[];   - переменная message из файла main.c недоступна
// void print(void);        - функция print из main.c недоступна
void hello(void);           // функция hello из main.c доступна

int main(void)
{
    // вызываем внешнюю функцию - hello
    hello();
    return 0;
}
```

> [!NOTE]
> Ключевое слово `static` на уровне файла меняет связывание объекта: переменная или функция получает внутреннее связывание (internal linkage) и видна только в пределах своего файла. Это отличается от локальных статических переменных из прошлой темы — там `static` менял время жизни.

## 5. Резюме

1. Внешние объекты определены в других файлах; для их использования нужны описания: `extern` для переменных, прототипы для функций.
2. Описание совпадает с определением, но без присваивания значения.
3. При компиляции нескольких файлов GCC перечисляет их через пробел: `gcc app.c main.c -o app`.
4. `static` на уровне файла скрывает объект от других файлов — он становится видимым только внутри своего файла.
