## Описание

Нередко возникает необходимость в получении большого набора данных или сложных по структуре данных фиксированной длины, которые могут изменяться в процессе работы программы.

С одной стороны, мы могли бы определить данные в статической памяти и возвращать указатель на них. Но в этом случае потребитель данных может столкнуться с **несогласованностью данных**: он получает одни данные и опирается на них, а тем временем данные где-то извне изменяются. Что особенно характерно для многопоточных систем.

Возвратить данные напрямую из функции в виде структуры тоже не всегда лучший вариант — структура копируется в стек, а стек ограничен, поэтому для больших данных этот способ не подходит.

## Решение: буфер на стороне приёмника

В качестве решения определяется **буфер** для получения данных на стороне компонента-приёмника данных. Компонент-источник данных определяет функцию, которая принимает данный буфер и копирует в него данные.

### Источник данных

```c
#define DATA_SIZE 256

static char data[DATA_SIZE];

void getData(char *buffer)
{
    memcpy(buffer, data, DATA_SIZE);
}
```

### Приёмник данных

```c
static char buffer[DATA_SIZE];

getData(buffer);
```

Код обоих компонентов копирует набор данных, размер которого заранее известен, и для обоих компонентов он совпадает, поэтому не существует проблемы, что будет скопировано меньше или больше байтов.

> [!NOTE]
> Похожий паттерн применяется, в частности, в библиотечной функции `fgets`, в которую передаётся буфер для считывания данных из файла.

## Пример: набор данных пользователей

### Определение структуры (user.h)

```c
struct User {
    char *name;
    unsigned age;
};

#define DATA_COUNT 5
```

### Источник данных (user.c)

```c
#include <stdio.h>
#include <string.h>
#include "user.h"

static struct User data[DATA_COUNT] = {
    {"Tom", 39}, {"Bob", 43}, {"Sam", 29},
    {"Alice", 35}, {"Kate", 28}
};

void getUsers(struct User *buffer)
{
    memcpy(buffer, data, DATA_COUNT * sizeof(struct User));
}
```

Функция `getUsers` получает в качестве параметра буфер, в который копируются данные. Поскольку данные фиксированного размера, ожидается, что буфер будет той же длины, что и массив с данными.

### Потребитель данных (app.c)

```c
#include <stdio.h>
#include "user.h"

extern void getUsers(struct User*);

int main(void)
{
    struct User buffer[DATA_COUNT];

    getUsers(buffer);

    for (int i = 0; i < DATA_COUNT; i++)
    {
        printf("%s - %u\n", buffer[i].name, buffer[i].age);
    }
}
```

Вызываем функцию `getUsers` из файла `user.c` и передаём в неё буфер. В данном случае буфер определён как автоматическая переменная в стеке, но он может быть определён и в статической, и в динамической памяти.

### Вывод программы

```
Tom - 39
Bob - 43
Sam - 29
Alice - 35
Kate - 28
```

## Преимущества и недостатки

| Преимущества | Недостатки |
|---|---|
| Быстрое получение больших данных | Приёмнику необходимо знать размер данных |
| Один параметр функции | Буфер должен быть заранее выделен |
| Безопасность в многопоточности (каждый поток — свой буфер) | Фиксированный размер не гибок |
| Нет копирования в стек вызывающей функции | Не подходит для данных переменной длины |

> [!NOTE]
> Компонент-приёмник может быстро и с помощью одного параметра получить большие и сложные по структуре данные. Приёмнику данных достаточно предоставить буфер нужной длины. Если к данным обращаются несколько потоков, каждый предоставляет свой собственный буфер, поэтому данный подход безопасен в многопоточных программах.
