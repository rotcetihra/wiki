## Описание

Иногда необходимо предоставить доступ к данным извне таким образом, чтобы они не могли быть изменены и были доступны только для чтения.

## Стандартное решение

Стандартным решением будет определение данных в **статической памяти**. Данные могут определяться как на этапе компиляции, так и на этапе запуска приложения, и после этого не изменяются. А для доступа к данным определяется функция, которая возвращает указатель на эти данные. Причём возвращается указатель на **константу**, чтобы данные не могли быть изменены извне.

На стороне источника данных:

```c
struct Immutable
{
    int x;
    int y;
};

static struct Immutable data = {11, 22};

const struct Immutable* getData(void)
{
    return &data;
}
```

На стороне приёмника данных:

```c
const struct Immutable *immut_data;
immut_data = getData();
```

Подобный паттерн иногда называют **Immutable Object** или **Immutable Instance**.

## Пример: пользовательские данные

### Определение структуры (user.h)

```c
struct User {
    char *name;
    unsigned age;
    char *email;
};
```

### Источник данных (user.c)

```c
#include "user.h"

static struct User data = {"Tom", 39, "tom@smail.ru"};

const struct User* getUser(void)
{
    return &data;
}
```

Данные представляют объект `data`, который размещён в статической памяти. Он определён с помощью ключевого слова `static`, поэтому напрямую извне файла `user.c` не виден. Для доступа к этому объекту определена функция `getUser`, которая возвращает указатель на константу.

### Потребитель данных (app.c)

```c
#include <stdio.h>
#include "user.h"

extern const struct User* getUser(void);

int main(void)
{
    const struct User *user;
    user = getUser();

    printf("name=%s\n", user->name);
    printf("email=%s\n", user->email);
    printf("age=%d\n", user->age);
}
```

Вызываем функцию `getUser` из файла `user.c` и получаем данные в указатель на константу.

### Компиляция и запуск

```
gcc -Wall -pedantic app.c user.c -o app
./app
name=Tom
email=tom@smail.ru
age=39
```

## Преимущества

- Компонент-потребитель данных не должен заботиться об управлении памятью — данные определены в статической памяти.
- Подход может успешно использоваться в **многопоточных приложениях**: потоки не изменяют данные, а только читают, и для всех обращающихся потоков данные остаются теми же.

## Недостатки

### Относительная неизменяемость

Если код в файле `app.c` получит указатель на неконстантный объект:

```c
struct User *user = getUser();
user->name = "Bob";
```

При компиляции компиляторы могут выдать предупреждение, но код скомпилируется и отработает, а значения по полученному указателю изменятся. Кроме того, данные могут измениться на стороне компонента `user.c`. Таким образом, мы имеем дело с **относительной неизменяемостью** данных.

### Инкапсуляция в функции

Можно пойти дальше в сторону инкапсуляции и определить объект в самой возвращающей его функции:

```c
#include <stdio.h>
#include "user.h"

const struct User* getUser(void)
{
    static struct User data = {"Tom", 39, "tom@smail.ru"};
    return &data;
}

void printUser(void)
{
    const struct User *user;
    user = getUser();
    printf("name=%s\n", user->name);
    printf("email=%s\n", user->email);
    printf("age=%d\n", user->age);
}
```

Внутри `user.c` для получения объекта также вызываем функцию `getUser` и получаем указатель на константу.

## Сводка

| Аспект | Описание |
|---|---|
| Размещение данных | Статическая память |
| Доступ | Функция, возвращающая `const`-указатель |
| Неизменяемость | Относительная (зависит от дисциплины потребителя) |
| Многопоточность | Безопасна для чтения |
| Управление памятью | Не требуется (автоматическое) |

> [!WARNING]
> Ключевое слово `const` в возвращаемом типе — это **совет компилятору**, а не жёсткое ограничение. Потребитель может привести указатель к неконстантному типу и изменить данные. Для строгой неизменяемости требуются дополнительные механизмы (отдельный процесс, шифрование памяти и т. д.).
