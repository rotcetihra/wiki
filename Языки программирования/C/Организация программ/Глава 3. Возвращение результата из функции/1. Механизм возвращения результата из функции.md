## Описание

Функция в языке C может возвращать некоторый результат, и для этого применяется оператор `return`. Однако помимо очевидного механизма возврата значений существуют важные детали: копирование данных при возврате, возврат указателей и возврат сложных объектов.

## Возврат примитивных значений

Функция `getNumber` имеет возвращаемый тип `int` и поэтому должна возвращать число этого типа:

```c
int getNumber(void)
{
    int result = 125;
    return result;
}
```

Далее мы можем получить результат этой функции в переменную:

```c
int getNumber(void)
{
    int result = 125;
    return result;
}

int main(void)
{
    int n = getNumber();
}
```

### Ассемблерный уровень

При возвращении результата происходит **копирование** возвращаемого значения из функции. Ассемблерный вывод программы (GCC, x86-64, синтаксис GAS):

```asm
getNumber:
    pushq   %rbp
    .seh_pushreg    %rbp
    movq    %rsp, %rbp
    .seh_setframe   %rbp, 0
    subq    $16, %rsp
    .seh_stackalloc 16
    .seh_endprologue
    movl    $125, -4(%rbp)
    movl    -4(%rbp), %eax
    addq    $16, %rsp
    popq    %rbp
    ret
    .seh_endproc
```

Под меткой `getNumber` нас интересуют две инструкции:

```asm
movl    $125, -4(%rbp)      ; число 125 помещается в стек
movl    -4(%rbp), %eax      ; из стека данные помещаются в регистр EAX
```

Первая инструкция помещает в стек по адресу `RBP-4` число 125. Вторая инструкция помещает данные по адресу `RBP-4` в регистр `EAX`. Фактически это выполнение оператора `return`: на архитектуре x86-64 для возвращения значения используется регистр `RAX` (или его младшие 32 бита — регистр `EAX`).

В функции `main`:

```asm
call    getNumber
movl    %eax, -4(%rbp)
```

После выполнения `call` в регистре `EAX` оказывается результат — число 125. И этот результат помещается по адресу `RBP-4` — адресу переменной `n` в функции `main`.

Таким образом, значение переменной `result` копируется в регистр `EAX`. Затем переменная `result` (как и все автоматические переменные в стеке) уничтожается, а её значение вызывающий контекст получает через регистр.

## Возвращение указателей

### Указатели на автоматические переменные

Изменим программу, использовав указатели:

```c
#include <stdio.h>

int* getNumber(void)
{
    int result = 125;
    return &result;
}

int main(void)
{
    int *n = getNumber();
    printf("*n = %d\n", *n);
}
```

Функция `getNumber` возвращает указатель — адрес переменной `result`. На этапе компиляции мы столкнёмся с предупреждением:

```
warning: function returns address of local variable
```

Поскольку мы возвращаем адрес локальной автоматической переменной, которая после выполнения функции уничтожается, её адрес будет недействительным.

Ассемблерный код для функции `getNumber`:

```asm
getNumber:
    pushq   %rbp
    movq    %rsp, %rbp
    subq    $16, %rsp
    movl    $125, -4(%rbp)
    movl    $0, %eax        ; в EAX NULL
    addq    $16, %rsp
    popq    %rbp
    ret
```

В качестве результата в регистр `EAX` помещается `0` — на уровне языка C это `NULL`.

> [!WARNING]
> Мы **НЕ** можем возвращать из функции адрес автоматических переменных, которые уничтожаются с завершением функции.

### Указатели на данные в статической памяти

Мы можем возвращать из функции указатели на данные в статической памяти, которая существует в течение всей работы программы:

```c
#include <stdio.h>

int* getNumber(void)
{
    static int result = 125;
    return &result;
}

int main(void)
{
    int *n = getNumber();
    printf("*n = %d\n", *n);
}
```

Переменная `result` является статической, соответственно её адрес будет валидным в течение всей работы программы.

### Строки: указатель vs массив

Рассмотрим два варианта возврата строки:

**Указатель на строку в статической памяти (работает):**

```c
#include <stdio.h>

char* getUser(void)
{
    char *name = "Tom";
    return name;
}

int main(void)
{
    char *user = getUser();
    printf("%s\n", user);
}
```

Строки в C располагаются в статической памяти. Функция `getUser` возвратит адрес этой строки, который доступен в течение всей жизни программы.

**Массив с инициализацией строкой (не работает):**

```c
#include <stdio.h>

char* getUser(void)
{
    char name[] = "Tom";
    return name;
}

int main(void)
{
    char *user = getUser();
    printf("%s\n", user);
}
```

Строки, которыми инициализируются массивы, сохраняются в стеке как автоматические переменные. Хотя имя массива — это указатель на его первый элемент, массив удаляется с завершением функции, и полученный адрес не действителен.

## Возвращение указателя из динамической памяти

Допустимо возвращение указателя на данные в динамической памяти:

```c
#include <stdio.h>
#include <stdlib.h>

int* getNumber(void)
{
    int *result = malloc(sizeof(int));
    *result = 134;
    return result;
}

int main(void)
{
    int *pointer = getNumber();
    printf("*pointer = %d\n", *pointer);
    free(pointer);
}
```

Переменная-указатель `result` уничтожается (она автоматическая), но динамическая память продолжает существовать. Через регистр `RAX` мы получаем адрес в переменную `pointer` и можем взаимодействовать с данными.

Фактически в данном случае происходит **передача владения** из функции `getNumber` в функцию `main`. После этого `main` несёт ответственность за освобождение динамической памяти с помощью `free()`.

## Возвращение сложных объектов

Для возврата структур действует тот же принцип — структуры **копируются**, и их копия передаётся в вызывающую функцию. Поскольку регистр `RAX` не может вместить всю структуру, для возвращения структуры применяется стек:

```c
#include <stdio.h>

typedef struct {
    int x;
    int y;
    int z;
} Point3D;

Point3D getCenter(void)
{
    Point3D point;
    point.x = 3;
    point.y = 5;
    point.z = 7;
    return point;
}

int main(void)
{
    Point3D center = getCenter();
    printf("x=%d\n", center.x);
    printf("y=%d\n", center.y);
    printf("z=%d\n", center.z);
}
```

### Ассемблерный вывод

```asm
getCenter:
    pushq   %rbp
    movq    %rsp, %rbp
    subq    $16, %rsp
    movq    %rcx, 16(%rbp)
    movl    $3, -12(%rbp)
    movl    $5, -8(%rbp)
    movl    $7, -4(%rbp)
    movq    16(%rbp), %rax
    movq    -12(%rbp), %rdx
    movq    %rdx, (%rax)
    movl    -4(%rbp), %edx
    movl    %edx, 8(%rax)
    movq    16(%rbp), %rax
    addq    $16, %rsp
    popq    %rbp
    ret
```

Сначала определяется локальная переменная `point` — три числа копируются в стек:

```asm
movl    $3, -12(%rbp)
movl    $5, -8(%rbp)
movl    $7, -4(%rbp)
```

Затем эти значения копируются в область стека, представляющую фрейм функции `main`:

```asm
movq    -12(%rbp), %rdx     ; копируем поля x и y в регистр RDX
movq    %rdx, (%rax)        ; копируем в стек во фрейм main
movl    -4(%rbp), %edx      ; копируем поле z в регистр RDX
movl    %edx, 8(%rax)       ; копируем в стек во фрейм main
```

После того, как функция `getCenter` отработает, её автоматические переменные уничтожаются, а скопированные данные оказываются во фрейме стека функции `main`.

### Возврат указателя на структуру

Если структура располагается в статической или динамической памяти, эффективнее возвращать указатель на структуру:

```c
#include <stdio.h>

typedef struct {
    int x;
    int y;
    int z;
} Point3D;

Point3D* getCenter(void)
{
    static Point3D point;
    point.x = 3;
    point.y = 5;
    point.z = 7;
    return &point;
}

int main(void)
{
    Point3D *center = getCenter();
    printf("x=%d\n", center->x);
    printf("y=%d\n", center->y);
    printf("z=%d\n", center->z);
}
```

Это экономит память в стеке, поскольку копируется только указатель (8 байт на x86-64), а не вся структура.

## Сводка

| Тип возврата | Механизм | Ограничения |
|---|---|---|
| Примитив (`int`, `char` и т.д.) | Копирование в регистр `EAX`/`RAX` | Нет |
| Указатель на автоматическую переменную | Копирование адреса | **Недопустимо** — адрес не действителен |
| Указатель на статическую память | Копирование адреса | Адрес валиден всю жизнь программы |
| Указатель на динамическую память | Копирование адреса | Передача владения, нужен `free` |
| Структура | Копирование в стек | Расход стека пропорционален размеру структуры |
| Указатель на структуру | Копирование адреса (8 байт) | Эффективнее для больших структур |

> [!NOTE]
> Возвращение указателя на автоматическую переменную — одна из самых распространённых ошибок в C. Компилятор предупреждает об этом, но не все ошибки ловятся на этапе компиляции.
