## Описание

Если программа имеет сложную структуру, где выделение динамической памяти производится в одном месте, её использование — в другом, а освобождение памяти — в третьем месте программы, возрастает риск использования недействительных указателей и программных ошибок. Можно столкнуться с использованием неинициализированного указателя, указателя, память по которому уже была освобождена, или с повторным освобождением памяти.

## Стандартное решение

Стандартное решение состоит в том, чтобы проверять валидность указателя (проверка на `NULL`) перед использованием. При определении указателя после освобождения памяти ему присваивается значение `0` или `NULL`:

```c
void some_function(void)
{
    char *pointer = NULL;
    pointer = malloc(1024);

    if (pointer)
    {
        // некоторая работа с памятью по указателю
    }

    free(pointer);
    pointer = NULL;
}
```

Проверка указателя и присвоение ему нуля увеличивает код, однако упрощает идентификацию тех мест в программе, где с указателем может возникнуть ошибка.

Также повторное освобождение памяти по указателю, которому ранее присвоили `NULL`, не окажет никакого влияния на программу:

```c
free(pointer);
pointer = NULL;
free(pointer);  // ни на что не влияет
```

## Пример: вывод файла на консоль

Рассмотрим программу, которая выводит на консоль текст из файла:

```c
#include <stdio.h>
#include <stdlib.h>
#include <assert.h>

int getFileLength(FILE *fp)
{
    fseek(fp, 0, SEEK_END);
    int file_length = ftell(fp);
    return file_length;
}

void readFile(FILE *fp, char *buffer, int file_length)
{
    fseek(fp, 0, SEEK_SET);
    int read_elements = fread(buffer, 1, file_length, fp);
    buffer[read_elements] = '\0';
}

void printFile(char *filename)
{
    FILE *fp = 0;
    char *text = 0;

    assert(filename && "Invalid file name");

    fp = fopen(filename, "r");
    assert(fp && "Unable to open file!\n");

    int file_length = getFileLength(fp);
    if (file_length > 0)
    {
        text = malloc(file_length);
        if (text)
        {
            readFile(fp, text, file_length);
            printf("%s\n", text);

            free(text);
            text = 0;
        }
    }
    fclose(fp);
    fp = 0;
}

int main(void)
{
    char *filename = "test.txt";
    printFile(filename);
}
```

### Инициализация указателей

Вначале определяются указатели и инициализируются нулем:

```c
FILE *fp = 0;
char *text = 0;
```

Это далее поможет при проверке идентифицировать, что файл открыт, а буфер успешно выделен.

### Проверка предусловий

С помощью `assert()` проверяется корректность имени файла:

```c
assert(filename && "Invalid file name");
```

Далее открываем файл и проверяем, что файл открыт:

```c
fp = fopen(filename, "r");
assert(fp && "Unable to open file!\n");
```

Выражение `assert()` проверяет, что `fp` не равен `NULL`, иначе прерывает программу. У нас есть два способа обработки корректности указателя: **жёсткий** с прерыванием программы и **мягкий** с некоторой обработкой и продолжением работы. Оба способа имеют свои плюсы и минусы. В данном случае прерываем программу, так как дальше нет смысла в работе функции, если файл не удалось открыть. Но это не аксиома — можно использовать более мягкие способы, например, проверку в конструкции `if`.

### Выделение памяти и чтение файла

Если длина файла меньше 1 байта, нет смысла считывать его содержимое:

```c
int file_length = getFileLength(fp);
if (file_length > 0)
{
    text = malloc(file_length);
    if (text)
    {
        readFile(fp, text, file_length);
        printf("%s\n", text);

        free(text);
        text = 0;
    }
}
```

В отличие от проверки указателя на файл `fp`, здесь используется мягкий подход с проверкой в конструкции `if`. После завершения работы с буфером его память освобождается, а указатель сбрасывается в `0`, что позволяет избежать висячих указателей:

```c
free(text);
text = 0;
```

В конце закрываем файл и сбрасываем указатель файла в `0`:

```c
fclose(fp);
fp = 0;
```

## Проблема висячего указателя

В данном случае ситуация в некотором смысле искусственная, поскольку после освобождения памяти указатель на неё никак не используется. Однако немного изменим функцию `printFile`:

```c
void printFile(char *filename)
{
    FILE *fp = 0;
    char *text = 0;

    assert(filename && "Invalid file name");

    fp = fopen(filename, "r");
    assert(fp && "Unable to open file!\n");

    int file_length = getFileLength(fp);
    if (file_length > 0)
    {
        text = malloc(file_length);
        if (text)
        {
            readFile(fp, text, file_length);
            printf("%s\n", text);
            free(text);
            // text = 0  // закомментируем сброс буфера в ноль
        }
    }

    // пробуем вывести текст после освобождения памяти
    if (text)
    {
        printf("%s\n", text);
        free(text);
    }

    fclose(fp);
    fp = 0;
}
```

Здесь после освобождения памяти по указателю `text` повторно проверяем валидность указателя и пробуем вывести текст на консоль. Результат в этом случае будет **неопределённым**. Вполне возможно, что будет выведен ранее считанный из файла текст. Однако формально память уже освобождена, и мы получили **висячий указатель** (dangling pointer), использование которого может служить источником программных ошибок.

Соответственно, сброс указателя в ноль сразу после освобождения с последующей проверкой указателя на валидность позволил бы избавиться от ряда проблем.

То же самое касается и других ресурсов, например, указателя на файл: даже если мы закроем файл, указатель сохранит своё значение. И нам ничего не помешает попытаться выполнить с файлом по этому указателю какие-нибудь операции. Сброс же указателя в ноль с последующей проверкой на `NULL` позволит избежать ненужных операций с закрытым файлом.

## Рекомендации

| Действие | Результат |
|---|---|
| Инициализация указателя `NULL` | Явное указание на отсутствие данных |
| Проверка на `NULL` перед использованием | Защита от неинициализированного указателя |
| Сброс в `NULL` после `free` | Защита от висячего указателя |
| Повторный `free(NULL)` | Безопасная операция (ничего не делает) |

> [!NOTE]
> Сброс указателя в `NULL` после освобождения памяти — это не формальность, а защита от трудноуловимых ошибок. В сложных программах висячий указатель может проявляться далеко от места освобождения памяти.
