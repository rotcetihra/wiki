## Описание

Для хранения объектов в программе на языке C в общем случае у нас есть три варианта, где хранить объекты:

- **Стек** (автоматическая память)
- **Статическая память**
- **Динамическая память** (куча / heap)

## Хранение данных в стеке

Стек представляет собой память фиксированной длины, которая выделяется для каждого потока. В зависимости от операционной системы размер стека может отличаться. При вызове функции в стек помещаются параметры и все автоматические (нестатические) переменные, которые определяются внутри функции.

Чтобы положить значение в стек, достаточно определить нестатическую переменную внутри функции:

```c
int main(void)
{
    int number = 1; // переменная number хранится в стеке
}
```

После завершения работы функции эта часть стека автоматически очищается.

Например, если посмотреть на ассемблерный вывод компилятора GCC для этой программы (применяется синтаксис ассемблера GAS), мы увидим:

```asm
    .file   "app.c"
    .text
    .def    __main; .scl    2;  .type   32; .endef
    .globl  main
    .def    main;   .scl    2;  .type   32; .endef
    .seh_proc   main
main:
    pushq   %rbp
    .seh_pushreg    %rbp
    movq    %rsp, %rbp
    .seh_setframe   %rbp, 0
    subq    $48, %rsp
    .seh_stackalloc 48
    .seh_endprologue
    call    __main
    movl    $1, -4(%rbp)
    movl    $0, %eax
    addq    $48, %rsp
    popq    %rbp
    ret
    .seh_endproc
```

Нас интересует выражение:

```asm
movl    $1, -4(%rbp)
```

Оно помещает число 1 в память, на которую указывает регистр `RBP` минус 4 байта. В дальнейшем через выражение `-4(%rbp)` программа ссылается на значение переменной `number`.

В конце программы инструкция:

```asm
addq    $48, %rsp
```

Прибавляет к указателю стека 48 байт, тем самым освобождая память.

## Хранение данных в статической памяти

Статическая память представляет собой блок памяти фиксированного размера, выделение которой происходит во время компиляции. Значения в статической памяти хранятся на протяжении всей работы программы. Статическая память обеспечивает быстрый доступ к данным и позволяет избежать фрагментации, характерной при использовании динамической памяти.

Тем не менее, применение статической памяти имеет определённые недостатки:

- **Размер данных должен быть фиксирован** и известен на стадии компиляции.
- **Неэффективное использование памяти:** если определён большой массив данных, большая часть которых не используется, память будет расходоваться впустую.
- **Проблема многопоточности:** статическая память является общей для всех потоков программы, и могут потребоваться дополнительные инструменты для разграничения доступа.
- **Задержка запуска:** программа может запускаться чуть дольше, поскольку надо выделить память для статических переменных и констант.

Для помещения переменной в статическую память эта переменная определяется с помощью ключевого слова `static`. Можно определять статические переменные на уровне функции (такие переменные доступны только в текущей функции) и на уровне файла (доступны только в текущем файле). Также глобальные переменные без слова `static` также помещаются в статическую память:

```c
int n1 = 1;         // глобальная — доступна во всей программе
static int n2 = 2;  // на уровне файла — доступна только в текущем файле

int main(void)
{
    static int n3 = 3; // на уровне функции — доступна только в main
}
```

Все три переменные (`n1`, `n2`, `n3`) помещаются в статическую память. Различие между ними состоит в уровне доступа.

Ассемблерный вывод программы:

```asm
    .file   "app.c"
    .text
    .globl  n1
    .data
    .align 4
n1:
    .long   1
    .align 4
n2:
    .long   2
    .def    __main; .scl    2;  .type   32; .endef
    .text
    .globl  main
    .def    main;   .scl    2;  .type   32; .endef
    .seh_proc   main
main:
    pushq   %rbp
    .seh_pushreg    %rbp
    movq    %rsp, %rbp
    .seh_setframe   %rbp, 0
    subq    $32, %rsp
    .seh_stackalloc 32
    .seh_endprologue
    call    __main
    movl    $0, %eax
    addq    $32, %rsp
    popq    %rbp
    ret
    .seh_endproc
    .data
    .align 4
n3.0:
    .long   3
```

Все три переменные определены в секции `.data`, которая хранит глобальные данные. Переменная `n1` также определена с директивой `.globl`, что позволяет увидеть её в других файлах программы. К `n3` при определении добавляется число 0, и в дальнейшем на эту переменную программа ссылается через идентификатор `n3.0`.

### Строки и константные массивы

Если внутри функции определяются данные, которые имеют фиксированный размер и не изменяются в течение программы, они также определяются в статической памяти. Например, строки хранятся в статической памяти:

```c
int main(void)
{
    char *message = "hello";
}
```

Ассемблерный вывод программы:

```asm
    .file   "app.c"
    .text
    .def    __main; .scl    2;  .type   32; .endef
    .section .rdata,"dr"
.LC0:
    .ascii "hello\0"
    .text
    .globl  main
    .def    main;   .scl    2;  .type   32; .endef
    .seh_proc   main
main:
    pushq   %rbp
    .seh_pushreg    %rbp
    movq    %rsp, %rbp
    .seh_setframe   %rbp, 0
    subq    $48, %rsp
    .seh_stackalloc 48
    .seh_endprologue
    call    __main
    leaq    .LC0(%rip), %rax
    movq    %rax, -8(%rbp)
    movl    $0, %eax
    addq    $48, %rsp
    popq    %rbp
    ret
    .seh_endproc
```

Строка `"hello"` определена в секции `.rdata` и проецируется на метку `.LC0`:

```asm
.section .rdata,"dr"
.LC0:
    .ascii "hello\0"
```

Фактически `.LC0` определена как глобальная переменная. А переменная `message`, которая хранит адрес этой строки, определена как автоматическая переменная, которая удаляется после завершения работы функции:

```asm
leaq    .LC0(%rip), %rax    ; помещаем в регистр RAX адрес переменной .LC0
movq    %rax, -8(%rbp)      ; данные из регистра RAX помещаем в стек по адресу RBP-8
```

То же самое относится к константным массивам:

```c
int main(void)
{
    const int nums[] = {22, 34};
}
```

Данные массива `nums` также будут храниться в статической памяти.

## Хранение данных в динамической памяти

При использовании динамической памяти обязанность по выделению и освобождению памяти ложится на программиста. С помощью функций `malloc`/`calloc`/`realloc` выделяется память в куче (heap), а с помощью функции `free()` память освобождается:

```c
void main(void)
{
    int *data = malloc(sizeof(int) * 100);
    // работа с data
    free(data);
}
```

Динамическая память позволяет уйти от ограничений размера стека и ограничений фиксированного размера данных статической памяти. Однако поскольку программы могут иметь сложную структуру, несвоевременное освобождение памяти может представлять проблему. Кроме того, многократное выделение/освобождение памяти может вести к **фрагментации памяти**: даже если суммарный размер свободных фрагментов превышает необходимый, операционная система не сможет выделить память, так как размер наибольшего фрагмента меньше необходимого.

## Рекомендации по выбору типа памяти

### Данные в пределах одной функции

Если данные невелики по объёму и необходимы в пределах одной функции, следует помещать их в стек — определять как автоматические переменные и константы, которые автоматически уничтожаются после завершения функции:

```c
#include <stdio.h>

int main(void)
{
    int nums[100];
    nums[0] = 25;
    printf("%d\n", nums[0]);
}
```

Использование `malloc` для локального массива неэффективно:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n = 100;
    int *nums = malloc(sizeof(int) * n);
    nums[0] = 23;
    printf("%d\n", nums[0]);
    free(nums);
}
```

Мы вынуждены вручную управлять памятью, тратить ресурсы на выделение и освобождение. Если необходимо определить размер массива с помощью переменной, начиная со стандарта C99 такая возможность поддерживается:

```c
#include <stdio.h>

int main(void)
{
    int n = 100;
    int nums[n];
    nums[0] = 25;
    printf("%d\n", nums[0]);
}
```

### Данные фиксированного размера на протяжении всей программы

Если данные фиксированного размера нужны в течение всей жизни программы, особенно если данные довольно большие и есть вероятность, что они не поместятся в стек, можно поместить данные в статическую память:

```c
#include <stdio.h>

int nums1[100];          // в статической памяти
static int nums2[100];   // в статической памяти

int main(void)
{
    static int nums3[100]; // в статической памяти
}
```

Другая проблема автоматических переменных состоит в том, что при передаче их значений между вызовами функций мы вынуждены использовать параметры, что ведёт к издержкам (данные надо скопировать). В этом случае глобальные (статические) переменные позволят избежать ненужного копирования, что особенно актуально при передаче больших данных.

### Когда применять динамическую память

Если автоматические и статические переменные не подходят в силу различных ограничений (динамический размер, время жизни больше одной функции, необходимость изменения размера), применяется динамическая память.

| Тип памяти | Размер | Время жизни | Управление | Использование |
|---|---|---|---|---|
| Стек | Фиксированный (VLA — динамический) | Время выполнения функции | Автоматическое | Локальные переменные |
| Статическая | Фиксированный | Вся программа | Автоматическое | Глобальные переменные, константы |
| Динамическая | Динамический | До вызова `free` | Ручное | Большие данные, динамические структуры |

> [!NOTE]
> В общем случае следует отдавать предпочтение стеку. Динамическую память используйте только тогда, когда стек и статическая память не滿足ают требованиям.
