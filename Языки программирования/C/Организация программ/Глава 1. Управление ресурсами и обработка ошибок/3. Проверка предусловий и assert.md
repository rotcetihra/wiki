## Описание

Иногда ошибки, возникающие в процессе работы программы, могут быть очень критичными для работы приложения, а их обработка — слишком сложной и требующей много кода. При этом подобные ошибки могут быть очень редки: вероятность, что они произойдут, очень низка.

Возникает вопрос: определять ли дополнительный код для обработки ошибки, которая критична, но маловероятна, либо поступить иначе? Особенно учитывая, что любой дополнительный код усложняет программу и снижает её читабельность.

## Assertion Context

Одним из выходов из подобной ситуации является **прекращение работы программы** при возникновении критичной ошибки. Для этого в языке C может применяться функция `assert()`:

```c
void some_func(void)
{
    assert(check_conditions() && "Error! Conditions are incorrect");
    // основной код
}
```

В данном коде `assert()` с помощью некоторой функции `check_conditions()` проверяет условия, и если они не выполняются, выводит в стандартный поток ошибок `stderr` сообщение и прерывает выполнение программы.

Подобный паттерн иногда называют **Assertion Context**. Его можно применять при проверке предусловий, например, на проверку параметров на `NULL`.

## Пример: запись текста в файл

Рассмотрим программу, в которой функция `writeTextToFile()` записывает текст в файл с проверкой предусловий через `if`:

```c
#include <stdio.h>

void writeTextToFile(char*, char*);

int main(void)
{
    char *filename = "test.txt";
    char *text = "Hello METANIT.COM";
    writeTextToFile(filename, text);
}

void writeTextToFile(char *file_name, char *text)
{
    // проверка предусловий
    if (file_name == NULL) {
        printf("Error! File name is incorrect!\n");
        return;
    }
    if (text == NULL) {
        printf("Error! Text is incorrect!\n");
        return;
    }

    // открываем файл
    FILE *file_pointer = fopen(file_name, "w");
    if (file_pointer == NULL) {
        printf("Error! Unable to open file!\n");
        return;
    }

    // запись в файл
    if (fputs(text, file_pointer) != EOF)
    {
        printf("Success! Text has been written to the file!\n");
    }

    // закрываем файл
    fclose(file_pointer);
}
```

Здесь параметры функции проверяются на значение `NULL`. Если хотя бы один параметр равен `NULL`, функция завершает работу.

## Применение assert

Теперь применим `assert`:

```c
#include <stdio.h>
#include <assert.h>

void writeTextToFile(char*, char*);

int main(void)
{
    char *filename = "test.txt";
    char *text = "Hello METANIT.COM";
    writeTextToFile(filename, text);
}

void writeTextToFile(char *file_name, char *text)
{
    // проверка предусловий
    assert(file_name != NULL && "Error! File name is incorrect!");
    assert(text != NULL && "Error! Text is incorrect!");

    // открываем файл
    FILE *file_pointer = fopen(file_name, "w");
    if (file_pointer == NULL) {
        printf("Error! Unable to open file!\n");
        return;
    }

    // запись в файл
    if (fputs(text, file_pointer) != EOF)
    {
        printf("Success! Text has been written to the file!\n");
    }

    // закрываем файл
    fclose(file_pointer);
}
```

Если выполняются условия `file_name != NULL` и `text != NULL`, функция продолжает свою работу. Если хотя бы одно из условий не выполняется, функция завершает работу, а в стандартный поток ошибок выводится сообщение:

```
Assertion failed: file_name != NULL && "Error! File name is incorrect!", file app.c, line 15
```

## Сравнение подходов

| `if` + `return` | `assert` |
|---|---|
| Работает всегда (в release и debug) | Работает только в debug-сборке |
| Можно обработать ошибку программно | Программа завершается немедленно |
| Подходит для ожидаемых ошибок | Подходит для «невозможных» ошибок |
| Увеличивает размер кода | Не влияет на размер в release |

> [!WARNING]
> В release-сборке (с определённым макросом `NDEBUG`) `assert` становится пустой операцией. Не используйте `assert` для проверки условий, от которых зависит корректность работы программы в production. Для этого подходят обычные проверки с возвратом кода ошибки.

> [!NOTE]
> `assert` полезен для отладки и документирования предположений разработчика. Если `assert` срабатывает — это означает ошибку в логике программы, а не во входных данных.
