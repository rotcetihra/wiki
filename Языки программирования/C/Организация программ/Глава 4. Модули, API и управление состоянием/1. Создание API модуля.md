**Дата написания:** 31.08.2026

## Описание

Для упрощения организации программы её код обычно разбивается на отдельные модули или отдельные файлы. Отдельный файл/модуль обычно содержит связанный функционал, который выполняет некоторую общую работу. Однако при разделении функционала программы на отдельные файлы мы можем столкнуться с рядом проблем.

## Проблема дублирования глобальных идентификаторов

Пусть у нас есть файл `user.c`:

```c
#include <stdio.h>

char *username = "tom@smail.com";

void printUserName(void)
{
    printf("UserName: %s\n", username);
}

void resetUserName(void)
{
    username = "Undefined";
}
```

И основной файл `app.c`:

```c
#include <stdio.h>

char *username = "Tom";

extern void resetUserName(void);

void printUserName(void)
{
    printf("Name: %s\n", username);
}

int main(void)
{
    printUserName();
    resetUserName();
}
```

При компиляции `gcc -Wall -pedantic app.c user.c -o app` мы столкнёмся с ошибкой — дублируются глобальные идентификаторы: переменная `username` и функция `printUserName`.

## Проблема несанкционированного доступа

В коде `app.c` мы вызываем функцию `resetUserName` для сброса имени. Однако должен ли внешний код иметь возможность выполнять эту функцию? Если модуль `user.c` создаем мы, а использует его внешнее приложение, мы можем не знать, в каком случае эта функция будет вызываться.

Обе проблемы ставят нас перед задачей **инкапсуляции** функционала в модуле и предоставления внешнему коду доступа только к определённым ограниченным возможностям модуля.

## Определение API

**API** (Application Program Interface) — тот функционал, который будет виден извне и который может использоваться во внешнем коде. Объявления функций и типов, которые входят в API, выносятся в заголовочный файл. Остальной функционал определяется с модификатором `static`, что делает его доступным только в рамках файла определения.

### Пример: модуль вывода файла на консоль

#### Заголовочный файл (file_printer.h)

```c
void printFile(char*);
```

API простое — определяем функцию `printFile`, которая принимает имя файла.

#### Реализация (file_printer.c)

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <assert.h>
#include "file_printer.h"

static int getFileLength(FILE *fp)
{
    fseek(fp, 0, SEEK_END);
    int file_length = ftell(fp);
    return file_length;
}

static void readFile(FILE *fp, char *buffer, int file_length)
{
    fseek(fp, 0, SEEK_SET);
    int read_elements = fread(buffer, 1, file_length, fp);
    buffer[read_elements] = '\0';
}

void printFile(char *filename)
{
    FILE *fp = 0;
    char *text = 0;

    assert(filename && "Invalid file name");

    fp = fopen(filename, "r");
    assert(fp && "Unable to open file!\n");

    int file_length = getFileLength(fp);
    if (file_length > 0)
    {
        text = malloc(file_length);
        if (text)
        {
            readFile(fp, text, file_length);
            printf("%s\n", text);
            free(text);
            text = 0;
        }
    }
    fclose(fp);
    fp = 0;
}
```

Функции `getFileLength` и `readFile` используются внутри модуля и не имеют смысла в отрыве от `printFile`. Они не входят в API и определены с помощью ключевого слова `static`.

#### Основной файл (app.c)

```c
#include <stdio.h>
#include "file_printer.h"

int main(void)
{
    char *filename = "test.txt";
    printFile(filename);
}
```

Для использования API подключаем его определение в файле `file_printer.h`. Для внешнего кода существует только функция `printFile`, а её реализация для него не важна.

## Итог

| Аспект | Описание |
|---|---|
| Заголовочный файл | Содержит объявления API (функции, типы) |
| Файл реализации | Содержит реализацию API и внутренний функционал |
| `static` | Скрывает внутренние функции и переменные от внешнего кода |
| Инкапсуляция | Внешний код видит только то, что определено в API |

> [!NOTE]
> Разделение API и реализации позволяет изменять внутреннюю логику модуля без влияния на внешний код, при условии сохранения интерфейса.
