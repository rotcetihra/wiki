## 1. Введение

Для создания многопоточных приложений, которые выполняют некоторые действия параллельно, в языке Си обычно используются потоки `pthread` (о них — урок «Создание потоков»), но это не единственный способ добиться параллелизма в C. Для этой цели также можно использовать библиотеку **OpenMP**.

Для применения OpenMP не нужно подключать какие-либо файлы заголовков (если мы сами не используем функции OpenMP). Вместо этого применяются прагмы (директивы `pragma`). Сначала посмотрим на небольшой пример:

```c
#include <unistd.h>
#include <stdio.h>

int main(void)
{
    static const char str[] = "Hello METANIT.COM\n";

    // Используются все доступные процессоры
    #pragma omp parallel
    write(STDOUT_FILENO, str, sizeof str - 1);
}
```

Разберем этот код. Сначала определяется строка, которую для примера мы будем выводить на консоль:

```c
static const char str[] = "Hello METANIT.COM\n";
```

Далее используем прагму:

```c
#pragma omp parallel
```

Эта директива создает **параллельную область** — каждый поток исполняет одну и ту же инструкцию, расположенную сразу после директивы.

Далее идет низкоуровневый системный вызов для вывода ранее определенной строки в стандартный вывод (`stdout`):

```c
write(STDOUT_FILENO, str, sizeof str - 1);
```

Запустим код на выполнение, например, с помощью компилятора GCC (предполагается, что код расположен в файле `app.c`):

```c
$ gcc -fopenmp app.c -o app && ./app
Hello METANIT.COM
Hello METANIT.COM
Hello METANIT.COM
Hello METANIT.COM
..................
Hello METANIT.COM
```

При использовании компиляторов GCC или Clang нужно явно указать флаг `-fopenmp`.

При выполнении создается несколько потоков (обычно столько, сколько ядер у процессора). Каждый поток одновременно вызывает функцию `write` и выводит строку `"Hello, METANIT.COM\n"` на консоль. Таким образом, в результате на экране появится несколько строк, выведенных параллельно.

## 2. Вывод с помощью write

Сразу отметим важную деталь: для вывода на консоль здесь применяется не стандартный `printf`, а прямой вызов в системный буфер вывода через `write`. Поскольку `write` — небуферизованный, он работает атомарно на уровне системных вызовов (в отличие от `printf`), поэтому каждая строка скорее всего будет выведена полностью, без перемешивания символов. Если бы использовался `printf`, вывод мог бы перемешиваться, потому что `printf` использует буферизацию и не потокобезопасен.

## 3. Директивы OpenMP

При работе с OpenMP применяется ряд директив. Отметим некоторые из них:

```c
#pragma omp parallel
#pragma omp simd
#pragma omp for
```

При использовании директив OpenMP после `#pragma` сначала идет `omp`, а затем собственно указывается директива OpenMP.

- `#pragma omp parallel` — создает параллельную область: несколько потоков начинают выполнение кода внутри этой области. Каждый поток исполняет одну и ту же копию кода.
- `#pragma omp simd` — указывает компилятору векторизовать (SIMD — _Single Instruction, Multiple Data_) следующий цикл: выполнять одну инструкцию одновременно над множеством данных, используя векторные инструкции процессора (например, SSE/AVX).
- `#pragma omp for` — обозначает, что итерации следующего за директивой цикла должны быть распределены между потоками. Обычно используется внутри `parallel`.

Директивы можно сочетать, например, `parallel` и `for`:

```c
#pragma omp parallel for
```

## 4. Параллельная обработка циклов

Директива `for` предназначена для использования с `parallel` и применяется для разветвления текущего потока на дополнительные N-1 потоков, где N — количество итераций цикла. Правда, если N больше количества логических процессоров, то N будет соответствовать этому значению, и тогда будет M групп по N потоков в последовательности, где M — количество итераций, деленное на максимальное количество потоков. Например:

```c
#include <stdio.h>

int main(void)
{
    int i;

    // Используем 8 процессоров (создаст 7 новых потоков + основной)
    #pragma omp parallel for
    for (i = 0; i < 8; i++)
        printf("%d\n", i);
}
```

Директива OpenMP `parallel for` делит итерации цикла `for` между несколькими потоками. Каждый поток получает свое значение счетчика `i` в диапазоне от 0 до 7. OpenMP по умолчанию использует количество потоков, равное количеству логических ядер, либо значение, заданное в `OMP_NUM_THREADS`. Пример консольного вывода:

```
$ gcc -fopenmp app.c -o app && ./app
1
3
2
4
7
5
0
6
```

Обратите внимание, что порядок, в котором потоки выполняются, не гарантируется. Если нужен правильный порядок, необходимо использовать директиву `ordered`:

```c
#include <stdio.h>

int main(void)
{
    int i;

    // упорядоченный вывод
    #pragma omp parallel for ordered
    for (i = 0; i < 8; i++)
        #pragma omp ordered
        printf("%d", i);
}
```

С помощью первой директивы `#pragma` мы сообщаем OpenMP, что цикл `for` распараллелен и внутри блока цикла есть выражения (в данном случае вызов функции `printf()`), которые должны быть выполнены по порядку. А чтобы указать, какие выражения должны быть упорядочены, к ним применяется вторая директива `#pragma` — `#pragma omp ordered`. Это подразумевает, что вполне возможно иметь выражения внутри блока цикла, которые выполняются не по порядку, а другие — по порядку.

```
$ gcc -fopenmp app.c -o app && ./app
0
1
2
3
4
5
6
7
```

## 5. Векторизация и SIMD

Директива `#pragma omp simd` применяется для векторизации цикла. Она указывает компилятору векторизовать цикл, используя SIMD-инструкции процессора (например, AVX, SSE). Она не создает потоки, как `#pragma omp parallel`, а применяет одну инструкцию к множеству данных одновременно. Например, применим эту директиву для операции сложения массивов:

```c
#include <stdio.h>
#include <omp.h>

int main(void)
{
    const int N = 8;
    float a[N], b[N], c[N];

    // Инициализация
    for (int i = 0; i < N; i++) {
        a[i] = i;
        b[i] = i * 2;
    }

    // Векторизуемый цикл сложения
    #pragma omp simd
    for (int i = 0; i < N; i++) {
        c[i] = a[i] + b[i];
    }

    // Вывод результата
    for (int i = 0; i < N; i++) {
        printf("c[%d] = %.1f\n", i, c[i]);
    }

    return 0;
}
```

Для компиляции применяется флаг `-O2` или выше, чтобы компилятор действительно применил векторизацию:

```
$ gcc -O2 -fopenmp app.c -o app && ./app
c[0] = 0.0
c[1] = 3.0
c[2] = 6.0
c[3] = 9.0
c[4] = 12.0
c[5] = 15.0
c[6] = 18.0
c[7] = 21.0
```

В общем, директива `omp simd` применяется, когда есть простые циклы над массивами (арифметика, копирование и т. п.), либо когда надо ускорить код за счет векторизации, без параллельных потоков.

> [!NOTE]
> Несмотря на то, что сам цикл векторизации не требует подключения заголовочных файлов, в примере выше включен `<omp.h>` — в нем определен вспомогательный код для работы с SIMD-циклами.

## 6. Функции OpenMP

Если нам надо использовать какие-то специфические функции OpenMP, то необходимо подключить заголовочный файл `omp.h`. Например, используем встроенную функцию `omp_get_thread_num()`, которая возвращает номер текущего потока:

```c
#include <stdio.h>
#include <omp.h>

int main(void)
{
    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        printf("Thread %d: Hello\n", tid);
    }
}
```

Пример консольного вывода:

## 7. Критическая секция

При параллельном выполнении следует помнить, что некоторые стандартные функции, как, например, функции вывода `printf()` или `puts()`, не потокобезопасны. Так, `printf`/`puts` используют буферизацию, и их вызовы не синхронизируются между потоками по умолчанию. Это может привести к перемешиванию вывода, поврежденным строкам (например, `"HeHlellollo"`) или даже к потере части вывода в редких случаях.

Чтобы решить эту проблему, мы можем применить еще одну директиву — `#pragma omp critical`. Она используется для синхронизации потоков и гарантирует, что только один поток заходит в критическую секцию в каждый момент времени:

```c
#pragma omp critical
{
    // Этот блок выполняется ОДНИМ потоком за раз
}
```

Использование этой директивы позволяет предотвратить одновременный доступ к общим ресурсам, таким как файлы, переменные, буферы вывода (`printf`, `puts`) и т. п.

Пример — конкурентный доступ к `puts`:

```c
#include <stdio.h>

int main(void)
{
    const char str[] = "Hello";
    #pragma omp parallel for
    for (int i = 0; i < 8; i++) {
        #pragma omp critical
        {
            puts(str);
        }
    }
    return 0;
}
```

Без директивы `critical` вызовы `puts()` из разных потоков могут перемешиваться, т. к. `stdout` не потокобезопасен. С `critical` потоки выводят по очереди. `puts()` выполняется атомарно (одним потоком за раз).

При всех плюсах есть и минусы: это замедляет производительность, если использовать `critical` слишком часто, — потоки начинают ждать друг друга. Поэтому лучше сужать критическую секцию до минимально необходимого кода.

## 8. Резюме

1. OpenMP — инструмент параллельного программирования, использующий директивы `pragma` вместо создания потоков вручную.
2. `#pragma omp parallel` создает параллельную область; `for` распределяет итерации цикла между потоками; `simd` векторизует цикл.
3. Порядок выполнения потоков не гарантируется; для упорядоченного вывода применяется `ordered`.
4. Для работы с функциями OpenMP подключается заголовочный файл `omp.h` (например, `omp_get_thread_num()`).
5. `#pragma omp critical` защищает критическую секцию от одновременного доступа потоков, но замедляет производительность.
